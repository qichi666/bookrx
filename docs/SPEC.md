## 1. 产品定义

| 项 | 内容 |
|---|---|
| 一句话 | 你说自己的困境，它给你 5 本书，每本告诉你为什么是这本，并且你能当场开始读。 |
| 目标用户 | 22–35 岁、有阅读意愿但连续 12 个月没读完一本书的中文用户 |
| 核心问题 | 所有榜单都在回答「哪些书好」，没人回答「以我现在的状态，我能读完哪一本，读完会变好吗」 |
| 与竞品差别 | `yzfly/LightRead` 是「阅读器 + 顺手几张书单」（推荐在设置里且默认关闭）；我们是「诊断器 + 自带阅读器」 |

## 2. MVP 范围（锁定）

### 2.1 P0 功能（17 项）

| # | 功能 | 验收标准摘要 |
|---|---|---|
| P0-1 | 困境问卷（3 屏必填 + 1 屏可选自由文本） | 第 3 屏同屏呈现 5 组 chip，不得拆页；「说不上来」跳转到 6 个具体场景而非报错 |
| P0-2 | 自由文本与降级 | ≤140 字；未命中标签不影响出结果 |
| P0-3 | 规则加权打分 + 硬约束排序 | 7 因子权重和 = 10000；同输入两次结果逐字节一致 |
| P0-4 | 三段式理由 + 字段降级 | 无 `{{` 残留；禁用词命中 = 0 |
| P0-5 | 符合度三档呈现 | 不出现任何百分数 |
| P0-6 | 推荐结果页（5 本分 3 组） | 第三组不显示档位方块 |
| P0-7 | 书籍详情页 | 可用性区块紧随书名，不放到页底 |
| P0-8 | 导入引导 + 失败态 | 12 种失败态按原因分类，不用统一文案（错误码表见 §6.4；落库失败区分 `E_STORAGE_QUOTA` 与 `E_STORAGE_FAILED`——前者删书能解决，后者删书没用） |
| P0-9 | EPUB 阅读器 | 翻页/字号/主题/目录/书内搜索 |
| P0-10 | TXT 阅读器 | GB18030 自动判定；章节识别有兜底 |
| P0-11 | 本地书库 | 在读 / 读完 / 想读 三组 |
| P0-12 | 划线 + 笔记 | 跨版式可恢复（双锚点） |
| P0-13 | 内置直读 | **改为：内置 1 本自写示例书**（一千余字，四章），走与导入书完全相同的链路；**不放第三方公版全文**——见下方条款 |
| P0-14 | 离线可用 | 断网刷新首屏与已导入书可读 |
| P0-15 | 推荐结果导出 | `*.booklist.json`，可被别人导入 |
| P0-16 | 危机资源条 | 仅「情绪与自我」域；不可关闭/不 toast/不折叠/滚动不移除；条内不写热线号，点开进本地资源页 |
| P0-17 | 结构性无 inline 域说明条 | 习惯与行动 / 工作与意义 / 认知与思考三域结果页顶部；信息色、可折叠、禁用道歉词 |

> **P0-15 文件格式（`bookrx.booklist/1`）**：`{ schema, exported_at, data_version, diagnosis, items[], note? }`。
> 两条硬约束：① **只存用户的选择**（`diagnosis`），**不存任何分数字段**——分数换个书库版本就会变，
> 存进文件会让收件人以为"对方的分数"可比（它不可比）；② `items[]` 只留 `book_id / title / tier`
> 三项，供收件人在自己书库里对照，缺失时不假装匹配。版本只向前兼容：`schema` 版本号大于本应用支持版本时
> 拒绝导入并明说"比本应用新"，不硬读。

> **P0-13 裁量（2026-10-20 修订）**：原条款要求内置 30–40 本公版书全文。实际不做，两个理由都不是省事：
> ① **保真**：公版文本版本差异极大（断句、错字、注释、删节），随手放一份进去，用户看到的是劣质底本，
> 而我们没有能力逐字校勘；② **边界**：分发别人的全文就要同时回答"底本来源 / 校勘责任 / 整理者权利"三问，
> 而"整理者权利"在中国法下并非总是清晰（点校、注释本可能另有权利）。
> 替代方案是 1 本**由本项目编写**的示例书：它解决的真问题是"在导入自己的书之前先试手感"，
> 且三个问题一个都不存在。公版书仍可通过外链读到（`book-links.ts` 的第一个链接）。
> 将来若要做真公版直读，前置条件是：有可核验的底本来源 + `audit:copyright` 能逐本证明 + 有人负责校勘。

> **P0-16 文案（定稿，不得改）**：「如果你现在不太好过，读书可以先放一放。这里有可以立刻联系的心理援助资源。」按钮「查看心理援助资源」。
> 用「不太好过」不用「状态很差」——后者是给用户下负面判断，他此刻不需要被诊断，需要被允许。「读书可以先放一放」必须留，这是本产品「不推销自己」的唯一硬证据，删掉就退化成免责声明。
> 资源页四要素：机构 / 地区 / 号码 / 最近核对日期，数据来自仓库内 `crisis_resources.json`，页顶标最近核对月份，页底给「打不通或已变更，请提 issue」。**号码不写进 UI 组件**：写死必然过期，而过期的热线比不展示更伤信任。
>
> **P0-17 文案（定稿，不得改）**：「这个方向的书基本都还在版权期内，正文需要你自己准备（EPUB 或 TXT），导入后就能读。下面的推荐和理由照常。」
> 是「说明」不是「道歉」。禁止以「抱歉 / 暂不支持 / 资源缺失 / 敬请期待」开头——道歉暗示我们在等一个永远不会来的修复版本，而这个缺口是结构性的、永久的。

## 3. 明确不做（锁定）

| 不做 | 原因 |
|---|---|
| 社区 / 评论 / 关注 | 冷启动社区是空地；UGC 审核成本超单人承载力 |
| PDF 阅读 | 固定版式导致重排/划线/深色全退化，等于再写一个引擎 |
| 账号 / 云同步 | 与 local-first 冲突；「不上传数据」是信任卖点 |
| LLM 打分 / LLM 写理由 / LLM 出题 | 结果不可复现、会编造、有成本 |
| 豆瓣评分 | 无公开 API；且「大众平均」≠「对你的适配度」 |
| 向量相似度推荐 | 300 本规模上规则更可解释；>5 万本再议 |
| 盗版书源 / 正文抓取 | 法律红线 |
| 打卡 / 排行榜 | 会把读书变成维持记录 |
| 原生 App | 只做 PWA |
| 书封大规模抓取 | 版权复杂 + 外链易失效；用书脊卡替代 |
| 富文本笔记 | Markdown 子集够用 |
| TTS / OPDS / 漫画 | 引擎已具备，第一版不开 |
| 任何变现 / 付费墙 | 与「可信的诊断器」定位冲突 |

## 4. 技术架构（锁定）

| 层 | 技术 | 版本策略 |
|---|---|---|
| 前端 | Vue 3 + TypeScript + Vite | **M0 时用 `npm ls` 锁定实际安装版写回本节**，不预设 |
| 状态 | 本地 ref / composable，不引 Pinia | 状态量小，全局 store 是多余抽象 |
| 存储 | IndexedDB via Dexie | 同上锁定 |
| 阅读引擎 | **foliate-js（MIT）** | git submodule 锁 commit，`vendor/foliate-js.commit` 记录 SHA |
| 图标 | **Lucide（ISC）单套**，`stroke-width: 1.75` | 禁止混入第二套 |
| 拼音 | `pinyin-pro` | **仅构建期**，禁止进 bundle |
| 复习 | `ts-fsrs` | 日期一律存 number，进出显式转换 |
| 部署 | 静态站点（Pages / Vercel）+ Docker | — |
| 许可 | 代码 MIT / 书目数据 CC BY-SA 4.0 | 不碰 AGPL |

### 4.1 分层与依赖方向

```
L4 views/ components/        只装配与交互
L3a domain/                  纯函数：无 I/O、无 DOM、无 Vue、无 Dexie
L3b engine/                  唯一允许 import foliate-js 的地方；不 import domain
L2  data/                    Dexie schema、repo、catalog 加载
L1  基础设施                  IndexedDB / 静态资源 / fetch
L0  contracts/               类型声明，编译后零字节
```

**三条 CI 可强制的边界**：
1. `domain/**` 不得 import `dexie` / `vue` / `window` / `document`
2. `engine/**` 不得 import `domain/**`
3. `src` 下除 `engine/foliate/` 外不得出现 `foliate` 字样

> 无后端，因此没有 HTTP API。**本节的「数据文件契约」取代传统 API 清单。**

### 5.1 静态数据文件

|---|---|---|---|
| `catalog/boot-columns.json` | 打分所需数值列 + 标签列（无中文长文本） | 首屏 | 22 KB |
| `catalog/titles.json` | id → 书名 / 作者 / 拼音 / 首字母 | 首屏 | 85 KB |
| `catalog/taxonomy.json` | 48 标签 + 8 族 + 反查 | 首屏 | 3 KB |
| `catalog/phrases.json` | 理由文案库与模板 | 首屏 | 14 KB |
| `catalog/shards/00..31.json` | 详情与文案字段 | 卡片/详情时 | 17 KB/片 |
| `catalog/core-link.json` | ISBN / 归一化书名 → book_id | 首次导入 | 26 KB |

### 5.2 `Book`（核心库与用户书同一类型）

| 字段 | 必填 | 类型 / 取值 | 约束 |
|---|---|---|---|
| `book_id` | 是 | `core:<6 位定宽>` \| `user:<hex16>` | **一经生成永不改，且不得编码任何可变属性**（域、难度、上架批次、书目版本一律不进 id）。永久空号不得回收 |
| `title` | 是 | string | 1–80 字，已剥离书名号 |
| `author_ids` / `author_display` | 是 | string[] | 等长同序；无署名填 `unknown` |
| `translator` | 否 | string | 中译本必填，版权闸门依赖 |
| `isbn13` | 否 | string | 13 位且校验位合法 |
| `problem_tags` | 是 | `{tag, weight}[]` | 1–4 项，weight ∈ [0.1,1.0] 一位小数，必须属 48 词表。**`topic` 因子的唯一依据**；缺失 ⇒ 不入个性化池 |
| `theme_tags` | 是 | `{tag, weight}[]` | 2–6 项，同上取值。用于浏览 / 搜索 / 相邻域，**不参与打分** |
| `category_l1` | 是 | `'文学'\|'心理'\|'思想哲学'\|'社科'\|'传记'\|'其他'` | 用于多样性配额与按品类浏览。**它是品类，不是困境域**：48 个困境标签另按 6 个困境域组织（只用于词表与「换个角度」取词） |
| `difficulty` | 是 | 1–5 整数 | 内容难度 |
| `prose_accessibility` | 是 | 1–5 整数 | 1 = 最易读 |
| `depth` | 是 | `'howto'\|'howto_why'\|'why'` | 与 3-e 一一对应：具体做法 / 做法加为什么 / 底层原理。**不用 1–5**：chip 只有 3 档，标 5 档等于造假精度 |
| `form` | 是 | `'story'\|'method'\|'framework'` | 与 3-d 一一对应：一个人的故事 / 一套方法 / 完整框架 |
| `entry_level` | 是 | 1–5 整数 | 1 = 零前置 |
| `length_class` | 是 | 1–4 整数 | <8 万 / 8–20 万 / 20–40 万 / >40 万 |
| `word_count` | 否 | number | 用于详情展示与时长估算 |
| `est_reading_hours` | 是 | number | **人工估算**，不用字数÷固定速度（文言可低到 150 字/分，通俗读物 700+）。构建期校验 `word_count / est_reading_hours ∈ [100,800]`，超界进人工复核 |
| `availability` | 是 | `'inline'\|'bring_your_own'\|'external'` | **唯一判定依据**，禁止临时推断 |
| `copyright_basis` | 是 | `'public_domain_cn'\|'public_domain_origin'\|'licensed_free'\|'in_copyright'\|'metadata_only'` | |
| `translation_copyright` | 是 | `'none'\|'public_domain'\|'in_copyright'\|'unknown'` | |
| `public_domain_reason` | 条件 | `'author_death_50y'\|'ancient_text'\|'gov_work'\|'cc_license'` | `copyright_basis` 含 public_domain 时必填 |
| `source_url` | 条件 | URL | `availability ≠ external` 时必填 |
| `one_line_what` | 是 | string | 60–90 字，客观讲「这本书讲什么」 |
| `structure_note` | 是 | string | **≤38 字**，必须以 `。`/`！`/`？` 结尾，构建期校验。**它就是卡面那一句**，也是 `promise` 的第一句 |
| `one_line_gain` | 是 | string | ≤35 字，「读完能得到什么」的工具/视角部分 |
| `first_action` | 是 | string | ≤30 字，**必须含动词短语**，构建期校验 |
| `match_brief` | 是 | string | **≤28 汉字**，按书预写，卡片第二行；不是书摘，是「这本对你的处境」 |
| `boundary_hints` | 否 | `Partial<Record<FactorId,string>>` | ≤30 字/项，某因子低分时的诚实提示 |
| `publisher_summary` | 否 | string | ≤120 字，S2 缺素材时降级用，渲染须标注「简介来自出版方」 |
| `content_warning` | 否 | `('suicide'\|'violence'\|'sexual_abuse'\|'eating_disorder'\|'addiction'\|'grief'\|'terminal_illness')[]` | 安全字段，参与硬过滤。**必须是 7 值**：少 `grief` / `terminal_illness` 这两个，`EX-terminal` 就永远不可能命中——标注人标不上、规则也读不到，**整条链路不报错，只是安静地失效** |
| `series_id` | 否 | string | 同系列去重 |
| `core_match` | 否 | `{book_id, method:'isbn'\|'title_author'}` | 仅用户书 |
| `content_ready` | 是 | `'full'\|'readable'` | `readable` = 用户导入书缺打分字段：能读，但不入个性化推荐池。**不要再加 `completeness` 字段**，「能不能读」由 `availability` 唯一表达 |
| `data_version` | 是 | `YYYY.MM.DD` | 缓存校验 |

> **必填边界**：核心库 300 本，`one_line_what` / `structure_note` / `one_line_gain` / `first_action` / `match_brief` 五个文案字段**全部必填**（构建期校验，缺一即 fail）。用户导入的书允许缺失，此时 `content_ready = 'readable'`，理由只出 S1+S2 并明确标注缺口。
>
> **`structure_note` 为什么从「可选 ≤40 字」改成「必填 ≤38 字且以句号结尾」**：它不是补充说明，**它是卡面那句唯一的来源**。≤40 在 13px 中文 343px 卡宽下（每行约 19 字、2 行 38 字）**物理上显示不下**，写 40 等于让内容侧写到 40、UI 在 38 处切掉——两边都按自己的尺子量，最后互相判不合格。同理，「以句号结尾」必须在**数据侧**保证，不能靠渲染时找句号：若靠渲染，一旦数据里那句没有句号，就得回退到硬截，卡面立刻出现半句话。
>
> **`reason.promise` 与 `structure_note` 的关系**：`promise` 是构建期生成的（不是书目字段），且**构建期断言 `promise.startsWith(structure_note)`**。`structure_note` 是 `promise` 的第一句——让这件事在构建期成立，卡面就永远不需要切分句子。
>
> **禁止字段 `last_reviewed`**：我们没有编辑时间线，且它会让结果随数据维护时间漂移，破坏「同输入同输出」这个可单测的前提。**tie-break 里不得出现任何时间类字段。**

### 5.2.1 `Diagnosis`

```
{
  diagnosis_id, created_at,

  answers: {
    domain,                    // 第 1 屏，用户选的困境域 —— 不是书的 category_l1
    problem_tags,              // 第 2 屏
    primary_tag,               // 必填
    primary_source,            // 'explicit'（第 2 屏追问）| 'single'（只选 1 项）
    time_budget, difficulty_pref, urgency, form_pref, depth_pref,   // 第 3 屏，键名见 §6.1
    free_text?
  },

  need_tags: { tag, weight, source: 'option'|'free_text', user_phrase }[],
  include_heavy,               // 用户偏好，默认 false
  excluded_book_ids
}
```

> **只存用户的选择，不存派生值。** 难度上限（2/3/5）、时长预算、各因子的 `target` 一律运行时从 `answers` 算。存下来就会出现「规则改了、老记录还是老规则算出来的」这种分叉，而且它**不报错**——半年后复盘会发现同一份诊断两次跑出不同档位，查不出为什么。
> **`primary_tag` 必须存进诊断记录**，不能运行时重算。它是档位封顶的依据，也是 S1 回引顺序、破冰位选书的依据；重算意味着这三处将来可能得出不同答案。
> **`source='order'` 不存在**——主诉不允许由勾选顺序推断。

> **`domain` 不是 `category_l1`。** 前者是用户的问题域（6 个，用于过滤与「换个角度」话术），后者是书的文体（文学 / 心理 / 思想哲学 / 社科 / 传记 / 其他，只用于多样性配额）。两个字段长得像、用途完全无关，混用会让「同文体 ≤2」静默变成「同问题域 ≤2」——测试全绿，排序变了。

> **`include_heavy` 是内容偏好，不是心理状态声明。** 它记的是「要不要把含**临终 / 丧亲**题材的书也放进推荐」，取值来自用户的二选一，默认「先不用」。
> **不能写成「我可以承受沉重的题材」这种句式**：那要求用户先对自己的状态做一次评估，而处在低状态的人最没能力做这个评估——把责任推回去，正是这条过滤存在的反面。同一件事，问「要不要看这类内容」是偏好，问「你承受得住吗」是让用户担保自己。
> **它只豁免 `EX-terminal`，不豁免 `EX-trauma`**（见 §6.3①）：一个问题只能承诺它写出来的范围，写了「临终或丧亲」就只能放行这两类。
> 它是**偏好**，所以每次诊断重新问、不预选、不记忆；用户改主意时，重新答一次问卷就是路径。
> 由它推出的过滤谓词**运行时不落库**，只存 `include_heavy` 这个原始选择。

### 5.3 `Recommendation`

{

## 6. 推荐算法（锁定）

### 6.1 问卷 → 四轴

| 屏 | 问题 | 形式 | 驱动 |
|---|---|---|---|
| 1 | 现在最想解决哪一类 | 单选 6 项 + 说不上来 | 候选池 + 标签域权重 |
| 2 | 具体是哪种感觉 | 多选 ≤3（随第 1 屏联动） | 权重 **0.60 / 0.25 / 0.15**；选了 ≥2 项时**同屏必答**一句「这些里面，哪个是你现在最想先解决的？」定主诉（单选，不新增屏、不预选、不可跳过） |
| 3 | 读书条件（同屏 5 组 chip） | 单选 ×5 | 见下 |
| 4 | 还有想说的 | 自由文本 ≤140 字，可选 | 命中**已有**标签：权重取 `max(该标签现有权重, 0.6)`；命中**新**标签：权重 **0.15** |

第 3 屏 5 组 chip（**答案键的唯一出处就是这张表，别处只准引用、不准重列**）：

| 组 | 答案键 | 选项值 | 驱动 |
|---|---|---|---|
| 3-a 每天能读多久 | `time_budget` | `10m`（10 分钟）/ `30m`（30 分钟）/ `1h+`（1 小时以上） | 认知负荷修正 + 篇幅默认值 |
| 3-b 能接受多难 | `difficulty_pref` | `easy`（越轻松越好）/ `challenge`（有点挑战）/ `hard`（不怕难） | 认知负荷 **25 / 50 / 75** + 难度硬上限（2/3/5） |
| 3-c 希望多快见效 | `urgency` | `3w`（这三周就要用）/ `1m`（一个月内）/ `none`（不着急） | 紧迫度 **75 / 50 / 25**（读数越低越不急）。它驱动 `readability` 的 target，且**越急要求文字越易读** |
| 3-d 想要怎么带你 | `form_pref` | `story`（一个人的故事）/ `method`（一套方法）/ `framework`（完整框架） | 结构需求（15/60/90） |
| 3-e 更想要哪种收获 | `depth_pref` | `howto`（具体做法）/ `howto_why`（做法加为什么）/ `why`（底层原理） | 深度（15/50/90） |

> **`load_target` 不是答案键**，它是 `difficulty_pref` 映射出来的派生值（25/50/75 → 难度上限 2/3/5）。把派生值当答案键存，会让「用户选了什么」和「我们算成了什么」混成一层，将来改映射就再也分不清是哪一边变了。

`need_tags` 上限 6 项，超出按权重截断。

> **自由文本不能进入主诉位。** 它是「补充」，不是「主诉」——主诉只能来自第 2 屏的显式选择。
> 更要紧的是防稀释：若命中已有标签就给 0.6，而原本那一项是 0.15，`Σ用户权` 会变大、主诉覆盖率被摊薄——**用户多写一句话，反而让自己的主诉变得不重要了**。所以命中已有标签时取 `max(现有, 0.6)`（不叠加），命中新标签时给 0.15（与第三标签同级，排在所有显式选择之后）。

> **所有产生 target 的选项，取值只能落在 25 / 50 / 75。** 因为 `target = 1 + 4×x/100`，而书的属性是整数刻度（1–5）。x 取 60 时 target = 3.4，**没有任何一本书能落在 3.4 上**，最接近的整数距离 0.4 → `difficulty.fit` 最高只能到 9000，永远拿不到 10000。
> 后果比"少 100 分"严重：如果只有部分选项能让 target 落在整数上（比如"越轻松"=25 → 2.0，"有点挑战"=60 → 3.4），那么**选"有点挑战"的用户在结构上就拿不到 strong**——这不是偏好差异，是系统性歧视某一类答题者。取值一律 25/50/75，target 恒为 2/3/4，三档同权。

**跳答处理（重要，不要写成「按中性处理」）**：第 3 屏某组未答时，该组驱动的因子**整条从本次计算中移除**，其权重按比例重分配给其余因子并归一化到 10000。理由：给未观测的维度填中位数，等于假装我们知道答案——那一个因子会稳定输出 5000 分，既不可解释，也会把真正有信号的因子挤薄。`weights_used` 字段必须记录本次实际权重，便于复盘。

只有第 1 屏（困境类别）与第 2 屏（具体感觉）是必答；第 3 屏 5 组允许全部跳过，此时退化为「困境 + 可获得性」两因子排序，结果页顶部必须说明「补上读书条件能排得更准」。

### 6.2 七因子权重（和 = 10000，单测锁定）

| 因子 | 权重 | 计算 |
|---|---|---|
| `problem` 困境契合 | **3800** | `Σmin(用户权, 书权) / Σ用户权`（覆盖率口径，非 Jaccard）。用户侧权重 0.60/0.25/0.15（主诉 / 次 / 第三）。**主诉来源只有两种**：`source='explicit'`（第 2 屏追问，≥2 项时必答）或 `source='single'`（只选了 1 项，它本身就是主诉）。**禁止用勾选顺序推断主诉**——顺序只证明手指先碰到它。**叫 `problem` 不叫 `topic`**：它比的是「书的困境标签 vs 用户的困境标签」，而 `theme_tags` 才是主题且不参与打分 |
| `difficulty` 难度匹配 | 1800 | `10000 − bp(\|book.difficulty − target\| / 4)`，`target = 1 + 4×认知负荷/100` |
| `depth` 深浅匹配 | 1200 | 三档序数距离：同档 10000 / 相邻 6000 / 跨档 1500 |
| `form` 体例匹配 | 1000 | 同 `depth`，三档序数距离 |
| `length` 篇幅匹配 | 1000 | 档差 0→10000 / 1→6000 / 2→2500 / 3→0；「不限」→7000 |
| `readability` 表达匹配 | 700 | `target = 1 + 4×(100 − 紧迫度)/100` → 急 75→2（要易读）、不急 25→4（可啃硬文字）。**方向不能反** |
| `availability` 可直读 | **500（5%）** | inline 10000 / 自备 5500 / 外部 2500。**上限 800，只作扳机不许做主排序力**；真正承担「优先推能读的」的是 ③ 的 tie-break 第 4 级 |

### 6.3 执行顺序（不可颠倒）

```
① hardFilter  →  ② score  →  ③ rank(6 级链)  →  ④ slotAssembly  →  ⑤ relax  →  ⑥ tier
```

**① 硬过滤**（打分之前）。**规则一律用下面的名字引用，不要用 F1/F2 编号**——两边编号不是一套，跨文档引用编号必错：
- `EX-difficulty`：`difficulty > difficulty_cap` → 剔除（cap：越轻松 2 / 有点挑战 3 / 不怕难 5）
- `EX-load`：`entry_level ≥ 4 && 认知负荷 < 40` → 剔除
- `EX-trauma`：`content_warning ∩ {suicide, sexual_abuse} ≠ ∅`，且**用户域 = 「情绪与自我」**，且用户选「越轻松」→ 剔除。**不可豁免**
- `EX-terminal`：`content_warning ∩ {grief, terminal_illness} ≠ ∅`，且**用户域 = 「情绪与自我」**，且用户选「越轻松」，且 `include_heavy = false` → 剔除

> **`include_heavy` 只豁免 `EX-terminal`，不豁免 `EX-trauma`。** 这条不对称是刻意的，理由是**文案必须说得出口**：那个开关的中文是「这类内容里有涉及临终或丧亲的，要不要一起看？」——它只承诺了临终与丧亲。如果同一个开关也放行自杀与性暴力题材，用户答「一起看」时同意的东西比他读到的问题更多，**而他永远不会知道**。
> 想把 `EX-trauma` 也做成可豁免，就必须把「自伤、性暴力」写进那句问题里——**而那等于在低状态用户面前摆一排最重的词**。两个代价都不可接受，所以这一半干脆不做成选项：想看那类书，走书库或直接搜索，它们在那儿，只是不被推荐。
> **不可豁免的方向只有一个**：默认剔除，必须用户主动打开。**反过来（默认放行、勾选后过滤）等于默认把重内容推给最没准备的人。**

> **为什么要有 `EX-terminal` 这一条**：`EX-trauma` 挡不住更常见的情况。《当呼吸化为空气》《此生未完成》既不含自杀也不含性暴力，但把一个说「我就想轻松点」的人推给一本讲临终的书，是这类推荐最恶劣的失败方式——**他会以为是系统在暗示他没救了。** 丧亲（`grief`）同理。
>
> **域为什么只有「情绪与自我」**：这个域里「越轻松」意味着人处在低状态、明确说了读不动重东西。`人生转折` 必须排除在这条之外——疾病与照护、亲人离世这类书就在那儿，去那里的人是在**找**它们，排除等于把他的问题藏起来。金标 G10 就是钉这条边界的：它在 `人生转折`、选「不怕难」，**任何一道剔除都不该命中它**。
>
> **已知缺口（不假装已解决）**：「关系」域里同样可能有刚失去亲人、又选了「越轻松」的用户，`EX-trauma` / `EX-terminal` 现在都**不会**命中他们。没有把「关系」加进触发集，不是因为它安全，而是**加进去就扩大了一条会静默删书的规则，而我们没有任何数据说这个扩大是对的**。这条缺口记在这里，等闸门 0 跑完、有真实画像分布再定；届时若要加，是改规则 + 改金标反向用例，不是悄悄改个集合。
>
> **两个易错点**：① 这里判断的是**用户第 1 屏选的域**，不是书的 `category_l1`（一个是问题域、一个是文体，混用会静默改变过滤结果）；② 用户没选「越轻松」（含整组跳答）时**不剔除**——只凭标签就剔除，会把所有丧亲题材书从所有域里清空。

**③ 6 级 tie-break 全序链**：
```
score_bp↓ → problem.fit↓ → difficulty.fit↓ → availability↑ → est_reading_hours↑ → book_id↑
```
第 6 级 `book_id` 保证全序，不依赖 `Array.prototype.sort` 稳定性，也不用任何时间字段。（原方案里 `completeness` 那一级已删除：它与 `availability` / `content_ready` 三重重叠，且能进池的书恒为 `full`，等于恒真条件。）

**④ 破冰位**：第 1 位若「`est_reading_hours > 3` 且非 inline」，在 `strong+worth` 中找第一本满足「≤3h 或 inline」者交换，记 `promoted_for_icebreak = true`。

**⑤ 多样性配额**：rank 1–5 内同作者 ≤2、同 `category_l1` ≤2；不足 5 本时第二遍无配额回填。

**⑥ 放宽阶梯**（触发条件：`strong + worth < 2`）：

| 级 | 动作 | 文案基调 |
|---|---|---|
| L0 | 无 | 正常 |
| L1 | 标签升族（48 → 8 族） | 正常 |
| L2 | `w_topic` 降至 1500 后归一化 | 「没有完全对口的书，这几本在难度和篇幅上最贴合你」 |
| L3 | `w_topic = 0` | 「暂时没找到直接相关的，这几本也许能帮你换个角度」 |
| L4 | 返回空 | 「试试换个说法」+ 重填 / 按品类浏览 |

**⑦ 分档**：

| 档 | 区间 | 枚举 | 中文 | 视觉 |
|---|---|---|---|---|
| 1 | ≥8000 | `strong` | 高度契合 | 3 方块全填 |
| 2 | 6000–7999 | `worth` | 较为契合 | 2 方块 |
| 3 | <6000 | `explore` | 换个角度 | 1 方块（第三组不显示） |

**三个值只能是 `strong` / `worth` / `explore`。禁止 `high`、`mid`、`low`、`fit`。** Token 组名 `color.tier.{strong,worth,explore}`。

> **主诉未命中 ⇒ 档位封顶 `explore`，与总分无关。**

> 主诉是分档的**硬前提**，所以它不能有"猜"的成分。这也是为什么它是一个必答单选而不是可选一问：它错了，档位就错，而且错得很安静（封顶只让档位降级，不报错）。与其事后统计「有多少人的档位建立在猜测上」，不如让猜测不存在——那一问的代价是一次点击，而一次点击已经在同一屏上发生过两三次了。
> 定义：**`primary_hit` 是整型基点，取值 0–10000**，`primary_hit = round(10000 × min(用户主诉权, 书对该标签权) / 用户主诉权)`。`primary_hit = 0` 即主诉未被覆盖。
> **必须写清单位**：全项目所有 `*_hit` / `*_fit` / `score` 都是 **0–10000 的整型基点**，不是 0–1 的小数。混用不会报错，只会让「`primary_hit ≥ 8000`」这类判据恒为假或恒为真——而且它看起来完全正常。
> 为什么需要这条：其余六个因子在理想情况下合计 6200，**一本完全不沾题的书，只要难度/篇幅/体例全中，就能拿到 5900–6500 → 自动落进 `worth`（较为契合）**。而"较为契合"这个说法对一本没回答他问题的书是谎话。
> 这条封顶不改分数、只改标签，所以调试时分数与档位可能"不匹配"——这是**故意的**，`tie_break_trace` 里要输出 `capped_by_primary_miss: true`。

### 6.4 字段覆盖率与降级（v2.4）

**口径**：`book_coverage_bp` = 该书**真的标注过**的因子基准权重之和（`availability` 恒计入，它来自渠道字段）。

| 书 | 覆盖字段 | `book_coverage_bp` |
|---|---|---|
| 核心库（28 字段人工核对） | 全部 6 个 | 10000 |
| enriched 层（派生困境标签） | `problem` + `availability` | 4300 |

**三条锁定规则**：

1. **缺失字段对应的因子整条不参与打分**，权重按 §6.1 的跳答机制重分配，**禁止给缺失字段填默认值**。理由与跳答同一条：填中位数会让一个没观测过的维度稳定输出 5000 分，既不解释得通，又把真信号挤薄。
2. **单测锁定**：未覆盖字段填任意值，`score_bp` 必须完全相同（填 1 与填 5 同分）。
3. **档位按覆盖率封顶**：`book_coverage_bp < 6000` 时最高只能到 `worth`，`tierOf` 输出 `capped_by_low_coverage: true`。理由：只凭 43% 的信息不能说「高度契合」——那是在用"沾题"冒充"适配"。

> **`primary_hit` 的单位**：`min(用户主诉权, 书对该标签权)` 两边**都必须是 0–1**（书的 `problem_tags[].weight` 合同值域 0.1–1.0）。任一侧改成基点会让 `primary_hit` 恒等于 1–2 分——档位看着正常（只判 `=== 0`），但那个数已经不是命中率。

### 6.5 宽池取书：域映射、证据分级、截断（v2.6）

宽池（`WideResults`，全库 6551 本里按困境域取书）有三个**不会报错**的失效点，本节把它们钉成契约。

**① 域映射必须显式列表，不许按名字猜。** 两套域枚举不是一回事：候选池是豆瓣的 7 个域（`growth/relationship/thinking/psychology/career/meaning/work`），`ProblemDomain` 是问卷的 6 个域（`emotion/relationship/work/habits/thinking/transition`），**只有 3 个名字撞上**。按名字求交集的结果是情绪、习惯、人生转折三个域宽池恒为 0，而接口返回的是 `size: 0` —— 和"这个域真的没书"长得一模一样。

唯一真源 `catalog/domain-map.json`，构建期脚本与运行时同读一张（各写一遍必然分叉）：

| `ProblemDomain` | 候选池域 | 下限 |
|---|---|---:|
| `emotion` | `psychology`, `meaning` | 20 |
| `relationship` | `relationship` | 20 |
| `work` | `work`, `career`, `meaning` | 20 |
| `habits` | `growth`, `psychology` | 20 |
| `thinking` | `thinking`, `growth` | 20 |
| `transition` | `career`, `meaning` | 20 |

未知域返回**空数组**（不是 `[domain]`）：宁可池子空着让人看见，也不要按名字猜出一个错的中毒池。

**② 派生截断禁止用字符串序决定保留谁。** 一个标签在同权候选里按 `tag` 升序取 `top_n=3`，会让 `speaking-block`（s 开头）被 `b`/`c`/`e` 开头的标签系统性挤掉——实测职场域 485 本相关书里只剩 5 本带 `speaking-block`。改为 `offset = hash32(book.id) % n` 的轮转窗口：**确定性保留**（同输入同输出），但不再有系统性偏向。`verify-derived` 断言「各标签保留率不低于中位数的 60%」，把"公平"变成每次都跑的数。

**③ 证据分级：书名证据与兜底证据不是一回事。**

| 证据类型 | 权重 | 含义 |
|---|---:|---|
| 书名词表命中 | 0.85（+ 5% 补充位，封顶 0.9） | 书名直接写着这件事 |
| 豆瓣大类兜底 | 0.4 | 只是同属一个大类 |

默认**只收书名证据**（`TITLE_EVIDENCE_MIN = 0.85`）。强证据池不足 `MIN_POOL_FOR_STRONG = 20` 本时**整池降级**并在结果里逐本标 `weak_ids`，界面标「这条相关性较弱」——拿兜底证据冒充精准匹配，比池子小更糟。

### 7.1 推荐卡信息层级（8 项，按阅读顺序）

| # | 元素 | 规格 |
|---|---|---|
| 1 | 书名（+ 书脊卡） | 书名 18px / 590 / 2 行；书脊卡 56×84，**仅 ≥768px 显示** |
| 2 | **第 2 行：`match_brief`（左）+ 档位块（右）** | `match_brief` 13px/510/`#3D4340`，`flex:1 1 auto; min-width:0`，`-webkit-line-clamp:2`；档位块 `flex:0 0 auto` 不收缩，3 个 8px 方块 + 11px 文字 |
| 3 | **S2 首句**（这本书讲什么） | 13px 灰，**≤2 行、≤38 字**。渲染 `structure_note` **原值**（它自带结尾句号），**不得按句号切分、不得硬截**；完整 S2（60–90 字）在展开区 |
| 4 | 可用性徽标 | **纯文字**，无图标，7 字内 |
| 5 | **`mismatch`「不过：…」** | 13px / **`neutral-800`**（不是警告色）+ 12px 三角图标 + 前缀「不过：」，**折叠时 1 行截断；展开后这一行原位变成全文，不在展开区另起一段**。缺失时整行不渲染 |
| 6 | **难度 · 篇幅 · 时长** | 12px 灰，20 字内，如「入门 · 12 万字 · 约 4 小时」。**必须在卡面，禁止折进展开区** |
| 7 | 主按钮 | 32px 高，文案随态变 |
| 8 | 展开区 | S1（最前）/ S2 全文 / S3 + 命中依据 + 作者 / 译者 / 出版社 / ISBN。**不含 B1**——它由第 5 行原位展开，另起一段就是同一句出现两次 |

**为什么 S2 首句在卡面、S1 不在**：两者一个关键差别——S2 是**书级独有**（每本书讲的当然不同），S1 是**标签级共享**（同一主标签的书会给出几乎相同的句子）。判断一句能不能上卡面，判据不是"它重不重要"，而是**"五张卡并排时它会不会重复"**。会重复的下沉，不会重复的上留。
但 S2 只留首句，且**必须是完整的句子**：13px 中文每行约 19 字，两行 = 38 字，正好装下一句完整的话。**不允许压成 1 行**——1 行只有 19 字，砍到 19 字就只剩半句，用户读到「这本书用认知行为疗法解释……」然后没了，比不放更糟。完整版 60–90 字在展开区。

**S1 放展开区，卡面只留 `match_brief`** —— 这是本页最重要的一条结构决定，理由是「独有句上卡面、共享句进折叠」：
`match_brief` 是**书级独有**（逐本预写），S1 是**标签级共享**（同一主标签的两本书会渲染出几乎相同的句子）。两句都上卡面，等于把 S1 的重复暴露在最显眼的位置，五张卡里出现三句一样的话——那正好摧毁「逐本说明理由」这个承诺。
`mismatch` 补上了另一半：卡面上仍有一句关于「这本不适合你哪里」的诚实说明，它比 S1 更能帮用户判断「这本是不是给我的」。

> **但「被理解」不能从首屏消失。** 它由结果页顶部的**诊断摘要条**承担，且必须满足两条：① **逐字回引用户原词**（`user_phrase`，不许改写）；② 全页只出现这一次。一次说透，胜过五张卡各说一遍。
>
> 卡片单卡高度约 **240px**（按 375px 视口、8 行文字实测；含 B1 行）。**骨架屏不含 B1 行**，只承诺与"无 B1 的真卡"同高（±4px）：三块占位条分别对应书名（1 行）、`match_brief`（2 行）、S2 首句（2 行）。带 B1 的卡比骨架高约 21px，**这个偏差是已知代价，不是缺陷**——结果页单列竖排，卡高不一致不影响阅读；反过来为对齐留一个空行，用户会把它读成「这里本该有内容、没加载出来」。
> **不要为了凑「骨架与真卡严格同高」去改骨架行高**：B1 是否出现取决于该组有没有同组重复（见 §7.1 的组头上提规则），同组内本来就存在两种卡高，一个对不上的精度指标比一个宽松但成立的指标更糟。CLS 门槛按「骨架 → 无 B1 卡 ≤ 0.1」判定。
> 为什么接受 240 而不是 190：190px 的账是靠把人名缩到 16px、按钮降到 30px、`match_brief` 硬截到 2 行挤出来的——**每一处都在拿可读性换高度**。而 240px 在 812px 视口下仍能露出 2.5 张卡（含第二张的 `match_brief`），已经足够让人判断"要不要往下滑"。**首屏的目标不是让人一次看完五张，是让他决定要不要继续。**

**第 2 行必须「差异在左、标量在右」**：若把 28 字排在档位标签右侧，五张卡会全部从「高度契合」四个字开始读——同头，正是本产品要修的病；且左边缘会随档位文字长短参差。375px 实测：卡内宽 343 − 档位块 ~82 − 8 = 253px，13px 中文每行约 19 字，28 字正好 2 行。
`match_brief` 缺失时同位置降级为「命中了：A · B」（12px `#5F6660`，1 行），**不留空位、不显示占位符**。

> **`mismatch` 必须在卡片首屏可见，禁止只放详情页或折叠区。** 它存在的唯一目的是回答用户看到「高度契合」那一秒的「凭什么不是 100%」——那个念头不会等到点开详情才出现。放折叠区只有少数人看得到，信任收益归零；放 S1 之前像拒信；放按钮之后就是 fine print。识别靠**三角图标 + 「不过：」前缀 + 位于按钮之前**，不靠颜色——顺带即色盲可用，**不得改成纯文字无图标**。

> **同组重复则上提到组头，卡上不重复。** 这不是新规则，是卡面准入判据的第二次应用——判据不是「它重不重要」，而是「几张卡并排时它会不会重复」。
> - 判据按**同组内同一条提示的出现次数**：≤1 次 → 逐卡陈述；≥2 次 → 上提到组头一次、卡上不渲染。**不要按档位或符号这类枚举分支**——那样会漏掉「两本都是 inline、但都缺同一章」这种同形不同因的情况。
> - 组头那句由 `phrases.json` 的**因子级句式**承担（7 个 `FactorId` 各一句，一次性写完，**不随书增加**，因此不计入 60 本工时）。它只覆盖 7 个因子；「因子之外」的组头说明（例如「本组没有能直接读的」）属于另一套机制，**不得塞进因子表**。
> - `boundary_hints` 的写作约束：**不得描述卡面已有专属元素的维度**（可获得性有徽标、难度·篇幅·时长有元数据行、体量有第 6 项）。重复不增加信息，只稀释信号。
> **这一行禁止用警告色（`warn` / `danger`）。** 五张卡里可能有四张都带这一行，若每张都挂一个琥珀三角，要么被习惯化到看不见，要么被读成「这几本都有毛病」——而它想说的是「这本没覆盖到你的全部需求」。警告色留给真正需要用户行动的错误（文件过大、导入失败）。

### 7.1.1 两条安全与可获得性条款（P0-16 / P0-17 的呈现细则）

**危机资源条**
- 位置：诊断摘要条之下、第一组之上。不能等用户滑到底才看见。
- 与 P0-17 说明条**互斥**：「情绪与自我」域不出 P0-17，其余域不出危机条。此互斥写死在渲染条件里，不留实现自由。
- 资源页 `/crisis` 三禁止：**禁止任何书籍推荐、禁止「读完这本书你会好起来」类关联、禁止阅读入口与进度提醒**。把求助和读书绑在一起，正是这条资源条要避免的暗示。
- 空态：`crisis_resources.json` 缺失或为空 → 资源条不渲染，但结果页对应位置必须渲染一段静态文案「如果你现在不太好过，可以在当地心理援助热线或精神卫生机构寻求帮助」。**安全网不允许因为构建出错而静默消失。**

**无 inline 域说明条**
- 触发条件**数据驱动**：该域 inline 覆盖书数 = 0 时显示，**不硬编码域名**。硬编码会在补进一本公版书后变成假话。
- 默认展开、可折叠；折叠状态按域持久化（老用户不必每次念经）。
- 折叠后**卡片上的「需自备电子书」标签必须保留**——事实不能随说明条的折叠一起消失。

**结果页纵向顺序（排序原则：安全 > 约束降级 > 可获得性说明 > 内容）**：
诊断摘要条 → 危机资源条（仅「情绪与自我」）→ 放宽提示（`relax_level > 0` 时）→ 无 inline 说明条（该域 inline 覆盖数 = 0 时）→ 三组卡片 → 页尾。

危机条**吸顶**（`sticky`）而非吸底：吸底会贴住每张卡主按钮所在的区域，一条不可关闭的条持续干扰点击。移动端 `top: 56px` 让开应用栏。

### 7.3 库外兜底（三条路径，全部不许伪造数据）

核心库 300 本之外的书写入，只允许这三条路径。**外链检索（豆瓣 / 微信读书 / OpenLibrary）只做「跳过去看一眼」，不落库、不入候选池、不参与打分、不生成理由。**

| 路径 | 触发 | 落库内容 | 能否进推荐 |
|---|---|---|---|
| A 用户自带文件 | 导入 EPUB / TXT | 文件 + 从文件解析出的元数据 | **否**（`content_ready='readable'`，不入池） |
| B 手动录入 | 30 秒表单：书名 + 作者 + 为什么想读 | 用户填的字段 + `book_id = user:xxx` | **是，但有硬上限** |
| C 外链检索 | 搜不到 → 给三个外链 | 不落库 | 否 |
| **D 系统直接列出** | 库内结果不足 5 条 | **不落库** | **否**（与库内结果并列展示，不混排） |

**路径 D 的三条硬约束**：
1. **不落库、不入候选池、不参与打分。** `ExternalSuggestion` 类型里**没有** `book_id` / `score_bp` / `factors` / `tier` 这四个字段——不是"算不出来所以留空"，是**这些字段对它根本不成立**。一旦让它带上 `score_bp`，它就会和库内书排进同一张列表，而那个分数没有任何标注支撑，是凭空的。
2. **理由禁止引用任何库内打分字段。** 不得出现契合度、分数、档位、排名、权重一类说法。只能说「它讲什么」和「它对着你的哪一点」。这条由 `assertExternal()` 在运行时断言（`FORBIDDEN_REASON_TERMS`）。
3. **卡片必须标注「未入库」。** `badge` 是字面量类型 `'未入库'`，少写它编译不过；数据来自 JSON 的部分再由 `assertExternal()` 兜一次。少了这个标识，用户会以为这本书和上面几本一样是"我们读过的书"。

> **为什么要有 D**：A/B/C 三条都要用户动手，而用户当时问的是"我现在这样该读什么"。回答"库里没有、请你自己导入"或"给你三个链接自己去看"，是**把我们自己的库存问题变成他的空手而归**。D 让系统直接说出书名——那正是用户要的东西。
>
> **推荐数量不受书库规模限制**：库内不足 5 条时用 D 补到 5 条（见 `src/engine/recommend.ts`）。库外候选也不足时**如实少给**，不为了凑数伪造。
>
> **D 的排序不产生分数**：只按主题标签重合数排先后，重合数是排序键、不是分数，不进任何加权、不参与档位。排序键 `(重合数降序, 书名升序)` 保证全序与确定性（不用 `localeCompare`，它依赖运行环境的区域设置）。

**路径 B 的推荐约束（三条同时生效）**：
1. **绝不进前 3 位**。用户自己录的书若排到第 1，整个结果的「诊断」属性就废了——他看到的只是自己刚写下的想法。
2. **档位上限 `worth`**，永不出 `strong`。缺失打分字段的书没有资格宣称「高度契合」。
3. **不参与多样性配额计数**，因为它的标签不可信；否则一本自建书会把同品类的真书挤出前 5。

路径 B 存在的唯一理由：让「我搜的书你们没有」有一个不撒谎的出口，而不是逼运营去扩库。卡片上必须显示「你录入的书」标识。

### 7.4 校准闸门（防止「全都不契合」）

档位阈值是 **绝对值**（8000 / 6000 bp），不是分位数。这意味着如果权重或标注有偏差，可能一次都不出 `strong`，页面就成了「5 本都不合适」。

**闸门 0（金标正对照，先于比例闸门执行）**：人工写 **10 个画像**——先写处境，再按常识回答问卷，**最后才指定**那本「就是为他写的」书。等人已经认定「这本书就是为这个人写的」之后，再看引擎给什么。**产出两个分开计数的指标，都要 ≥7/10**：

| 指标 | 定义 | 不达标时该改什么 |
|---|---|---|
| **认出率**（校准，主判据） | 金标书档位 = `strong` 的条数 | **口径 / 权重 / 标注**。这一项错，调阈值是徒劳的——问题不在靶子偏了，在靶子画错了 |
| **首屏率**（回归，副判据） | 第 1 位档位 = `strong` 的条数 | **R1 破冰位与排序**，不是权重。第 1 位被换下去而档位没变，是排序问题不是匹配问题 |

**为什么必须分成两个数，不能合成一个「≥7/10 通过」**：合成之后一次 6/10 可能是 3 条校准错 + 3 条排序错，而报告只告诉你「没过」——于是最自然的反应是去调权重，把排序的 bug 越调越深。**判据的价值不只是挡住不合格，还在于让失败指向正确的那一层。** 两个数同一次跑出来，报告里分两列，不许求平均。

- 金标集必须在**第一次跑之前**提交进 `tools/gold-set.json`，跑完再改要写 ADR。否则会出现「把金标改到通过」这种自欺——它不是造假，是标准漂移，而且没人会发现。
- 为什么需要它：如果引擎对「人认为完美对口」的样本都给不出 strong，那 30% 永远达不到，此时**调权重是徒劳的，因为问题在口径不在权重**。没有正对照就开始调参，等于不知道靶子在哪。
- 两个方向的判据（比 30% 好判）：**主诉完整命中却不到 strong → 口径错**；**只对上一个陪衬标签却进了 strong → 阈值被夸饰**。两个方向都挡住才算校准成功。

**金标集格式（`tools/gold-set.json`，10 条，字段即契约）**：

| 字段 | 必填 | 类型 | 约束 |
|---|---|---|---|
| `id` | 是 | string | `G01`…`G10`。**不复用、不回收**——删掉一条就永久空号，避免「改到通过」时编号对不上账 |
| `domain` | 是 | `ProblemDomain` | 6 域全覆盖，每域 1–2 条 |
| `situation` | 是 | string | 100–150 字，用这个人自己会说的话写他此刻的处境。**不得出现书名、作者、流派名、症状学名词** |
| `answers` | 是 | object | 按 §6.1 的**答案键**填：第 1 屏 `domain`、第 2 屏 `problem_tags`（含 `primary_tag`）、第 3 屏**全部组**（当前 5 组：`time_budget` / `difficulty_pref` / `urgency` / `form_pref` / `depth_pref`，**组数以 `questions.json` 为准，不写死为 5**）、`free_text?`。**键名唯一出处是 §6.1 那张表，这里只是引用**——一旦两边各列一套，必然出现一个用 `load_target`、一个用 `difficulty_pref` 的分叉 |
| `expect_book` | 是 | string[] | 1–2 个 `book_id`。写 2 个必须在 `why` 里说清「为什么这两本对这个人等价」，说不清就删到一个。**字段名里刻意没有 `top1`**：位置由 R1 破冰位决定，是另一件事；叫 `expect_top1` 会诱导实现者顺手写成位置断言，把两个判据又粘回一起 |
| `expect_tier` | 是 | `'strong'` | 恒为 `strong`。金标验的是「理想对口能不能被认出来」，不是分档 |
| `why` | 是 | string | ≤80 字，回答「凭什么这本书就是为他写的」。**这句是人先说的，不是引擎算完再补的** |
| `frozen_at` | 是 | string | ISO 日期。此后的任何修改都要 ADR |

六条硬约束：
1. **`answers` 不得由引擎反推。** 顺序必须是：先写 `situation` → 再按常识回答问卷 → 最后才填 `expect_book`。顺序反过来，画像是「为了某本书而写的」，金标集就成了循环论证，而且它还会显示 10/10 通过。
2. **只允许填问卷里真实存在的选项值**，不得为了拟合自造中间值（如把 25/50/75 写成 60）。写了就是给引擎定制输入，金标集立刻失去「独立样本」身份。
3. **10 条里 ≥5 条必须是 `bring_your_own`。** 首发 60 本中 inline 只占 7 本；若金标全是公版书，等于只验证了「可获得性权重没写反」，推荐主体一次没验。
4. 构建期校验：`expect_book` 的每个 `book_id` 必须在 60 本首发库中存在；`domain` 与 `primary_tag` 所属域必须一致。
5. **10 条里至少要有 1 条「反向用例」**：它存在的唯一目的，是抓出某条规则被实现得过宽。它不验契合度，验的是「不该被枪毙的书没被枪毙」——主诉清晰可映射、答案不矛盾、无内容警示，因此**任何一道硬过滤都不该命中它**。它一旦被过滤掉，说明某条规则的条件写错了，而不是这本书不好。反向用例必须在 `why` 里写明「它为什么不该被过滤」，否则半年后没人知道它特殊在哪。
6. **金标画像不许跳答**：第 3 屏**全部组**必须填满（当前 5 组；组数以 `questions.json` 为准，**本文件不写死为 5**）。理由不是「样本要完整」，而是**跳答会改变权重本身**——按 §6.1，未答组的因子整条移除、权重按比例重分配。于是这份画像的 `score_bp` 与其他样本不在同一套 `weights_used` 下，**「≥7/10」这个计数就失去意义**，而报告里不会显示这件事。所有样本必须在同一套权重下比较，否则校准测的是「有多少样本碰巧分布均匀」。
   > **这条只约束金标画像，不约束问卷。** 真实用户第 3 屏仍可全部跳过（§6.1 的跳答处理不变）。两者的区别是目的：**用户跳答要的是「还能用」，金标跳答毁掉的是「互相比」**。看到「全部填满」和「可全部跳过」并列时，先分清说的是谁。

闸门 0 通过后，再跑比例闸门：抽样 20 个画像 × 60 本书目，统计**第 1 位落在 `strong` 的比例**。

- ≥30% → 通过
- <30% → **只能调权重与标注，禁止下调阈值**
- 补充判据：若全部候选的 `score_bp` **P95 < 8000**，说明不是「运气不好没有好书」，而是标注或权重让你永远够不到 strong。此时允许**一次性**按实测分布重推阈值，但必须写成 ADR 并把分布数据一起提交，且新阈值同时回写本文件。**只允许发生一次，发生在发布前。**

> **算例必须覆盖三档。** 一个三本全是 `worth` 的算例，无法验证一个三档分类器——它证明不了 `strong` 可达，也证明不了 `explore` 会被触发。所以 `ARCH §3.9` 的算例必须恰好包含 1 本 `strong`、至少 1 本 `worth`、至少 1 本 `explore`，且 `strong` 那本要能说清它凭什么强（困境覆盖 ≥0.72 + 难度恰好命中 + 深浅恰好同档 + 篇幅档相同）。
> 另注：`depth` / `form` 的 `fit` 只能取 `10000 / 6000 / 1500` 三个值（三档序数距离），`length` 只能取 `10000 / 6000 / 2500 / 0`（或「不限」7000），`availability` 只能取 `10000 / 5500 / 2500`。**任何算例里出现 7250 这种数，就是还按旧的 1–5 刻度在算，必须重算。**
>
> 为什么阈值定在 8000 / 6000：七因子下，一本真正对味的书（困境覆盖 78%、难度与体例全中、需自备文件）落在 **8450–9050**；一本只是同领域但维度不对的书落在 **5900–6500**；一本勉强相关的落在 **3600–4000**。三个区间之间是分开的。早期把可获得性权重设在 700 时这套阈值算不准，500 才是自洽的。
>
> **8000 这个数不是拍出来的，它卡在两块短板之间**：
> - **主诉单独撑不到线。** 只盖住主诉、次诉与第三标签都不中，`problem` 只贡献 3800×0.60 = **2280**，是阈值的 28.5%。
> - **其余六项全满也只有 6200**（1800+1200+1000+1000+700+500），同样低于 8000。
> - 两块合起来、且其余六项确实全满，落点是 **8480**，只比阈值高 **480 bp**。
>
> 所以 `strong` 的实际含义是：**主诉被接住，同时其他维度基本不拖后腿，两者缺一不可**。它从来不是「主诉对了就行」。改动权重前先核对这三行；它们一旦不成立，`strong` 就开始退化成夸奖词。
>
> **但不要把它读成「主诉全中是进 `strong` 的必要条件」**——不是。`primary_hit` 只接住 30%、次诉与第三标签满额、其余六项全满时，`problem.fit = 1800+2500+1500 = 5800` → 2204 分，总分 **8404**，仍然进 `strong`。这是 ARCH §3.6 纪律 3 明确记录的**已知缺口**：封顶规则挡的是「完全没接住」，挡不住「只接住一点」。要挡住得再给 `strong` 加一道 `primary_hit` 下限，但那会让档位变成双条件——**留待闸门 0 的实测数据再决定，本轮不拍。**
>
> 这段之所以写这么细：上面任何一条被简化成「主诉对了就给 strong」，档位就会开始撒谎；而撒谎的档位比没有档位更糟，因为它给了用户一个可以引用的理由。
>
> 下调阈值是自欺：它让「高度契合」变成夸奖词，而用户一旦发现第 1 位那本他读不下去，整套诊断的可信度一次性归零。

结果写入 `tools/calibration-report.md`，进仓库。

### 7.5 推荐理由与来源（v2.6）

每张卡有一个可展开的「为什么是这本」，其中**每一句都必须能说出它是从哪来的**。

| 来源 | 界面徽章 | 事实依据 | 例子 |
|---|---|---|---|
| `prewritten` | 书里写的 | 编辑为这本书写的 `match_brief` | 「咨询室里的人生，比方法好入口」 |
| `from_answer` | 你的回答 | 逐字回引主诉原词（`need_tags.user_phrase`），缺省时退回标签文案 | 「你说的是「情绪一直很低落」」 |
| `from_tag_weight` | 书的标注 | 书真的带了、且用户也选了的标签，附该书权重 | 「这本在「情绪一直很低落」上有标注（正是你的主诉），权重 0.8」 |

**两条硬约束**：

1. **没有来源的理由不许上界面。** 一条说不出出处的理由比没有理由更糟——它看起来像结论。
2. **理由不新增任何事实。** 只说「书里标了什么」「你选了什么」，不解释这个标签意味着什么。解释属于诊断建议，而这个产品有书单、没有资质。

契约层 `ReasonSource` 是枚举，`assertReason` 在测试与调试构建中校验「非空文本 + 合法来源」。

## 10. 边界与约束

- 不支持 IE；不支持 `file://` 直接打开（Web Crypto 需 secure context，README 必须写明）
- 响应式：手机 320–767 / 平板 768–1279 / 桌面 ≥1280
- 性能：首屏可交互 ≤3s（4G 中端安卓）；推荐生成 ≤200ms；EPUB 打开 ≤2s（10MB）
- 存储：首次导入调 `navigator.storage.persist()`；未获授权时明确告知可能被清理
- 安全：CSP 由 meta 注入，`script-src 'self'`，禁止 `unsafe-eval` / `unsafe-inline`(script)
- 版权：`npm run audit:copyright` 六条规则任一违反即 fail；**证明不了就当作有版权**

### 10.0 inline 书的「注释」不是公版，除非它是旧注

**原著公版 ≠ 中译本公版 ≠ 现代注释版公版。** 第三条最容易被漏掉：一本《庄子》的原文是公版，但某出版社的「题解 + 注释 + 白话翻译」整体是有版权的，连它的排版和断句都可能构成编辑作品。

**唯一允许的三种来源：**
1. **清代及以前的旧注**：郭象注《庄子》、刘孝标注《世说新语》、王先谦《荀子集解》、陶澍注《陶渊明集》—— 作者均已故超过 50 年，可用。
2. **自己写**的导读与注释（300–500 字导读 + 疑难词条），版权归本项目。
3. 明确标注 CC / 公有领域授权的现代整理本，且保留出处与许可声明。

**禁止**：把任一在售版本的注释、译文、断句直接搬进仓库。这类内容在 `catalog:audit` 里无法机器识别，只能靠这一条纪律。

### 10.1 版权闸门：没有「豁免」，只有「改数据」

```
若 availability = 'inline' 且 translation_copyright ∈ {'in_copyright','unknown'}
  → 构建期 fail，不提供任何运行时开关、环境变量或人工豁免
```

**为什么不做人工豁免**：豁免开关在实践里会退化成「谁着急谁豁免」，而这是唯一一类错了会下架整个项目的错误。
**唯一的通行方式**是改数据，且必须留下证据：把 `translation_copyright` 改成 `public_domain`，同时 `public_domain_reason` 填具体依据（`author_death_50y` / `ancient_text` / `gov_work` / `cc_license`），并在 `docs/copyright/<book_id>.md` 里写清依据来源。写不出那份文件，就证明不了，就留在 `unknown`。
**豁免不是一次点击，是一次带证据的提交。** 这个区别决定了它是否会被滥用。

### 10.2 数据与隐私（v2.2 裁决：不上报，只本地计数）

- **不做任何上报式埋点**。应用不向任何第三方发请求；书目层分片随站点发布，首次搜索时同源加载（公版书 inline 文本打包进构建，字体 subset 自托管），这条承诺不因运营需求破例。PRD §15 的上报式埋点**作废**。
- **仅本地匿名计数**：`localStorage` 记 归一化后的困境域 / 标签命中 / 结果档位 计数器，**不含自由文本**（第 4 屏主诉原文绝不入计数），仅用于 About 页展示"大家都卡在哪"的聚合视图。
- **隐私声明**：About 页明示三句话——所有数据只存在本机、卸载即消失、我们看不到你。
- **计数器键名与结构进 `src/contracts/`**，跟随既有契约纪律（机械可校验，不散落字符串）。
- **本地轻反馈（v2.6，P2-3）**：结果页一个「有用 / 没什么用」。三个边界**写死在代码里，不写在文案里**——只存 `domain / primary_tag / 三档计数 / 判断 / 时间戳`、**不存 `free_text`**；只写 `localStorage`（键 `bookrx.feedback.v1`，上限 200 条，同一诊断只留最后一条）；导出是用户主动点的**一次性 JSON 下载**，不经任何服务器。
  > 刻意不做成"进化机制"：它只是**主观体验样本**。把它说成进化机制，就是在给一个不存在的东西贴标签——而且这个标签会让下一个人以为这里有闭环，从而不再去看真问题。

## 11. 内嵌已知坑

| 坑 | 触发 | 正确做法 |
|---|---|---|
| `ts-fsrs` 的 `Card` 用 `Date` | 经 `JSON.stringify` 后变字符串，回喂调度器算出错误 `elapsed_days`（静默） | 存储层与调度层之间显式 `number ↔ Date` 转换，并写单测 |
| IndexedDB 整行反序列化 | Blob 与元数据同表同行 → 列表页读 50 本 = 150MB | `book_files` 独立表 |
| Blob URL 不释放 | 连开 10 本后移动端 OOM | 契约测试断言 `revokeObjectURL` 次数 = `createObjectURL` 次数 |
| foliate `metadata.title` 三种形状 | string / `{lang}` / 数组，直接强转会炸 | 写 `normalizeMetadata()` |
| Vite 预打包破坏 foliate | 内部相对动态 import 与 `new URL(..., import.meta.url)` | `optimizeDeps.exclude: ['foliate-js']` |
| 中文 TXT 多为 GB18030 | 只支持 UTF-8 会让一半用户导入失败 | 严格 UTF-8 → GB18030 → 手选 |
| 字体混淆被误判 DRM | 大量正版无 DRM 的 EPUB 打不开 | 只把指向内容文档的 AES 判为 DRM |
| 中文 Webfont 全量 8–10MB | 首屏爆炸 + subset 字体跳变 | 只自托管拉丁/数字 subset |
| `pinyin-pro` 700KB | 进 bundle 直接超预算 | 仅构建期使用，CI 检查产物不含其标识符 |

**一条关于校验命令的规矩**：上面每一条都必须在**不达标时以非零码退出**。禁止 `|| true`、禁止把断言写成 `console.warn`、禁止「扫到 0 个命中就当作通过」——0 命中恰恰是「目标文件根本没被扫到」的典型症状，把它当通过等于给整套门禁发了一张空头支票。**一个永远不会失败的检查比没有检查更危险：它会让所有人以为这一项已经有人守着。**

**推论（「未验证」是第三种状态）**：任何检查都有三种结果——**通过 / 失败 / 未验证**。当**扫描对象本身为空**（0 个文件、0 条记录、测试不存在、构建产物的目标 chunk 不在）时，只能报「未验证」并以非零码退出，**不得报「通过」**。实现上强制三条：
1. 每条检查**必须显式声明检索范围**（路径 / glob / 排除项）。**范围为空就是未验证**，不是通过——本项目的故障绝大多数是「扫的地方不对」，而不是「扫到的东西不对」。
2. 每个脚本**第二行必须打印「扫了 N 个文件 / N 条记录」**，且 `N ≤ 0` 直接 fail。
3. 检查项里出现「命中 0 即为通过」时，**同一个断言旁边必须写明谁是分母**——没有分母的「0 命中」不可判定。
4. **存在性检查要数条目，不要数关键词。** 凡是「某规则 / 某字段 / 某文件必须存在」的检查，断言的是**条目数等于预期值**，不是「某个关键词出现过」。理由：关键词在、结构已经坏了——两行表格被粘成一行、去掉一个 `|`、少一列，关键词全都还在，而任何按关键词的校验都不报错。**「0 命中 ≠ 通过」和这条是一对镜像：前者抓不到「什么都没扫到」，后者抓不到「扫到了但结构坏了」。** 例：过滤规则表断言 `规则条数 == 6`，而不是断言 `EX-trauma` 这个码出现过。
> 为什么单列这一条：失败会有人去修，「未验证」被显示成绿色则**永远不会有人发现**。这条规矩的适用面比它看起来宽——它同时管住了「glob 写错」「路径改名」「测试没写」「chunk 被合并进主包」「文档里那张表其实没有这一列」五种故障，而它们的共同特征是**页面行为完全不变、测试全绿**。
