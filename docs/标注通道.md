# 千本级标注通道

> 写于 2026-10-21。解决的问题是「68 本人工 + 书名规则撑不起 6551 本候选」，
> 也就是 `docs/整合方案-第四轮.md` §六 的第 3 条遗留。

## 一、为什么必须做

书名词表能提供强证据的只有 **1872 本**，其余 4679 本只有豆瓣大类兜底，而兜底已被
证明是抽签（1 对多映射 × 每本留 3 个 × 散列截断）。撤掉兜底之后，逐个标签的池子长这样：

| 标签 | 修复后池子 |
|---|---|
| `big-choice` | 1 本 |
| `emptiness` | 1 本 |
| `self-doubt` | 3 本 |
| `rumination` | 5 本 |
| `speaking-block` | 5 本 |

界面如实说「只找到 N 本」，这是对的（不凑数）。但 1 本等于这个标签实际上不可用。

## 二、为什么不走"更好的关键词"

第一反应是：简介可比书名长多了，把简介喂给**同一套词表**不就行了？

试了。在 30 本人标书上，结果直接否掉这条路：

| 通道 | 精确率 | 召回率 | 覆盖 |
|---|---|---|---|
| 书名词表（现有） | **84%** | 26% | 18/30 |
| 简介 + 词表 | **35%** | 38% | 27/30 |

覆盖率上去了，精确率掉到 35%——三条推荐里错两条。原因很清楚：简介是营销长文，
辞藻铺得开，关键词命中从"这本书解决什么"退化成"它提到过这个话题"。
典型失败：《心流》人标 `emptiness / low-mood`，简介匹配给出
`attention-scatter / cant-see-whole / meaning-loss`，三个全错。

**结论：扩到千级只能靠语义判断。再多加一层关键词，只是把抽签换得更贵。**

## 三、通道长什么样

```
取证          标注                校验                接入
fetch-intros  annotate-books     verify-annotations  derive-annotations
   ↓              ↓                   ↓                   ↓
.cache/intros  catalog/annotations  catalog/reports/    public/catalog/
 (不入库)        (入库)              annotation-quality  enriched/derived
```

### ① 取证 `tools/fetch-intros.mjs`

豆瓣详情页 → 简介全文 + 目录 → `.cache/intros/<id>.json`。

- 只抓公开详情页，**不登录**；限速 1.7–2.5s，403/418 立即整体停止（不硬刚反爬）
- 断点续跑：按缓存文件跳过；失败单独记进 `.cache/intros-failed.json`
- 简介取**最长的那段**：豆瓣把短版放前面、全文放后面，只取第一段会稳定拿到
  390 字截断版（末尾带「展开全部」），信息量差一半

### ② 标注 `tools/annotate-books.mjs`

DeepSeek `deepseek-chat`，`temperature: 0`，强制 JSON 输出，`prompt_version` 与
`prompt_sha` 写进产物。

**只产 `problem_tags`。** 这是刻意的收缩：

| 字段 | 为什么不做 |
|---|---|
| `one_line_what` / `first_action` / `match_brief` | 要读过全书才写得出来。看 400 字简介写这些就是编造 |
| `difficulty` / `prose_accessibility` | 是"读起来难不难"，同样要正文；靠术语密度猜不可靠 |
| `depth` / `form` | 目录能提供一部分信号，但不足以单独成证 |

与其产一堆无法验证的弱字段，不如把唯一能负责的那个做到可核对——而它恰好就是
决定池子大小的那个字段。

### ③ 证据闸（这一步是通道的全部信用）

模型每给一个标签，必须附一句**从简介或目录里逐字复制的原文**（≤40 字）。
本地做 `normalize(evidence) ⊆ normalize(原文)` 校验，不通过就**丢掉这个标签**并记账：

```
unknown_tag / duplicate / no_evidence / evidence_too_long
evidence_not_verbatim / over_top_n / json_parse
```

**不采信模型自报的 confidence**——那个数字没法被证伪。"这句话在不在原文里"可以。

这条闸自己有 10 条测试（`tests/tools/annotate-gate.test.ts`），两头都测：
改写一个字的引文必须被丢掉；原文里真有的引文不许误伤。

### ④ 校验 `tools/verify-annotations.mjs`

四类断言：

1. **结构**：id 在候选层、无重复、标签来自词表、≤3 个、证据 ≤40 字、带 prompt 版本
2. **证据可追溯**：逐条证据必须在原文里逐字出现。**缓存不在本机时报「未验证」，
   不报「通过」**——三态纪律
3. **覆盖对账**：逐标签统计标注证据数
4. **金标校准**：拿 `.cache/gold-eval.json`（模型在 30 本人标书上的输出）比
   precision / recall，**精确率 ≥70%、召回率 ≥50% 才允许放量**

第 4 条是通道的门槛。没有金标的标注通道，本质上只是用更贵的方式抽签。

### ⑤ 接入 `tools/derive-annotations.mjs`

新增第三档证据：

| 证据等级 | 权重 | 含义 | 运行时 |
|---|---|---|---|
| `annotation` | 0.95 | 读过简介与目录后的逐本判定 | 放行 |
| `title` | 0.85–0.9 | 书名/副标题命中词表 | 放行 |
| `category` | 0.4 | 豆瓣大类兜底 | **挡住** |

规则细节：

- 标注优先于规则命中（同一标签以标注为准），但**标注没给的标签，书名命中仍然算**
- 词表外的标签在派生层也忽略一次，不靠上游守规矩
- **通道没跑过时，`derived.json` 与接入前逐字节相同**（已验证），这样"池子变大"
  只可能是标注带来的，不会与接入改动混在一起

## 四、版权边界

| 东西 | 去向 |
|---|---|
| 简介 / 目录原文 | 只存在 `.cache/intros/`，`.gitignore` 已排除，**永不入库** |
| 派生标签 + 权重 | `catalog/annotations/`，入库 |
| 证据引文（≤40 字） | 跟着标签入库，供人工抽检与追责 |

`tools/release-check.mjs` 会查两件事：`.gitignore` 里有 `.cache/` 和 `.env`；
标注产物里没有超过 40 字的证据（防止整段原文混进来）。

## 五、规模与成本

| 项 | 数量 |
|---|---|
| 候选书 | 6551 本 |
| 全量取证 | 约 3.5 小时（1.7–2.5s/本） |
| 千本级取证 | 约 35 分钟 |
| 全量标注 | 约 45 分钟（串行 300ms 间隔） |
| token | 每本约 1.2k in / 150 out；千本约 ¥1.5–3 |
