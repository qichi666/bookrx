# ADR-007：全项目图标锁定 Lucide（ISC），不使用 emoji 作功能图标

## Status
Accepted（2026-10-18）—— 对应团队 P0 规则"禁止 emoji 作为功能图标、必须锁定一套 SVG 图标库"

## Background

P0 规则要求锁定**一套** SVG 图标库并写明库名与版本、评估许可与按需引入方式。emoji 作功能图标的三个硬问题（不是审美问题）：

1. **跨平台渲染不一致**：同一个 emoji 在 Windows / macOS / Android / 各家微信内嵌浏览器上字形不同，甚至有的缺字（显示为豆腐块）。功能图标一旦"可能是豆腐块"，可用性就不成立。
2. **不可控的尺寸与基线**：emoji 的字号、行高、垂直对齐由字体决定，UI 无法精确对齐，1px 的偏差在多处复用后会变成明显的错位。
3. **无法跟随主题色**：emoji 是全彩固定色。深色模式下无法反色，也无法表达"禁用/选中/警告"这些状态。

候选：Lucide（ISC）、Tabler Icons（MIT）、Heroicons（MIT）、Phosphor（MIT）。

## Decision

**`lucide-vue-next` 1.22.x（许可 ISC），全项目唯一图标库。**

评级结果见 ARCH.md §8.6：Lucide 4.80 / Tabler 4.30 / Heroicons 4.15 / Phosphor 3.58。

决定性理由：
- **许可 ISC（等同 MIT 的宽松度）**，可商用、可闭源分发，只需保留声明。
- **真正的逐图标 tree-shaking**：每个图标是一个 ESM 具名导出，单图标约 2 KB，28 个约 40 KB 原始 / 12 KB gzip。全量导入则是 1.4 MB 原始 / 335 KB gzip —— 所以按需引入不是优化项，是必须项。
- **有官方 Vue 3 包**，内联 SVG，`currentColor` 直接继承文字颜色 → 天然跟随 `tokens.css` 的主题变量，与"禁止硬编码颜色"的 P0 规则一致。
- 阅读类语义齐备（`book-open` / `highlighter` / `sticky-note` / `rotate-ccw` / `calendar-check`）。

Tabler 图标覆盖更广但无官方 Vue 包（要自己封装组件，多一层维护）；Heroicons 只有约 300 个图标，缺"高亮/书签/复习"这类阅读专属语义；Phosphor 的 6 种字重导致体积膨胀且难以控制一致性。

## Consequences

**正面**
- 28 个图标约 12 KB gzip，可内联进主 JS，首屏零额外请求。
- 单一描边风格（2px）保证视觉一致；`stroke-width` / `size` 都是 props，可被 tokens 控制。
- 无障碍：默认 `aria-hidden="true"`，需要语义时加 `aria-label`。

**负面与对应约束（三条，均为 CI 门禁）**
1. **禁止 `import * as Icons`**（会让 tree-shaking 完全失效）。→ `grep -rn "import \* as .* from 'lucide-vue-next'" src` 必须零命中。
2. **白名单机制**：`src/components/icon/icon-map.ts` 维护唯一允许的 28 个图标及语义名（清单见 ARCH.md §8.6）。新增图标必须改这个文件 → 把"随手加个图标"变成显式评审。
3. **不混用**：不装 iconfont、不引第二套图标库、不用 emoji。→ `scripts/audit-style.ts` 扫 emoji 码点区间（`\u{1F300}-\u{1FAFF}`、`\u{2600}-\u{27BF}`），命中即 fail。

额外约束：图标不携带任何色值，一律 `currentColor`；需要"警告/成功/三档符合度"等状态色时，用外层元素的 `color: var(--color-*)` 控制。
