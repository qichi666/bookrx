# ADR-008：TXT 通过实现 foliate 的 book interface 接入，不另写渲染器

## Status
Accepted（2026-10-18）

## Background

第一版支持 EPUB + TXT 两种格式。EPUB 由 foliate-js 处理，TXT 需要自己接。

有两条路：

- **方案 A**：TXT 单独写一个渲染器（一个 `<pre>` 或自建滚动视图 + 自己的分页逻辑）。
- **方案 B**：为 TXT 实现 foliate 的 `book` interface，让它走与 EPUB 完全相同的渲染管线（`paginator.js` + `overlayer.js` + `progress.js` + `search.js`）。

表面上方案 A 便宜得多：TXT 出字就是一个 `<pre>`。但产品的阅读能力不是"出字"，而是：

| 能力 | 方案 A 的成本 | 方案 B 的成本 |
|---|---|---|
| 划线 + 高亮渲染 | 重写（自己的偏移模型 + 覆盖层） | 0（复用 `overlayer`） |
| 分页 / 改字号 / 旋转 | 重写 | 0（复用 `paginator`） |
| 进度百分比 | 重写 | 0（复用 `progress`） |
| 书内搜索 | 重写 | 0（复用 `search` + `text-walker`） |
| 章节跳转 | 重写 | 0（复用 `toc`） |
| 笔记/小测定位 | 第二套坐标系 | 0（同一套 `Locator`） |
| 主题注入 | 重写 | 少量（复用注入机制） |

方案 A 在前两周看起来更快，但从第二个阅读功能开始，每个功能都要写两遍，且两套坐标系必然产生同步 bug。

## Decision

**方案 B：`engine/formats/txt-book.ts` 实现 foliate 的 book interface。**

要实现的最小成员（foliate 原文定义）：
- `sections[]`：按章节切分，每项含 `.load()`（返回 `blob:` URL，内容是包了 XHTML 外壳的 HTML）、`.size`、`.linear`、`.id`、`.createDocument()`（供搜索）
- `toc[]`：章节标题识别
- `metadata`：`title` 取文件名去扩展名，`language='zh'`
- `rendition`：`{ layout: 'reflowable' }`
- `resolveHref(href)`：按 `#chapter-<n>` 解析
- 不实现 `resolveCFI`：TXT 无 CFI，由 `locator/txt-codec.ts` 用 `{chapter, offset}` 代替（§7.3）

## Consequences

**正面**
- 一套 `Locator`、一套高亮、一套进度、一套搜索。**每新增一个阅读功能，两种格式只做一次。**
- TXT 与 EPUB 的交互表现一致（用户可以无差别使用），这本身就是产品质量。
- 章节切分逻辑是纯函数，可在 Node 里用真实 TXT 样本单测。

**负面与必须写进规格的硬约束**
1. **切分必须是流式的**。100 万字 TXT 不能先 `split('\n')` 出 20 万行数组再逐条正则——移动端会卡 2 s 以上。要边读边切、边建 section 元数据。
2. **必须有兜底切分**。识别不到任何章节时，不能返回 1 个巨型 section（分页会卡死），必须按 8000 字切块，标题为"第 N 节"；单章超过 2 万字也要再切。
3. **章节识别要防误判**。正则族覆盖"第X章/回/卷/节/篇/部""Chapter N""序/前言/后记/附录"、数字标题行、以及"短行（≤30 字且不含句号）且前后为空行"的常见网文格式。宁可少识别（退化为块切分），不可把正文段落误判成标题（会在目录里塞进几百条垃圾）。
4. `createDocument()` 需要生成 XHTML，注意必须做 HTML 转义（`& < > "`），否则正文里的 `<` 会破坏 DOM 结构。
5. 每章生成的 `blob:` URL 必须在卸载时 `revokeObjectURL`（与契约测试第 15 条一致），否则连开几本书就 OOM。
