# ADR-009：阅读器自建（字符流 + 引文锚点），不引入 foliate-js

## Status
Accepted（2026-10-21）。本决策**修订 ADR-001**，不推翻它的判断依据。

## Background

ADR-001（2026-10-18）在 foliate-js / epub.js / Readium 之间选了 foliate-js，决定性理由是「epub.js 的 DOM 重排分页会在尺寸变化时重建 DOM，而高亮挂在 DOM Range 上，重建后要么消失要么错位」。

但项目落地到 M1 时，实际依赖只有 `vue` + `vue-router`：**foliate-js 从未接入**。ADR-001 描述的是一个不存在的实现。这本身是个需要修的事实——文档里写着"已选型"，代码里没有一行。

现在要把 P0-8 ~ P0-13 真正做出来，必须在两条路里选一条：

1. 按 ADR-001 接入 foliate-js（git submodule，锁 commit）；
2. 自建一个最小阅读器。

## Decision

**自建**。EPUB / TXT 统一转成「章节 → 段落文本」，用 CSS 多列分页渲染；标注锚点用契约里已有的 `RangeLocator`（`chapter_ref` + 引文 `quote` + `occurrence`），**不持久化 DOM Range**。

三条理由，按重要性排序：

1. **ADR-001 的问题已经被契约层解决了，而且解法更彻底。** `contracts/reader.ts` 里的 `Locator` 是判别联合（`epub-cfi` / `txt-offset` / `quote`），`RangeLocator` 要求「双锚点 + 引文 + 上下文各 30 字」。也就是说，即使 DOM 全量重建、即使换成另一份版式不同的文件，标注也能靠引文找回来（四级降级：CFI → 同章引文 → 全书引文 → 章节首）。DOM Range 在自建方案里只是**渲染态的一次性产物**，从不落库。ADR-001 担心的失效点因此不存在。
2. **EPUB 自带的 CSS 会破坏阅读主题。** 用户导入的书里，固定版式、写死的字号与颜色、绝对定位随处可见。foliate 走的是"尊重原书排版"的路线，那意味着我们的字号/主题/夜间模式在部分书上会失效，而用户不知道为什么。自建方案把内容抽成文本流，排版权归我们——这是"能读"优先于"还原"的取舍。
3. **构建依赖面。** submodule + 锁 commit 会让 CI 多一个外部仓库依赖（本项目刻意零后端、单页静态托管）。自建的解析层是纯函数，可以在 Node 里用真实样本单测——这恰好是本项目最看重的验证形态。

## Consequences

**得到的**

- 解析层（`engine/import/`）纯函数化，EPUB/TXT 都能在 Node 里单测，不需要浏览器。
- 主题 / 字号 / 行距 / 分页完全受控，夜间模式在每一本书上行为一致。
- 标注持久化与渲染引擎解耦：换渲染实现不影响已有标注。

**放弃的（写清楚，免得以后当成 bug）**

- **不支持 EPUB3 固定版式**（`rendition:layout=pre-paginated`）：导入时识别并给 `fixed-layout-unsupported` 警告，按文本流尽力渲染。
- **表格、多栏、复杂脚注**降级为线性文本；图片只在有 `alt` 时留一行占位说明。
- **不渲染原书字体**（`@font-face`）：一律用系统字体，避免字体混淆（obfuscated font）与授权问题。
- 章节小测、笔记导出 PDF 等 M3 之后的项不在本次范围。

**若将来要回到 foliate**

不需要推翻本决策：`ReaderEntry` / `Locator` / `RangeLocator` 都是引擎无关的契约，把渲染层替换掉即可。**先保证锚点契约稳定，渲染引擎是可换的。**
