# ADR-005：项目采用 MIT 许可，不用 AGPL

## Status
Accepted（2026-10-18）

## Background

本项目是一个开源 Web 阅读应用。许可选择有两条实际路线：

- **MIT**：任何人可复制、修改、商用、闭源分发，只需保留版权声明。
- **AGPL-3.0**：任何人可复制修改，但通过网络提供服务时必须开放全部源码。

有一个非常具体的反例必须写清楚：**LightRead 是 AGPL-3.0**（因为它内嵌了 MuPDF）。如果本项目借鉴了它的代码（哪怕只是"看懂了然后重写"且结构高度相似），本项目就会被要求整体转为 AGPL。

同时，候选依赖的许可分布决定了路线的可行性：
- foliate-js：MIT；其 vendored 的 fflate 为 MIT、zip.js 为 BSD-3-Clause、PDF.js 为 Apache-2.0。
- Vue 3：MIT。Dexie 4：Apache-2.0。ts-fsrs：MIT。Lucide：ISC。Vite：MIT。
- 全部为宽松许可，**没有一个是 copyleft**。

## Decision

**本项目采用 MIT。**

## Consequences

**正面**
- 与全部依赖的许可相容，且不会因为"引了某个 copyleft 库"被迫升级许可。
- 开源阅读器这个品类的价值就在"可被复用"：别人能把它嵌进自己的网站、能打包进内部工具、能做成商业产品。AGPL 会挡住几乎所有商业与内部使用场景（法务直接否掉），这等于让项目失去影响力。
- 教育/研究/个人使用零摩擦。

**负面**
- 有人可以闭源 fork 并商用而不回馈。→ 接受。对一个 3000 本库 + 规则打分的产品，真正的护城河是标注数据质量与文案质量，不是代码本身；许可证保护不了数据质量。
- 无法通过 copyleft 强制下游贡献回来。→ 接受。

**具体执行要求（否则等于自找合规风险）**
1. `LICENSE` 放 MIT 全文；`THIRD-PARTY-NOTICES.md` 必须包含 foliate-js（MIT）、fflate（MIT）、zip.js（BSD-3-Clause）的版权声明与许可全文。MIT/Apache/BSD 都要求保留声明，漏掉是明确缺陷。
2. **禁止引用 LightRead 的代码**。允许了解其公开文档与产品思路；不允许复制代码、不允许"结构高度相似的重写"。代码评审时若发现某段逻辑与 LightRead 高度雷同，必须重新实现。
3. `package.json` 的 `license` 字段为 `MIT`；`foliate-js`（submodule）的许可状态记录在 `vendor/foliate-js.commit` 同目录的说明文件里。
4. 核心库的书目**数据**与**文案**的许可需要单独声明（建议 CC BY-SA 4.0 或 CC0，由产品定），因为数据许可与代码许可不是一回事；而"内联正文"必须逐本核对书名页版权状态（ARCH.md §6.3 的 R1–R6）。
