# BookRx 全新能力规划方案（在现有功能之外的净新增）

> 版本：2026-11-10 · 性质：**规划方案，本轮不写业务代码**；确认后按阶段 TDD 实现
> 基础：`D:\wkbd\reading-app` 磁盘实际代码（165 源文件 / 19 路由 / 61 测试 / 456 用例）
> 前提：你已确认现有功能齐全，本方案只做**代码里确实没有**的新能力，不重复造已有模块

---

## 1. 目标、适用场景与范围

**目标**：在不破坏「困境因果 × 可解释 × 可复现 × 零收集 × 危机安全」差异化的前提下，补齐 local-first 阅读产品的**个人目标、状态管理、数据深度与可携带性**四类净新增能力，让产品从"诊断+闭环"升级为"可长期自我管理的本地阅读中枢"。

**适用场景**：单用户、无账号、离线优先的个人阅读管理；所有新数据留在本机，零网络请求。

**范围冻结（继续不做）**：账号/云同步、星级评分、UGC 社区、ML/LLM 生成、心理量表、推送、打卡排行榜、PDF/漫画/TTS/OPDS。本方案的"个人目标"是**私密进度**，不是排行榜，不违反冻结项。

**关键工程承诺**：本方案**不提升 DB_VERSION、不新增 objectStore、不做数据迁移、不新增运行时依赖**；偏好类数据走 localStorage，计算走纯函数，图形手写 SVG/Canvas。

## 3. 新增功能清单（按优先级）

### 3.1 P0 高优先级：零迁移、纯增量，立即提升日常可用性

#### N1 全局主题切换（浅色 / 深色 / 跟随系统）

- **推荐理由**：当前深色只能跟随系统，用户无法手动固定；主题切换是 StoryGraph、Bookly、Bookmory、微信读书等的标配，且实现风险极低。
- **预期价值**：补齐基础个性化，消除"在浅色环境被迫深色"等错配。
- **实现思路**：
  - 新增 `src/lib/theme.ts`：纯函数 `resolveTheme(choice, systemDark)` + `applyTheme()` 操作 `document.documentElement.dataset.theme`；
  - localStorage 键 `bookrx.theme`，值 `light | dark | auto`；
  - `tokens.css` 增加 `[data-theme="dark"]` / `[data-theme="light"]`，与现有 media 块复用同一组变量；`auto` 时移除属性交回系统 media；
  - `AppHeader.vue` 加三态切换按钮（触控 ≥44px，带 `aria-pressed`）。
- **改动范围**：新增 `lib/theme.ts`；改 `AppHeader.vue`、`tokens.css`。**不碰** domain/打分/存储表。
- **扩展方式**：后续主题色板只在 tokens 层扩展，组件零改动。
- **风险**：data-theme 与 media 的优先级；以显式属性覆盖、auto 回落 media 解决。

#### N2 个人阅读目标（私密，按本数/时长，年度/月度）

- **推荐理由**：StoryGraph/Hardcover/Goodreads 的 reading challenge、Bookly/Bookmory 的 goal 都是核心留存点；本产品有统计却无目标，用户缺一个"我要去哪"的锚。
- **预期价值**：给阅读行为设私密目标并展示在轨进度，提升回访；无社交、无排行。
- **实现思路**：
  - 目标存 localStorage 键 `bookrx.goal`：`{scope:'year'|'month', metric:'books'|'hours', target:number}`，**无 DB 迁移**；
  - 新增 `src/domain/goal.ts` 纯函数：`goalProgress(goal, sessions, finished, today)` → `{done, target, percent, onTrack}`；`now/today` 由视图传入（domain 禁时钟）；
  - 新增 `components/stats/GoalCard.vue`：设置目标 + 进度条 + 是否在轨；挂到 `StatsView`，并可在首页"今天"区块给一行摘要；
  - 语气约束：不达标只陈述、不羞辱（符合产品"无负罪感"原则）。
- **改动范围**：新增 `domain/goal.ts`、`components/stats/GoalCard.vue`；改 `StatsView.vue`（可选 `TodayPanel.vue`）。**不碰**打分。
- **扩展方式**：metric/scope 为受控枚举，后续加"每周"等只扩枚举与纯函数。
- **风险**：跨月/跨年边界用本地 ISO 日期（复用 `lib/local-date.ts`），避免时区错位。

#### N3 弃读（DNF）书架状态

- **推荐理由**：Openreads、StoryGraph、Hardcover 均有 did-not-finish；读不下去是真实状态，硬塞进"想读/在读"会污染统计。
- **预期价值**：让书架状态诚实，且不把弃读误算成失败或稀释读完率。
- **实现思路**：
  - `storage/db.ts` 的 `ShelfGroup` 增加 `'abandoned'`，`SHELF_LABEL` 加中文；
  - `ShelfCard.vue` 加"标记弃读"动作；`LibraryView.vue` 增加弃读分组；
  - `StatsView` 读完率分母仍为"在读+读完"，**另列弃读数**，不纳入读完率；
  - 无需 DB 迁移（store 存字符串，仅 TS 联合类型与 UI 扩展）。
- **改动范围**：`storage/db.ts`（类型）、`storage/library.ts`、`ShelfCard.vue`、`LibraryView.vue`、`StatsView.vue`。
- **扩展方式**：后续可给弃读加一句原因（仍本地、非量表）。
- **风险**：确认 `doc-audit`/`check-enums` 不拦（ShelfGroup 在 storage 层，非 contracts 受控词表，风险低）。

### 3.2 P1 中优先级：数据深度，复用已有会话数据、不采集新数据

#### N4 月度阅读热力图 + 困境标签分布

- **推荐理由**：StoryGraph wrap-up、GitHub 式贡献热力、LightRead 仪表盘都用可视化呈现积累；本产品有完整 sessions 却只展示近 7 天。
- **预期价值**：让长期积累"被看见"，强化留存与凭证感。
- **实现思路**：
  - 新增 domain 纯函数：`heatmapCells(sessions, year, month)`（每日时长/本数）、`tagDistribution(books, annotations)`（按困境标签聚合）；
  - 手写 SVG 渲染（无图表库，与关系图谱一致），新增 `components/stats/Heatmap.vue`、`TagDistribution.vue`，挂 `StatsView`；
  - 数据全部来自现有 sessions/books，零新增采集。
- **改动范围**：新增两个组件 + domain 纯函数；改 `StatsView.vue`。
- **风险**：SVG 无障碍（加 `title`/`aria-label`）；单文件 ≤300 行，超限即拆组件。

#### N5 阅读速度 / 时段洞察

- **推荐理由**：Bookly/Bookmory 提供平均速度与阅读时段；本产品已有 sessions 与 progress，可直接算。
- **预期价值**：帮助用户理解自己的节奏；纯展示，不接排期（与终版"只展示不改排期"一致）。
- **实现思路**：domain 纯函数输出平均会话时长、阅读速度（字数/时长）、时段分布；`StatsView` 加小面板；样本不足如实标"样本太少"。
- **改动范围**：domain 新增纯函数 + `StatsView.vue`。
- **风险**：样本不足不硬给数字，避免误导。

### 3.3 P2 低优先级：数据可携带与安全

#### N6 整库备份 / 恢复（全 10 表 JSON）

- **推荐理由**：无云设计下，整库可备份是数据安全的根本；Openreads、LightRead（.okf.zip）、BookWyrm 均提供。当前只有笔记与诊断的局部导出。
- **预期价值**：换浏览器/清数据前可完整带走并恢复，零网络。
- **实现思路**：
  - 新增 `src/lib/backup.ts`：`exportBackup()` 遍历 10 个 store 序列化为单 JSON（带版本与导出时间）；`importBackup()` 校验后按 store 写回，冲突默认**跳过并出报告**，不静默覆盖；
  - 在 `ProfileView.vue` 加备份/恢复区块；大文件走 Blob。
- **改动范围**：新增 `lib/backup.ts`；改 `ProfileView.vue`。
- **风险**：恢复是写操作，必须显式用户确认 + 结果报告，绝不自动执行。

#### N7 快速位置书签（可选，建议暂缓）

- 现有划线已覆盖大部分标记需求，轻量位置书签价值有限；列为备选，不进核心范围，避免功能膨胀。

## 6. 风险与注意事项

1. **不重复造已有功能**：本方案已逐项核验为净新增；实现前如再遇"已存在"项立即停止并核对。
2. **零迁移红线**：偏好走 localStorage，避免重蹈 IndexedDB 版本陷阱；不主动提升 DB_VERSION。
3. **隐私与语气**：所有新数据零外发；目标/统计不做羞辱式标红，样本不足如实标注。
4. **恢复类写操作**：N6 必须显式确认 + 报告，不自动执行、不静默覆盖。
5. **真实浏览器验证不可省**：单测全绿不等于线上无问题，每阶段保留冒烟步骤。
