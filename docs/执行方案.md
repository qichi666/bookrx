## 0. 一页纸

**做什么**：用户描述自己的困境，系统推荐 5 本书，每本给一句对症点 + 三段理由 + 符合度档位，按符合度降序。有版权的书只给推荐信息，用户自行导入 EPUB/TXT 阅读；公版书内置可直接读。

**一句话链路**

```
说困境 → 拿 5 本书 → 看懂为什么是这本 → 点开能读（或导入后能读）→ 划线笔记 → 章末小测 → 间隔重复
```

**三个数字（已定，不再讨论）**

| 数字 | 值 | 含义 |
|---|---|---|
| 300 | 首发核心库本数 | 6 域 × 50 本；v1.0 前扩到 800；架构按 3000 设计 |
| 5 | 一次推荐本数 | 不出无限流，避免选择过载 |
| 3 | 符合度档位数 | 高度契合 / 较为契合 / 换个角度；**不显示百分数** |

**三条不可妥协**

1. **规则打分，不用 LLM 打分、不用向量相似度** —— 可解释、可单测、同输入同输出、零成本
2. **模板渲染理由，不用 LLM 生成** —— 不编造、不漂移、300 本可批量校验
3. **不提供任何版权书的正文** —— 只给书目信息与导入路径，正文由用户自己提供

## 1. 功能范围

### 1.1 定位

> **一个诊断器，为了让你读得下去，自带一个阅读器。**
> 不是书城，不是书单，不是评分网站。

与最强对手 `yzfly/LightRead`（轻阅）的差别：它把推荐做成 `设置 → 功能` 里一个默认关闭的精选书单；我们把推荐做成首屏唯一入口。

### 1.2 做什么（P0，15 项，按用户旅程排序）

| # | 功能 | 用户看到什么 |
|---|---|---|
| 1 | 困境问卷（4 步） | 6 域单选 → 具体感觉多选 → 读书条件 5 行 chip → 可选自由文本 |
| 2 | 自由文本输入与降级 | 不填也能出结果；填了则理由第一段回引你的原话 |
| 3 | 规则加权打分 + 硬约束排序 | 见第 2 节 |
| 4 | 三段式理由渲染 + 字段降级 | 见第 3 节 |
| 5 | 符合度呈现 | 三档标签 + 命中依据短语 + 「为什么不是更高档」 |
| 6 | 推荐结果页 | 5 张卡；可切「阅读路径」视图 |
| 7 | 书籍详情页 | 理由完整展开 + 版权说明 + 确定的下一步 |
| 8 | 导入引导 + 11 种失败态 | 拖拽区、真实解析进度、按原因分类的错误文案 |
| 9 | EPUB 阅读器 | 分页/字号/主题/目录/书内搜索 |
| 10 | TXT 阅读器 | 编码自动判定（含 GB18030）、章节自动识别 |
| 11 | 本地书库 | 按「在读 / 读完 / 想读」分组，显示进度 |
| 12 | 划线 + 笔记 | 跨版式可恢复的锚点（见 4.7） |
| 13 | 公版书内置直读 | 30–40 本，点开即读，标注版本来源 |
| 14 | 无网络可用 | Service Worker 缓存，二次访问零网络 |
| 15 | 推荐结果本地保存 / 导出 | 书单导出为 JSON，可分享给他人导入 |

### 1.3 不做什么（13 条）

前 5 条是定位级决策，不是技术妥协：

| # | 不做 | 为什么 |
|---|---|---|
| 1 | 社区 / 评论 / 关注 | 冷启动社区是空地，空地比没有更伤；UGC 审核成本超过单人维护者的承载力 |
| 2 | PDF | 固定版式导致重排/字号/划线定位/深色模式全退化，等于再写一个引擎；且用户的 PDF 多是论文扫描件，与「读完一本书」是两种场景 |
| 3 | 账号 / 多端同步 | 与 local-first 冲突，「你的数据不上传」正是本产品的信任卖点 |
| 4 | LLM 生成书单 / 写理由 | ①结果不可复现，无法单测 ②会编造不存在的书，用户一查无此书就永久流失 ③与零成本自建定位冲突 |
| 5 | 豆瓣评分 / 评论 | 无公开 API（2017 关停、2023-07 平台下线）；且「大众平均」与「对你的适配度」语义不同，混用会破坏符合度设计 |

其余 8 条：盗版书源聚合、内置版权正文或抓取试读章、向量相似度推荐、原生 App（只做 PWA）、大规模书封抓取、打卡/连续天数/排行榜、任何变现与付费墙、理由的用户自定义编辑。

### 1.4 规模：三层口径

| 阶段 | 核心库 | inline 可直读 | 配题数量 | 人工投入 |
|---|---|---|---|---|
| **M0.5 先行** | **60 本**（6 域 × 10） | 0 | 0 | **25–40 小时** |
| **M1 首发** | 300 本（6 域 × 50） | 0 | 100 本 × 3 题 | 累计 125–200 小时 |
| v1.0（M4） | 800 本 | 30–40 本 | 200 本 × 3 题 | 累计 **365–680 小时** |
| 架构上限 | 3000 本 | 按品类可及 | 按需 | 不在本项目周期内 |

**工时构成（这是全项目最大的成本项，比开发还重）**

| 项 | 单价 | 数量 | 合计 |
|---|---|---|---|
| 书目结构化 | 25–40 分钟/本（8 个文案字段 + 5 个 1–5 评分 + 版权核验） | 300 本 | 125–200 小时 |
| inline 正文校注 | 8–12 小时/本（断句标点、错字校勘、白话注释、导读） | 30–40 本 | **240–480 小时** |
| **合计** | | | **365–680 小时 ≈ 2.3–4.3 人月** |

**两个必须知道的事实**

1. **inline 校注是全项目唯一「不能靠加人加速」的部分** —— 它需要有文言能力的贡献者，而这类人极少。所以它不是「以后再说」的活，而是**越早启动越好**。
2. **但它只在 M4 才需要**。M1 发版完全不碰 inline。这意味着：**首发不被它阻塞，v1.0 被它决定**。

**降本方案（把 240–480 小时砍到 60–120 小时）**

不要自建校注。改用**既有的公版校点本**（中文维基文库、标准电子书、互联网档案馆），自己只写导读与生僻字词注释：

| 做法 | 单价 | 30–40 本合计 |
|---|---|---|
| 自建全套校注（断句+校勘+白话注释+导读） | 8–12 小时/本 | 240–480 小时 |
| **采用公版校点本 + 自写导读** | **2–3 小时/本** | **60–120 小时** |

代价：文本的校点质量取决于来源（维基文库的校点水平参差，需要抽检）；且维基文库是 CC BY-SA，必须在书末标注来源与协议——**但这只影响文本文件，不影响代码保持 MIT**。

**为什么首发是 300 而不是 3000**：3000 本 = 1250–2000 小时 = 全职 10–17 个月。按每天 4 小时算要 10 个月，而你年底要去实习。而且没有哪个环节能靠加人提速（书目质量要一致，校注要文言能力）。

**推荐质量取决于单本理由的质量，不取决于库存量。** 300 本写透能连用 3 个月；3000 本字段半空，用户第一次搜书就撞上「暂无深度推荐」，第一印象直接毁掉。

**所以真正的路径是分批，不是一次做完**：先做 60 本（25–40 小时）→ 用它验证推荐质量 → 有人用再补到 300 → v1.0 才补 inline。这也是为什么 M0.5 被单列出来。

### 1.5 必须说清的三条能力边界

| 边界 | 实情 | 产品怎么处理 |
|---|---|---|
| **inline 品类错配** | 能公版直读的是古籍与民国作品（庄子、论语、史记、鲁迅、朱自清）。它们解决不了「焦虑失眠 / 拖延 / 职业困惑」——这些书全是版权书 | 不承诺占比，只承诺「每类困境至少 1 本能直读」。焦虑类困境就是没有可直读的书，UI 不得暗示「这本本该能读」 |
| **导入的书没有小测** | 小测题库随核心库分发，只覆盖 100 本 | 用「笔记一键建卡」兜底，任何书都能进复习流 |
| **没有同步就没有跨设备** | 数据在 IndexedDB | 提供导出/导入 JSON；Safari 需申请持久化存储，否则可能被清 |

## 2. 推荐与排序逻辑

### 2.1 输入：4 步问卷（一屏最多 8 个 chip）

| 步骤 | 问题 | 形式 | 驱动什么 |
|---|---|---|---|
| 1 | 你现在最想解决的是哪一类？ | 单选 6 项 + 「说不上来」 | 候选池 + 主题标签域级权重 |
| 2 | 具体是哪种感觉？ | 随域联动，多选 ≤3 | 主题标签主权重（0.9 / 0.5） |
| 3 | 读书条件（5 行 chip） | 单选 | 见下 |
| 4 | 还有想说的吗？ | 自由文本 ≤140 字，可选 | 关键词词表命中（400 条）→ 标签权重 0.6 |

步骤 3 的 5 行 chip 对应四个轴：

| chip | 选项 | 驱动 |
|---|---|---|
| 每天能读多久 | 10 分钟 / 30 分钟 / 1 小时+ | 认知负荷修正 + 篇幅偏好 |
| 能接受多难 | 越轻松越好 / 有点挑战 / 不怕难 | 认知负荷主值 + **难度硬上限** |
| 希望多快见效 | 这三周就要用 / 一个月内 / 不着急 | 紧迫度轴 |
| 想要这本书怎么带你 | 讲一个人的故事 / 讲清一套方法 / 给我完整框架 | 结构需求轴 |
| 更想要哪种收获 | 具体做法 / 做法加为什么 / 底层原理 | 深度轴 |

**「说不上来」不是失败态**：选它则跳过步骤 2，改问「最近生活里哪块最耗你」（6 个具体场景：睡不好 / 和某个人关系紧张 / 工作提不起劲 / 总在纠结一个决定 / 感觉自己落后了 / 只是空虚）。把抽象问题降维到具体场景——说不清的用户需要被提示，不是被追问。

### 2.2 七个因子与权重（和恒为 10000）

| # | 因子 | 权重 | 计算 |
|---|---|---|---|
| 1 | 主题契合 | **3800** | 覆盖率口径 `Σmin(用户权重, 书权重) / Σ用户权重`，不是 Jaccard |
| 2 | 难度匹配 | 1800 | 目标难度 = 1 + 4 × 认知负荷/100 |
| 3 | 深浅匹配 | 1200 | 目标深度 = 1 + 4 × 深度诉求/100 |
| 4 | 体例匹配 | 1000 | 目标体例 = 1 + 4 × 结构需求/100 |
| 5 | 篇幅匹配 | 1000 | 档差 0→10000 / 1→6000 / 2→2500 / 3→0；「不限」→7000 |
| 6 | 表达匹配 | 700 | 目标友好度 = 1 + 4 × 紧迫度/100 |
| 7 | 可直读倾斜 | 500 | inline 10000 / 自备 5500 / 外部 2500 |

**为什么主题用覆盖率而不是 Jaccard**：书多打了几个用户没提的标签不该扣分。用户问的是「这本能不能对上我的问题」，不是「这本有没有跑题」。用对称口径会系统性惩罚标注丰富的书。

**为什么可直读只给 500**：一个难度档差 = 1800 × 1/4 = 450。所以 500 能翻转「难度略差半档」，但翻转不了主题差异（单标签差通常 ≥570）。这是有意设计的量级。

**全程定点整数运算**（单位 basis point，万分制），不出现浮点比较 —— 同输入必得同输出，跨浏览器一致。

### 2.3 执行顺序（顺序错了结果就错）

```
① hardFilter        硬过滤，先砍掉根本不该出现的书
   ├─ difficulty > 用户声明的难度上限 → 剔除
   ├─ entry_level ≥ 4 且 认知负荷 < 40 → 剔除
   └─ content_warning 命中且用户未同意沉重题材 → 剔除
② score            7 因子加权，得 score_bp
③ rank             7 级 tie-break 全序
④ icebreak         破冰位校正（见下）
⑤ diversify        rank 1–5 内：同作者 ≤2、同品类 ≤2
⑥ relax            不足 2 本 strong+worth 时按 4 级阶梯放宽
⑦ tier             8000 / 6000 切三档
```

**为什么硬过滤必须在打分前**：如果先打分再过滤，被过滤掉的高分书会占据多样性配额，导致最终结果既不准也不够多样。

**破冰位（R1）**：排序后若第 1 位「预计阅读时长 > 3 小时」且不是 `inline`，则在 `strong + worth` 中找第一本满足「≤3 小时 或 inline」的，与第 1 位交换，并在结果里记 `promoted_for_icebreak: true`（否则无法复现）。

> 这是整个产品的第一性目标：让用户今晚开始读。第 1 本如果是 600 页的《原则》，用户会在看结果的 10 秒内离开，后面所有功能都没机会展示。

**安全底线（content_warning）**：用户选「情绪与自我」且选「越轻松越好」时，标了自杀 / 性侵题材的书**直接剔除**，默认不给「你可以自己判断」的选项。给一个正在抑郁状态的人推《自杀论》是产品事故。

### 2.4 排序：7 级全序链（保证同输入同输出）

```
1 score_bp 降序 → 2 主题契合降序 → 3 难度契合降序 → 4 可获得性升序
→ 5 预计时长升序 → 6 字段完整度降序 → 7 book_id 升序
```

第 7 级保证全序（id 唯一），所以结果不依赖 `Array.prototype.sort` 的稳定性。单测：随机打乱输入 200 次，断言输出序列完全一致。

### 2.5 分档

| 档 | 分数区间 | 卡片标识 | 中文名 |
|---|---|---|---|
| `strong` | ≥ 8000 | 3 个方块全填 | 高度契合 |
| `worth` | 6000–7999 | 2 个方块 | 较为契合 |
| `explore` | < 6000 | 1 个方块 | 换个角度 |

**阈值不是拍的**：所有因子满分 = 10000，但现实里主题契合极少到 10000。取「主题 8500、其余全满、需自备」这一理想构型，上限约 9200。所以 8000 意味着「七个维度里最多一处小失配」。

**校准目标**（M3 用真实 300 本跑基线）：`strong` 占候选池 12%–18%，`worth` 占 35%–45%。偏离就调阈值，不调权重——权重承载业务含义，阈值只承载分组线。

### 2.6 完整算例（可直接当单测）

**用户**：32 岁产品经理，「带团队时总忍不住替下属做决定，团队长不起来」。
主题标签：管理授权 0.9 / 沟通与反馈 0.5 / 自我认知 0.3（Σ=1.7）；紧迫度 85、认知负荷 50、结构需求 60、深度 90、篇幅档 2。

| 书 | 主题 | 难度 | 深度 | 体例 | 篇幅 | 表达 | 可获得 | 总分 | 档 |
|---|---|---|---|---|---|---|---|---|---|
| 《领导梯队》 | 7647 | 10000 | 7250 | 7250 | 10000 | 6500 | 5500 | **8030** | strong |
| 《非暴力沟通》 | 4706 | 7500 | 4750 | 9000 | 6000 | 4000 | 2500 | **5613** | explore |
| 《原则》 | 1765 | 7500 | 8500 | 8500 | 2500 | 7750 | 5500 | **4957** | explore |

这个算例说明三件事：
1. 《非暴力沟通》主题相关度不低（用户第二需求是沟通），但深度/表达/篇幅三个维度都不贴，掉到 explore —— **光看主题不够，四轴问卷不是装饰**。
2. 《原则》在深度和体例上几乎满分，但主题不贴 —— 这是放宽场景的典型候选。
3. 《领导梯队》8030 刚好压线进 strong，说明阈值 8000 是紧的，M3 校准要重点看 strong 比例。

并且这个算例里 strong+worth 只有 1 本 < 2，**会触发放宽阶梯**——正好用来锁住放宽逻辑。

### 2.7 为什么不用 LLM 打分、不用向量相似度

| 方案 | 否决理由 |
|---|---|
| LLM 打分 | 同输入两次结果不同 → 无法单测、无法回归；需要 API key 与成本；无法解释「为什么这本排第三」 |
| 向量相似度 | 300 本书上，可解释的规则优于不可解释的召回；书库 >5 万本且规则明显失准时再议 |
| LLM 生成理由 | 会编造书里没有的内容；用户核对不上就永久流失 |

## 3. 推荐理由的输出形式

### 3.1 卡片上的三层结构

```
┌─────────────────────────────────────────┐
│ 一句话对症点（≤28 字）                    │  ← 承担 80% 说服工作
│ ■■■ 高度契合   [可直接阅读]  [开始读]     │  ← 档位 / 可用性 / 操作同一行
│ 为什么是这本 ▾                            │  ← 折叠区
└─────────────────────────────────────────┘
       展开后 ↓
   S1 你的处境（左侧 2px 竖线，回引你的原词）
   S2 这本书讲什么（客观讲方法与切入）
   S3 你读完能得到什么（含一个可执行动作）
   S4 一处不匹配（可选，诚实披露）
```

**为什么默认折叠三段**：全展开单卡 320px，一屏只能看 2 张，8 张要滚 4–5 屏，用户读完 1000 字才能决定读哪本——信息前置反而降低决策效率。折叠态 132px，一屏 4 张。

**为什么卡片第二行不能用 S1**：S1（`situation`）是按主题标签从文案库取的**共享句**，同一个用户下两本主标签相同的书会渲染出完全相同的第一行——5 张卡里出现 3 张同样的话，「逐本说明理由」就废了。所以第二行用 `match_brief`（按书预写，≤28 字），S1 留在展开区。**两个字段各管一层，不能合并。**

**5 本书分三组，不是一条流**

| 组 | 标题 | 数量 | 档位 | 卡片规格 |
|---|---|---|---|---|
| 1 | 今晚就能开始 | 1 | `strong` | 完整卡（含档位方块 + 书脊卡） |
| 2 | 读完这本再看 | 3 | `worth` | 完整卡 |
| 3 | 也可以看看 | 1 | `explore` | **简化卡**：不显示档位方块 |

第三组为什么去掉档位方块：只有 1 格，显示出来等于反复告诉用户「这本不行」。这一组的定位已经由组标题表达了，再叠一层档位是重复否定。只保留可用性徽标与按钮。

### 3.2 字段与槽位

| 槽位 | 数据来源 | 长度 | 必填 |
|---|---|---|---|
| `match_brief` 一句话对症点 | 按月/按标签预写，**不是运行时生成** | ≤28 汉字 | 是 |
| S1 `situation` | 文案库按标签取句；有第二标签且权重 ≥0.5 时用预写的组合句 | 40–70 字 | 是 |
| S2 `promise` | `one_liner`（60–90 字）+ `angle`（≤40 字） | 40–70 字 | 是 |
| S3 `payoff` | `payoff_by_tag[主标签]` → 依次回退 → `payoff_generic`，再拼 `first_action` | 40–70 字 | 是 |
| S4 `mismatch` | 最低分因子的 `mismatch_hints` → 通用句 | 15–30 字 | 否，仅当最低因子 < 5000 |

**三条写死的规则**

1. **S1 必须包含至少一个用户输入的原词**（选项文本或自由文本命中词）。取不到就走降级，不允许静默生成通用 S1。
2. **S3 必须包含动词短语**（「你会分清…」「你可以用…」「改成…」），不允许只有名词。构建期用动词表校验 `first_action`，不含动词即 fail。
3. **S4 只在最低分因子 < 5000 时出现**。这是最反直觉但最重要的一段：主动说「这本书比你想要的长一倍」，比藏在 7 个因子里更能让人相信另外 6 个因子。

### 3.3 三个真实示例

**示例 A（版权书，需自备）**
用户：「开会不敢发言，总怕被否定，反复想别人怎么看我」；每天 30 分钟，有点挑战。自由文本：「明明没做错什么，就是会怕」。

> **《被讨厌的勇气》** ｜ 岸见一郎、古贺史健 ｜ 渠海霞 译 ｜ 约 12 万字 / 预计 4 小时 ｜ 需自备 ｜ **高度契合**
> 命中了 — 开会不敢发言 · 怕被否定 · 反复想别人怎么看
>
> **S1**　你提到「开会不敢发言」和「反复想别人怎么看我」——这不叫性格内向，也不是能力不够，这是把自己的价值判断权交到了别人手里。
> **S2**　这本书是哲人与青年五个晚上的对话，用阿德勒心理学的「课题分离」和「目的论」，拆解「一切烦恼都来自人际关系」这句话到底成立在哪。
> **S3**　读完你至少能拿到一件工具：分清「别人怎么评价我」是别人的课题、「我要不要开口」是你的课题。下次会前你可以拿这句话先把自己从审判席上放下来。

**示例 B（版权书，聚焦「读不下去」）**
用户：「买了很多书一本没读完，每次读几页就困」；每天 10 分钟，越轻松越好。自由文本：「我觉得我就是没毅力」。

> **《微习惯》** ｜ 斯蒂芬·盖斯 ｜ 桂君 译 ｜ 约 9 万字 / 预计 2.5 小时 ｜ 需自备 ｜ **高度契合**
>
> **S1**　你说「我觉得我就是没毅力」——先把这个判断放下。每次读几页就困，通常不是毅力问题，是你给自己定的启动门槛比当天的心力高。
> **S2**　这本书从一个俯卧撑开始讲：作者把目标缩小到「小到不可能失败」，用超额完成带来的成就感替掉意志力的消耗，全书就是这套方法的完整操作步骤。
> **S3**　读完你能拿到一条今天就能用的规则：把「每天读 30 分钟」改成「每天翻开书读 2 页」。2 页这个量小到没法拒绝，而绝大多数时候你会多读几页。

**示例 C（公版书，可直接读）**
用户：「工作三年越来越觉得没意义，不知道自己要什么」；自由文本：「好像做什么都在为别人交代」。

> **《庄子》（内篇）** ｜ 庄周 ｜ 公版原文附白话注释 ｜ 内七篇约 3.2 万字 / 预计 3 小时 ｜ **可直接读** ｜ **高度契合**
>
> **S1**　你说「好像做什么都在为别人交代」——这不是矫情，是你的价值感只剩一把尺子：工作绩效。一把尺子量不完一个人，所以你才会觉得空。
> **S2**　《庄子》内七篇用寓言讲一件反直觉的事：一棵因为「不成材」而没被砍走的树，恰恰因为「没用」活了下来。它不给你答案，它拆掉你量自己的那把尺子。
> **S3**　读完《逍遥游》和《人间世》两篇，你能拿到一个备用视角：这世上有一部分事，不必换算成「有没有用」。这本书是公版原文，可以直接在这里读，每段下面有白话注释。

三个示例的共同点：S1 全部回引了用户原词（「没毅力」「为别人交代」「开会不敢发言」）；S3 全部给了当天可做的动作；没有一句「这本书非常经典」。

### 3.4 字段缺失时的降级（宁可少一段，不可编一段）

| 缺失 | 降级 |
|---|---|
| `payoff_by_tag` 全空 | 用 `payoff_generic`；仍空则**不生成 S3**，卡片加一行「这本书我们还没整理出读完能得到什么」 |
| `one_liner` 缺失 | 用 `publisher_summary` 截 60 字，并标注「简介来自出版方」 |
| `theme_tags` 缺失 | 该书不进个性化推荐池，只出现在按品类浏览 |
| 自由文本未命中任何标签 | S1 只用选项文本回引（选项是用户自己选的，可以回引） |
| 译本信息缺失 | 卡片显示「译本信息待补充」，详情页提示「不同译本差异较大，请自行核对译者」 |

### 3.5 禁用词表与 CI 校验

**禁用**：「经典」「必读」「神作」「受益匪浅」「提升认知」「干货满满」｜「本书讲述了」「在这个快节奏的时代」「让我们一起」｜「92% 匹配」｜「你应该」「你必须」｜「读完你的人生会改变」。

**CI 三重校验**（任何一条失败即阻断合入）：

| 层 | 断言 |
|---|---|
| 字段覆盖率 | 300 本 × 必填字段缺失 = 0；48 个标签的 S1 句齐备 = 100%；`payoff_by_tag` ≥2 项 = 100% |
| 渲染断言 | 无 `{{` 残留；各段字数达标；同一推荐列表内 `match_brief` 不重复；禁用词命中 = 0 |
| 确定性 | 9000 次渲染总耗时 < 400ms；同输入两次渲染逐字节一致 |

## 4. 版权书籍的处理方式（B 方案落地）

### 4.1 三态：一个字段管到底

| `availability` | 含义 | 卡片徽标 | 主按钮 | 视觉重量 |
|---|---|---|---|---|
| `inline` | 公版正文随应用分发，点开即读 | 本书可直接读（品牌色底） | 开始读（实心） | 最重 |
| `bring_your_own` | 只给推荐信息，用户自备文件 | 需自备电子书（灰底） | 导入我的文件（描边） | 中 |
| `external` | 只给书目信息 | 仅提供书目信息（无底） | 查看来源（纯文字） | 最轻 |

**视觉重量递减不是审美，是暗示**：能直接读的给最强按钮，只能看外部来源的给最轻按钮。界面在说「我们更推荐读得到的书」，但不必说出口。

**只有这一个字段是判定依据**。任何地方不得根据「有没有来源链接」「是不是公版」临时推断。

### 4.2 三个位置的文案

| 位置 | 看到什么 |
|---|---|
| 推荐列表 | 徽标 + 对应主按钮。`bring_your_own` 的按钮是「导入我的文件」，不是「无法阅读」 |
| 书籍详情页 | 可用性区块紧随书名之后（不放到页底）+ 一句 20 字内解释 + 理由三段完整展开 |
| 点「导入我的文件」 | 进导入页，标题直接承认事实：「《书名》需要你自己准备文件」 |

**文案四不四要**

| 不写 | 改写 |
|---|---|
| 暂无资源 | 需自备电子书 |
| 不可用 | 仅提供书目信息 |
| 该书籍不支持在线阅读 | 绑定你的文件后就能读 |
| 版权受限，无法提供 | 这本书还在版权保护期，可以读你自己买的版本 |

**两条硬规则**：① 任何 `bring_your_own` / `external` 卡片必须紧邻一个可点的下一步，不允许出现「读不了」且没有按钮的卡片；② 徽标文案 ≤7 个汉字，保证 320px 宽手机上与档位同排不换行。

### 4.3 导入流程（7 步，纯函数实现）

| 步 | 动作 | 关键点 |
|---|---|---|
| 1 | 前置校验 | ≤50MB 正常；50–100MB 警告可继续；>100MB 拒绝；空文件拒绝。前端 `accept` 只是体验，不做安全判断 |
| 2 | **格式嗅探（读魔数，不信扩展名）** | EPUB = ZIP：前 4 字节 `50 4B 03 04`；是 ZIP 后再确认包内有 `META-INF/container.xml`。用户常把 .txt 改名成 .epub |
| 3 | **加密检测（区分 DRM 与字体混淆）** | `encryption.xml` 里若是 `idpf.org/2008/embedding` 或 `adobe pdf/enc#RC` → 只是字体混淆，**不阻断**；若指向内容文档的 AES → 判 DRM |
| 4 | TXT 编码判定 | 有 BOM 直接定；无 BOM 先严格试 UTF-8（fatal），失败试 GB18030；都失败让用户手选。**中文 TXT 的现实是 GB18030 占比极高**，只支持 UTF-8 会让一半用户导入失败 |
| 5 | 元数据解析 | `title` 可能是 string 或 `{lang}` 对象；`author` 可能是 string / 对象 / 数组 —— 必须写归一化函数，直接强转会炸 |
| 6 | 生成 `book_id` | EPUB 有 `dc:identifier` → 规范化后用它；没有 → `sha256(OPF + spine 顺序)` 前 16 位。**同一文件必得同一 id** |
| 7 | 与核心库对齐 | 有 ISBN 查 ISBN 表，否则用「归一化书名 + 第一作者」查；命中则把核心库字段补进来（但**阅读内容仍是用户的文件**） |

**为什么 `book_id` 哈希要含 spine 顺序**：同一本书的不同版式（精排/重排/插图版）理应得到不同 id —— 因为定位符与版面绑定。若只哈希正文，两个版式会得到同一 id，标注位置立刻错乱。

### 4.4 失败态（11 种，按原因分，不用统一「导入失败」）

| 原因 | 错误码 | 用户看到 | 可做什么 |
|---|---|---|---|
| 文件 >100MB | `E_IMPORT_TOO_LARGE` | 超过 100MB 的文件在浏览器里无法可靠解析 | 拒绝 |
| 文件 50–100MB | — | 文件较大（{x}MB），导入后可能卡顿 | 「仍然导入 / 取消」 |
| 空文件 | `E_IMPORT_EMPTY` | 文件是空的 | 拒绝 |
| 不是 EPUB | `E_IMPORT_NOT_EPUB` | 这不是一个 EPUB 文件 | 提示改选 TXT |
| ZIP 损坏 | `E_IMPORT_CORRUPT_ZIP` | 文件似乎损坏了 | 重试 / 换文件 |
| DRM 加密 | `E_DRM_PROTECTED` | 这本书有 DRM 保护，无法在浏览器里打开 | 拒绝，**不引导绕过** |
| 元数据损坏 | `E_IMPORT_BAD_OPF` | 这本书的元数据损坏 | **降级导入**：仅阅读，标题取文件名，元数据手填 |
| 编码无法判定 | `E_IMPORT_ENCODING` | 无法确定文本编码，请选择 | 手选 UTF-8 / GB18030 / UTF-16 |
| 正文为空 | `E_IMPORT_EMPTY_CONTENT` | 这本书没有可显示的正文 | 拒绝 |
| 存储不足 | `E_STORAGE_QUOTA` | 本地空间不足 | 去「我的书」删书 |
| 重复导入 | — | 你已导入过这本书 | 保留原档，幂等 |

**降级导入这条要单列**：用户手上很多书是「能读但元数据烂」的，直接拒绝会让用户觉得产品脆弱。

### 4.5 法律边界（把判断编码成 CI 门禁）

**保护期**：作者终生 + 死后 50 年（至第 50 年 12 月 31 日）。

**最大的坑**：**原著公版 ≠ 中译本公版**。译者单独享有著作权。《悲剧的诞生》原文公版，周国平译本不公版。

**六条构建期硬规则**（任一违反即 `exit 1`）：

| 规则 | 内容 |
|---|---|
| R1 | inline + 原著公版 + 译本非公版 → 违规 |
| R2 | 声称公版但没写 `public_domain_reason` → 违规 |
| R3 | 非 external 但没有 `source_url`（出处不可核验）→ 违规 |
| R4 | 译本在版权期却 inline → 违规 |
| R5 | 明确在版权期却 inline → 违规 |
| R6 | 译本版权状态 `unknown` 却 inline → 违规（**未知按有版权处理**） |

**R6 是本项目的默认姿态：证明不了就当作有版权。**

**可 inline 的书只有四类**：中文古籍原文 / 民国及以前旧译（译者逝世 >50 年）/ Project Gutenberg 与中文维基文库既有文本 / CC 或作者授权免费作品。

### 4.6 存储：只删文件、保留笔记

`book_files`（Blob 原文件）与标注/笔记/进度/复习卡**分表存放**。删掉原文件后，笔记、划线引文、复习卡全部保留——因为标注存了 `quote`（≤500 字）与引文锚点，不需要原文也能回看。

**两个必须写进规格的坑**：
1. IndexedDB 读一行会把该行所有字段一起反序列化。若把 3MB Blob 与元数据放同一行，「我的书」列表读 50 本 = 读 150MB。**Blob 必须独立表、独立主键。**
2. Safari 有「长期不访问清库」的策略，首次导入必须调 `navigator.storage.persist()`；未获授权时明确告诉用户「笔记可能被系统清理，建议定期导出」。

### 4.7 标注为什么不能只存 CFI

CFI 只对**同一份文件**稳定。用户换了一个版式的同一本书，同一段话的 CFI 完全不同，而本产品的书大部分由用户自己导入。

所以标注**必须双写**：CFI 范围 + 引文（`quote` + 前后各 30 字）+ 章节引用。解析阶梯：CFI 精确恢复 → 失败则在章节内搜引文 → 再失败全书搜 → 还找不到归入「失效标注」并**明确告知**。

**宁可让标注失效并告知，也不能静默错位。错位的高亮比消失的高亮更伤信任。**

## 5. 技术选型

| 层 | 选择 | 一个关键理由 |
|---|---|---|
| 前端 | Vue 3 + TypeScript + Vite | 阅读引擎是纯 JS，无框架耦合；中文阅读类开源项目主流是 Vue 3 |
| 阅读引擎 | **foliate-js（MIT）** | 用二分查找定位、`overlayer` 天生为标注设计；epub.js 的 DOM 重排会冲掉高亮 |
| 存储 | IndexedDB via Dexie，local-first | 无后端 = 零成本 + 不上传数据 = 信任卖点 |
| 数据 | 静态 JSON，构建期建索引 | 可版本化、可 PR、可 fork、可离线、零延迟 |
| 检索 | 自建（汉字 + 全拼 + 拼音首字母） | 中文的难点是输入法不是错字（打 `ldtd` 找《领导梯队》），Fuse.js 不支持拼音 |
| 复习 | FSRS-4（`ts-fsrs`） | 比 SM-2 复习次数更少、留存更高 |
| 图标 | **Lucide（ISC）** 单套 | 许可最宽松、逐图标 tree-shaking |
| 许可 | **MIT**（代码）+ CC BY-SA 4.0（书目数据） | 不碰 AGPL，否则所有二次集成都被挡住 |

**不选 LightRead 的代码**：它是 AGPL-3.0（因 MuPDF）。沾上 AGPL，你的项目也必须 AGPL，会劝退几乎所有商业与内部使用场景。这不是道德问题，是传播问题。

**首屏预算 241 KB gzip**（catalog 121 + 应用 JS 108 + 图标 12），阅读器 145 KB 懒加载。CI 门禁：超预算 5% 即 fail。

## 6. 实施步骤

| 阶段 | 内容 | 产出 | 为什么这样切 |
|---|---|---|---|
| **M0** | 脚手架 + 设计 Token + 书目 schema + 构建校验脚本 | 能跑的空壳 | schema 必须先定死，否则 300 本数据要返工 |
| **M0.5** | **60 本书目**（6 域 × 10）+ 用 3 个虚构画像跑打分 | 能证明推荐排得对 | 25–40 小时就能验证一件事：**推荐结果像不像人给的**。如果不像，别做后面的 |
| **M1** | 诊断问卷 → 打分 → 5 本卡片 → 详情页（**无阅读器**） | **v0.1 可发布** | 不依赖版权内容和重型引擎，发出去才知道有没有人要 |
| **M2** | 导入流水线 + foliate-js 集成 + 进度 + 目录 | v0.2 | star 主要来源，也是风险最大的一步 |
| **M3** | 划线/笔记 + 100 本章末小测 + FSRS 复习 | v0.3 | 学习闭环成立，「推荐+学习」才名副其实 |
| **M4** | 30–40 本 inline 公版书 + 书单导入导出 + SW | **v1.0** | 零配置体验，决定留存；**但 inline 校注这笔 60–120 小时的账也是在这里才付** |

**并行线**：M0.5 之后，书目整理与开发是两条并行线——你写代码时，书目按 60 → 300 的节奏补。不要串行，否则总工期翻倍。

**排序核心理由**：M1 是唯一不需要处理版权、也不需要重型引擎就能验证核心假设的版本。如果 M1 发出去没人要，M2–M4 就是白做；如果 M1 有人要，阅读器会让它升级成产品。

### 每个里程碑的验收

| 阶段 | 必须跑通 |
|---|---|
| M0 | `npm run catalog:audit` 字段缺失 = 0；权重表 7 项和 = 10000 |
| M1 | 算例三本书得分 8030 / 5613 / 4957；打乱输入 200 次结果一致；5 本卡片含档位+理由+三态徽标 |
| M2 | 9 份真实样本（中文 EPUB / 含图 / 字体混淆 / DRM / GB18030 TXT / UTF-8 BOM / 改名 TXT / 损坏 ZIP / 无 OPF）逐一断言错误码与 id 稳定性 |
| M3 | 划线跨刷新不错位；换版式后标注进「失效标注」且可见；FSRS 存读调度间隔一致 |
| M4 | 断网刷新首屏与已导入书仍可读；恶意 EPUB（含 script）不执行、不发请求 |

## 7. 三天内能开工的第一件事

不要先做界面。按这个顺序，三天能拿到一个可验证的地基：

```
第 1 天  contracts/ 全部类型 + domain/recommend/{weights,score,rank}.ts
         跑通 §2.6 算例的单测（8030 / 5613 / 4957）
第 2 天  scripts/build-catalog.ts + Book schema 校验
         手写 10 本书的真实数据，跑 catalog:audit
第 3 天  domain/reason 模板引擎 + 渲染 10 本书 × 3 个画像，跑禁用词校验
```

三天后你手上有一个**能在 Node 里跑、能证明推荐排序正确、能生成通顺理由**的核心。这时候再碰 UI，才不会返工。

## 8. 待你确认的四件事
