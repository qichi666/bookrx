# BookRx 完整建设方案（local-first 阅读管理应用）

> 版本：v3（总览版） · 2026-11-08
> 配套文档：《功能增强方案-v2.md》（F1–F12 逐项目的/边界/验收，本文不再重复其全部细节，只做总览、竞品对比与落地规划）
> 定位：**只规划、不实现**。确认后再按批次动代码。

---

## 一、方案目标、适用场景与范围

### 1.1 目标
在不改变"纯前端、无后端、无账号、无埋点"这一结构性优势的前提下，把产品从"一个问卷工具"扩展为"问卷之后不让用户掉出去的完整 local-first 阅读管理应用"。

三个可量化目标：
1. **首屏可点入口 1 → 6**：开始诊断 + 功能卡 + 继续读，让 10 个页面在首屏被表达。
2. **补全一条闭环**：推荐 → 存下（想读）→ 开读 → 读完回执 → 回看统计 → 带走凭证。
3. **产出可带走物与本地统计**：可打印书方、JSON 导出、书摘图，以及时长/连续天数等本地积累。

### 1.2 适用场景
- 隐私敏感、不愿注册登录，或网络不稳定/需要离线使用（PWA 可安装）。
- 同一台设备上的多身份隔离：家人共用电脑，或把"工作相关的书"与"情绪相关的书"分开。
- 类"书方/阅读疗法"场景：把推荐结果打印出来，带去咨询室或对照阅读。
- 单人维护者做内容治理：核对标签厚度、危机资源核实状态、回执有用率。

### 1.3 范围

**做（local-first 等价物）**
| 传统模块 | 本项目形态 |
|---|---|
| 用户管理 | 本地档案（IndexedDB 多档案，同设备隔离，非账号、非云同步） |
| 数据统计可视化 | 本地 IndexedDB 统计（手写 SVG/CSS，无云端仪表盘） |
| 结果分享 | 文件导出 / 打印 / 书摘图（纯客户端，零上传） |
| 后台管理 | 只读本地治理面板（`/admin`，不入导航，单人维护） |

**明确不做**：账号体系/云同步、用户评分/星级、UGC 书评/社区、ML/LLM 生成书单、心理测评量表、推送提醒、打卡排行榜。理由见 §6 与 v2 文档 §3。

## 二、整体思路与关键步骤

### 2.1 核心判断
四个传统模块不是"加后端做完整应用"，而是**翻译成本地优先等价物**。这条路已被多个无账号 PWA 验证："无账号 + IndexedDB + JSON 导出"足以支撑完整产品体验。

### 2.2 四条不可动摇的架构原则
1. **问卷主链路不被阻塞**：诊断→打分→推荐仍是第一入口，扩展模块是结果下游与回访理由。
2. **隐私承诺语义不变**：新增数据只写本机 IndexedDB，导出是用户主动触发的下载，不是上报。
3. **确定性内核不受污染**：`src/domain` 内禁止随机与时间依赖；日期、排序持久化字段放 `storage`/`lib`。
4. **单人维护现实**：治理面板服务唯一维护者，不引入服务端权限体系。

### 2.3 数据流（单向本地管道）
```
问卷 → Diagnosis → 确定性打分 → 推荐
                           ├─ 加入想读 → shelf(want)
                           ├─ 直接开读 → shelf(reading)
                           └─ 导出/打印 → 书方
开读 → reading_sessions + progress
        ├─ 阅读统计（时长/连续天数/分布）
        ├─ 读后回执（useful/neutral/unfit）
        └─ 笔记/划线/书摘图
以上本地数据 → /admin 只读聚合（不写用户数据）
```

### 2.4 关键步骤
1. 扩展存储：v1→v2 迁移，新增 `profiles`/`reading_sessions`/`receipts`，旧表补 `profile_id` 索引并回填默认档案。
2. 信息架构先行：首页工作台化 + 导航扩展，让新页面可达。
3. 书单库独立化，承载浏览/筛选/导出/对比。
4. 补留存闭环：想读清单、读后回执、阅读统计。
5. 可信度与深度：可解释面板、书摘图、笔记总览、读书计划、治理面板。

## 三、技术要点与模块

### 3.1 技术栈
Vue 3 + TypeScript + Vite，PWA 可离线安装；数据全部在 IndexedDB；零 UI 组件库、零图表库。

### 3.2 模块清单（对齐 v2 的 F 编号）
| 编号 | 模块 | 层 | 优先级 | 依赖 |
|---|---|---|---|---|
| F1 | 首页工作台化 | L0 可见度 | P0 | 无 |
| F2 | 全局导航扩展（3→5/6） | L0 | P0 | 无 |
| F3 | 书单库独立化（筛选/排序/浏览） | L1 宽度 | P0 | 无 |
| F4 | 书方导出与打印 | L2 闭环 | P0 | 无 |
| F5 | 想读清单与排队 | L2 | P0 | shelf 表 |
| F6 | 读后回执 | L2 | P0 | F5 钩子 |
| F7 | 阅读统计页 | L1 | P1 | 埋点扩展 |
| F8 | 可信度面板（为什么推荐这本） | L1 | P1 | 无 |
| F9 | 书摘卡片 | L1 | P1 | 现有笔记 |
| F10 | 书籍对比 | L1 | P1 | 无 |
| F11 | 笔记总览 | L2 | P2 | 无 |
| F12 | 读书计划 | L2 | P2 | 预计时长、F7 |

### 3.3 关键技术点
- **存储迁移只加不改**：只加表/字段/索引，旧数据回填默认档案，不改旧字段语义。
- **多表事务清单必须完整**：事务里要 `objectStore(name)` 的表，必须在 `db.transaction(stores)` 清单内，少一张即 `NotFoundError`。
- **时长按会话落库，不按秒写**：复用阅读器现有 clock/`visibilitychange`，页面隐藏或退出时 flush 一条会话。
- **手写 SVG / Canvas**：图表用 SVG，书摘图用 Canvas 2D（1080×1350），不引入图表库或 html2canvas。
- **打印**：`@media print` 隐藏导航/按钮，`break-inside: avoid` 防条目被分页截断。
- **可复现**：`domain` 内禁 `Math.random`/`Date.now`/`new Date`/`performance.now`；日期计算放 `lib`/`storage`。
- **筛选状态入 URL query**：可分享、可刷新保持；同组件内 query 变化（前进/后退/共享链接）需 `watch(route.query)` 同步，否则地址变结果不变。
- **导出契约**：JSON 带 `schema_version`，只存用户选择与分档、**不存分数字段**；全程零网络请求。
- **状态规则**：档案切换=全局重装载；空状态诚实、不显示 0 值假图表；`/admin` 只读、不入导航。
- **导航/路由**：导航 3→5（书架/书单库/统计/怎么读书/关于），375px 折叠汉堡，触控目标 ≥44px，`data-crisis-entry` 配额恒为 2。

## 四、同类产品调研与对比

### 4.1 三类玩家
1. **综合追踪（有账号/云）**：Goodreads、StoryGraph、Literal、Hardcover、Bookly。
2. **处方式/阅读疗法**：Reading Well（Books on Prescription）、Book Therapy。
3. **local-first 无账号 PWA**：NextChapter、nextly.page、lokl、Oku 等。

### 4.2 关键事实
- **StoryGraph**：读完书采集 mood/pace/plot-vs-character 与内容警告，驱动统计与推荐；Stats V4 支持标签统计对比、过滤子集、平均读完天数；Custom Tags/Lists 可筛选 TBR 并分享；2026 年新增 Private Books（私密书不进主页/统计/信息流）；其推荐是 **ML 输出、不可解释**，这是它被批评的主要点。[1][2][3]
- **Reading Well（英国）**：GP/链接员/专业人员开方，患者到公共图书馆免费借阅；累计借出 **380 万册**，**92% 受访者觉得有用、97% 年轻人愿推荐、90% 专业人员认为支持了诊室外工作**。相关 RCT 系统综述（8 项 RCT、1347 人）显示阅读疗法可长期降低成人抑郁症状。[4][5][6]
- **微信读书**：阅读统计覆盖时长/活跃天数/进度/可视化画像，笔记划线可批量调取，支持私密阅读、时长兑书币、好友时长排行榜——强账号、强社交。[7][8]
- **local-first 代表**：NextChapter 数据全在 IndexedDB、无账号/分析/追踪、支持导出；nextly.page 可安装 PWA、离线、随时导出可读 JSON，浏览器直连 Open Library、查询不经其服务器；lokl 提供 Markdown 笔记、标签、JSON/Markdown 导入导出，无账号/云/遥测。[9][10][11]

### 4.3 横向对比
| 维度 | Goodreads | StoryGraph | 微信读书 | Reading Well | 典型 local-first PWA | **BookRx 目标态** |
|---|---|---|---|---|---|---|
| 账号 | 必须 | 必须（可私密） | 必须 | 无（图书馆体系） | 无 | 无（本地档案） |
| 离线优先 | 弱 | 弱 | 弱 | 实体书离线 | 核心 | 核心（PWA） |
| 社交/社区 | 核心 | 有 | 强（排行） | 无 | 无 | 无 |
| 计时/统计 | 仅年度挑战 | 强（可对比） | 强（画像） | 外部年度评估 | 本地统计 | 本地统计 |
| 推荐可解释 | 群体均分 | ML 黑箱 | 算法黑箱 | 专家背书书单 | 无/规则 | **确定性可解释** |
| 导入/导出 | CSV | 导入为主 | 弱 | 实体凭证 | JSON 双向 | JSON/打印/图片 |
| 隐私 | 低 | 中（私密书） | 中（私密阅读） | 高 | 很高 | **很高（零外发）** |

### 4.4 结论
"**local-first 无账号 + 确定性可解释推荐 + 处方式可带走书方**"三者交集，目前没有产品同时做。StoryGraph 强在统计与元数据但推荐黑箱、依赖账号；Reading Well 强在证据与凭证但走线下图书馆体系；local-first PWA 保证隐私但普遍缺"按处境匹配"的推荐内核。这正是 BookRx 的差异化空位。

## 五、现有功能差距与可落地补充建议

基线实测：10 页面 / 3 导航入口 / 68 书 / 33 标签（中位仅 4 本）/ telemetry 仅 3 个聚合计数 / 无时长 / 无想读态 / 无凭证 / 无统计。

| # | 差距（对照竞品标配） | 具体可落地补充（最小可做版本） | 对应 | 优先级 |
|---|---|---|---|---|
| 1 | 问卷独占首屏，书单/书架/导入不可见 | 首页重排为工作台：开始诊断 + 4 张功能卡 + 继续读；问卷逻辑不改 | F1/F2 | P0 |
| 2 | 书单页依赖诊断、不能独立逛 | 无诊断时渲染全量 68 本，默认 book_id 升序、不显示分档；筛选状态入 URL | F3 | P0 |
| 3 | 无可带走凭证（Reading Well/Book Therapy 的交付主体） | 加打印样式 + 导出带 schema_version 的 JSON/Markdown；不含医疗措辞 | F4 | P0 |
| 4 | 无想读/排队，留存断点（所有阅读产品都有） | shelf 加 `want` 枚举值与一键加入，支持队列排序，不反向影响打分 | F5 | P0 |
| 5 | 无效果反馈，阈值无校准（Reading Well 效果数全靠读后调查） | 读完弹三选一 + 可选理由，同书只弹一次；若接排序须确定性加权、缺失取中性 | F6 | P0 |
| 6 | 无时长/连续天数/统计（标配留存） | 新增 reading_sessions，按会话落库；手写 SVG 图表；空状态诚实 | F7 | P1 |
| 7 | 可解释性埋在代码里 | 详情页可展开七因子中文得分条，薄标签如实说薄，不暴露字段名 | F8 | P1 |
| 8 | 无传播物 / 无对比 / 笔记无聚合 / 无排期 | Canvas 书摘图；2–3 本 SVG 对比；跨书笔记总览；按时长排周计划 | F9–F12 | P1/P2 |

## 六、风险与注意事项

1. **内核污染**：统计/日期/随机若误入 `domain` 会破坏"同输入同输出"。用分层约束 + 现有门禁拦截。
2. **事务与迁移**：多表事务清单漏表会 `NotFoundError`（删除档案漏 `profiles` 是实测踩过的点）；迁移只加表/字段，多标签页靠 `onversionchange` 让路。
3. **版本陷阱**：v2 代码与 v1 库反向打开，可能停在"无表"的损坏态（本轮实际遇到并已修复）。方案须写清升级与回滚路径，避免在低版本上空跑。
4. **隐私/合规**：新增文案不得含"诊断/症/治疗/疗效"等医疗措辞（沿用 copy-audit 词表）；坚持不做诊断、危机配额=2、数据零外发。
5. **数据厚度诚实**：标签中位仅 4 本、最薄 3 本，必须如实呈现；无数据显示引导文案，不渲染 0 值假图表。
6. **依赖纪律**：不引入图表/UI/截图库，不新增后端或服务端权限。
7. **体验细节**：375px 无横向溢出、触控 ≥44px、导出不显示 loading（无网络等待）、不做惩罚性打卡。
8. **测试口径**：基线为 54 文件 / 412 断言；新增功能同步补测试，勿与实现期的更大数字混用对比。

## 七、实施计划与预期结果

### 7.1 五批路线图
| 批次 | 内容 | 工期参考 | 关键依赖/验收 |
|---|---|---|---|
| 第一批（观感） | F2 导航 → F1 首页工作台 | 1–2 天 | 首屏入口 ≥6；375px 不溢出 |
| 第二批（面积+凭证） | F3 书单库 → F4 导出打印 | 2–3 天 | 无诊断可逛 68 本；打印单页不断行 |
| 第三批（闭环） | F5 想读 → F6 回执 | 2–3 天 | 刷新保持；同书不重复弹 |
| 第四批（可信+深度） | F8 可解释 → F10 对比 → F9 书摘 | 3–4 天 | 因子对拍；导出零网络请求 |
| 第五批（数据积累） | F7 统计 → F11 笔记总览 → F12 计划 | 需先跑一段时间 | F12 必须在 F7 之后 |

### 7.2 每批门禁
`npm run check` 全绿（typecheck + 测试 + 各 audit）、`npm run build` 断言通过、真实浏览器无 console error、375px 无溢出、危机配额恒为 2。

### 7.3 预期结果
- 产品形态从"问卷工具"升级为"完整 local-first 阅读管理应用"，推荐→留存→读完→回看→凭证的闭环跑通。
- 获得可对外陈述的**真实指标**（回执有用率、阅读时长/连续天数），而非自评；同时"数据不出机器"的隐私承诺完全不变。
- 差异化清晰：可解释确定性推荐 + 无账号隐私 + 可带走书方，三者交集暂无竞品。
