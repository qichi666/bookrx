## 0. 三十秒版本

用户描述**此刻的具体困境**（如"开会轮到我发言就脑子空白"），系统用一套**确定性规则**打分，给出 5 本书，**逐本说明为什么是这本**，然后**当场就能开始读**——公版书直接读，版权书导入自己的文件后读。

纯前端、无后端、无账号、无埋点上报。推荐不接大模型，阅读不上传文件。

一句话赌注：**用户不缺书，缺的是"第一步"。** 所以产品做的是「诊断 → 推荐 → 当场能读 → 记住」，这条链任何一环断掉，用户就退回原样。

## 1. 产品定位

### 1.1 一句话

> 你说自己的困境，它给你 5 本书，每本告诉你为什么是这本，并且你能当场开始读。

### 1.2 核心问题

所有榜单都在回答「**哪些书好**」，没有人回答「**以我现在的状态，我能读完哪一本，读完会变好吗**」。

后半句拆开是两个可解的子问题：

| 子问题 | 含义 | 市面现状 |
|---|---|---|
| 匹配 | 书和我的困境对不对得上 | 做得粗（按人群、按品类） |
| 可完成性 | 这本书我今天晚上真能翻开并读下去 | **基本没人做** |

产品把第二个问题当成一等公民：难度、篇幅、文体门槛、可读性都是打分因子，不是标签；库内没有合适的书时明说「这些都不对」，而不是拿三本不对症的书把列表填满。

### 1.3 与替代方案的差别

| 替代方案 | 它回答的问题 | 为什么不够 |
|---|---|---|
| 电商 / 畅销榜 | 最近什么好卖 | 买回来发现不对味，书架越堆越高，形成「买了等于读过」的代偿 |
| 小红书 / 公众号书单 | 一次给 20 本 | 没有一本是为他选的，收藏完一本都不开始 |
| 豆瓣 | 大众平均分 | 无公开 API；8.9 分的书对他可能是 0 分，因为他读不下去 |
| 微信读书 | 有书、有社交 | 推荐按人群偏好；不解决「我该读哪本」 |
| `yzfly/LightRead`（最接近的开源竞品） | 「阅读器 + 顺手几张书单」 | 推荐藏在设置里且**默认关闭**。我们是「诊断器 + 自带阅读器」，主路径就是诊断 |

### 1.4 三条不可让渡的底线

1. **危机优先**：诊断命中危机信号时，结果页**只给心理援助资源、不给推荐**。这是硬互斥，有单测；结果页与关于页各留一个援助入口，全项目配额恒为 2，多了少一个构建就失败。
2. **不凑数**：库内不足 5 本时如实少给并说明，同时给出库外书名（标「未入库」），永远不拿不对症的书填满列表。
3. **理由可追溯**：每句推荐理由要么来自预写文案，要么来自打分字段，**不允许模型现编**。界面上每句理由都带来源徽章（书里写的 / 你的回答 / 书的标注）。

### 1.5 名字

**BookRx**，中文「书方」——处方之意。名字本身承担产品定位：它给的是处方，不是书单。

## 2. 目标用户

### 2.1 谁

**一个 22–35 岁、有阅读意愿、但连续 12 个月没完整读完一本书的中文用户。** 通常在通勤、睡前，或某个情绪低点（被裁员 / 分手 / 体检报告异常 / 转岗失败）打开手机想「我是不是该读点书」。

### 2.2 三类画像

| 画像 | 占比预估 | 具体场景 | 他要什么 |
|---|---|---|---|
| A 卡住的人 | 60% | 28 岁运营，被说「表达没说服力」，买了《金字塔原理》读 18 页就停，书架还有 9 本同样命运的书 | 别让我做 20 道选择题；告诉我「先读这本，2 小时」；现在就要能读 |
| B 读了很多但记不住 | 30% | 34 岁产品经理，去年读完 11 本，被问「最近那本讲了什么」说不出来 | 验证「我真的读进去了」的机制，而不是又一个进度条；笔记要能导出 |
| C 开源贡献者 / 策展人 | 10% | 读过 200 本心理学的开发者，愿意 PR 补字段 | 字段结构清晰、有校验脚本、数据纯文本可 diff、PR 72 小时内 review |

### 2.3 明确排除的用户

找免费盗版书的人（不提供、不做书源爬虫）；要读 PDF 论文的人（第一版不做）；想在阅读器里社交的人（不做社区）。

### 2.4 业务上必须成立的三件事

这三条是产品的存亡条件，也是所有取舍的裁判：

1. **诊断结果必须让人点头**：第一本书得是「对，就是这本」，不是「哦，也行」。
2. **推荐必须能落到"开始读"**：给出书名却让人自己去找，链条就断在最后一步。
3. **危机场景必须让位于安全**：任何增长手段都不能挤占这一步。

## 3. 核心功能与流程

### 3.1 主链路与页面

```
问卷（3 屏必填 + 1 屏可选自由文本）
   |
   +-- 命中危机信号 --> 危机资源页（硬互斥，不出推荐）
   |
   +-- 正常 --> 结果页（5 本分 3 组 + 库外候选 + 调参滑杆）
                 |
                 +--> 书籍详情页（可用性区块紧随书名 / 逐句来源 / 同主题 3 本）
                 +--> 荐书单页（导出 / 导入 *.booklist.json）
                 +--> 到哪读（公版全文 / 微信读书 / 买一本 / 图书馆）
                 |
                 +--> 导入（EPUB / TXT）--> 本地书库（在读 / 读完 / 想读）
                                              |
                                              +--> 阅读器（翻页 / 字号 / 主题 / 目录 / 搜索 / 划线 / 笔记）
```

| 路由 | 页面 | 职责 |
|---|---|---|
| `/` | QuizView | 四屏问卷；第 3 屏 5 组 chip 必须同屏，不拆页；「说不上来」跳 6 个具体场景而非报错 |
| `/result` | ResultView | 原词回显、三组卡、库外卡、不足 5 本说明、域级说明条、调参滑杆 |
| `/book/:id` | BookDetailView | 无诊断时退化为「书目页」，不假装知道用户是谁 |
| `/booklist` | BooklistView | 书单导出（`*.booklist.json`）与他人书单导入 |
| `/library` | LibraryView | 本地书库三组；删除只清书与进度，**不删划线笔记** |
| `/import` | ImportView | 拖入解析、失败态分流、落库 |
| `/reader/:id` | ReaderView | 阅读器主体 |
| `/crisis` | CrisisView | 援助资源（独立 chunk，不随主包加载） |
| `/about` | AboutView | 隐私说明、本机匿名计数、危机入口（全项目 2 个入口之一） |
| `/framework` | FrameworkView | 读书框架（怎么读一本书的方法页） |

### 3.2 十七项 P0

| 编号 | 功能 | 关键验收点 |
|---|---|---|
| P0-1 | 困境问卷 | 第 3 屏 5 组 chip 同屏；「说不上来」有出口 |
| P0-2 | 自由文本与降级 | ≤140 字；未命中标签也照常出结果 |
| P0-3 | 规则打分 + 硬约束排序 | 7 因子权重和恒为 10000；同输入两次结果逐字节一致 |
| P0-4 | 三段式理由 + 字段降级 | 无 `{{` 残留；禁用词命中 0 |
| P0-5 | 三档呈现 | **不出现任何百分数** |
| P0-6 | 结果页 5 本分 3 组 | 第三组不显示档位方块 |
| P0-7 | 书籍详情页 | 可用性区块紧随书名，不放页底 |
| P0-8 | 导入引导 + 失败态 | 12 种失败态按原因分类，不用统一文案 |
| P0-9 | EPUB 阅读器 | 翻页 / 字号 / 主题 / 目录 / 书内搜索 |
| P0-10 | TXT 阅读器 | GB18030 自动判定；章节识别有兜底 |
| P0-11 | 本地书库 | 在读 / 读完 / 想读 |
| P0-12 | 划线 + 笔记 | 跨版式可恢复（双锚点） |
| P0-13 | 内置直读 | **1 本自写示例书**，走与导入完全相同的链路（见 §5.4） |
| P0-14 | 离线可用 | 断网刷新首屏与已导入书可读 |
| P0-15 | 推荐导出 | `*.booklist.json`，可被别人导入 |
| P0-16 | 危机资源条 | 仅「情绪与自我」域；不可关闭 / 不折叠 / 滚动不移除 |
| P0-17 | 无 inline 域说明条 | 显示与否**从书库算**，不是写死域名列表 |

### 3.3 结果页怎么呈现

- **5 本分 3 组**：较为契合（strong）/ 值得一读（worth）/ 可以试试（explore）。阈值是绝对值（8000 / 6000 基点），不是分位数。
- **只给档位，不给分数**：不出现百分数、不出现原始分。理由有两条：版权风险；避免「分数崇拜」——推荐的主依据是困境匹配，不是书的好坏。
- **主诉封顶**：若一本书对用户的**主诉**标签一条都不沾（`primary_hit = 0`），无论总分多高，档位封顶 `explore`。这是防止「一本不沾题的书靠难度篇幅全中混进 worth」的保险。
- **每句理由带来源**：界面上的理由句必须在三档来源之内（书里写的 / 你的回答 / 书的标注），点开能看到它是怎么来的。
- **调参滑杆**：结果页可实时覆写难度 / 篇幅 / 时长三组偏好，即时重算，不持久化——它是对诊断的修正，不是新设置。

### 3.4 危机通道（两条，互斥）

| 通道 | 触发 | 表现 | 约束 |
|---|---|---|---|
| 全局 | 自由文本检出危机信号 | 结果页整体让位，不出推荐 | 与推荐**硬互斥**，有单测 |
| 域级常驻条 | 用户落在「情绪与自我」域 | 结果页顶部常驻条 | 不可关闭、不 toast、不折叠、滚动不移除 |

定稿文案（不得改）：「如果你现在不太好过，读书可以先放一放。这里有可以立刻联系的心理援助资源。」

- 用「不太好过」而不是「状态很差」：后者是给用户下负面判断，他此刻不需要被诊断，需要被允许。
- 「读书可以先放一放」必须留：这是本产品「不推销自己」的唯一硬证据，删掉就退化成免责声明。
- **热线号码不写进界面组件**：写死必然过期，过期号码比不展示更伤信任。号码只在资源页从数据文件读取，页顶标最近核对月份，页底给「打不通或已变更，请提 issue」。

### 3.5 库外路径 D

库内不足 5 本时，用「库外候选」补齐，但**不是**把库外的书当库内书用：

- 不落库、不入池、**不参与打分**、不显示档位方块，卡片固定标「未入库」。
- 理由文案禁止出现任何打分口径词（契合度 / 得分 / 档位 / 排名 / 权重等）。
- 排序键为「标签重合数降序、书名升序」，保证确定性（不用 `localeCompare`，它随语言环境变化）。

### 3.6 导入到阅读这条链路

**导入**：拖入 EPUB 或 TXT，浏览器内解析、切章、落 IndexedDB。零依赖、不上传、不用等服务器。

| 环节 | 关键做法 | 为什么 |
|---|---|---|
| ZIP 解析 | 以**中央目录**为唯一真源 | 本地文件头里的文件名与扩展字段可被伪造，按本地头解压等于相信书里自带的一张标签 |
| 解压 | `DecompressionStream('deflate-raw')` | 零依赖，不引 JSZip |
| 编码判定 | BOM → 严格 UTF-8（fatal）→ UTF-16LE 启发式 → GB18030 | 顺序不能换：`TextDecoder('gb18030')` 对任何字节都能解出一串字，先试它等于永不失败、也永不出错，只会得到乱码 |
| 失败态 | 12 种按原因分流 | 「导入失败」四个字对用户毫无用处；DRM 保护、扫描件无文字层、超大文件各有各的下一步 |
| 落库失败 | 区分 `E_STORAGE_QUOTA` 与 `E_STORAGE_FAILED` | 前者删本书就能解决，后者是隐私模式下库打不开，删书没用 |

**阅读**：

- **按段落分页**，不按字符硬切（否则一段话会被切成两页）。换字号后靠 `pageOfParagraph` 找回原段落，位置不丢。
- **双锚点定位**：`txt-offset`（字符偏移）+ `quote`（引文）+ `prefix/suffix` 各 30 字。四级降级依次是精确命中、邻近命中、引文重复时就近取值、按 occurrence 取第 n 次。**不伪造 CFI**。
- **删除不删笔记**：删一本书清掉 books / chapters / files / progress / shelf 五处，`annotations` / `notes` 保留——划线是位置，笔记是内容，位置没了内容更值钱。

### 3.7 书单导出与导入

格式 `bookrx.booklist/1`：`{ schema, exported_at, data_version, diagnosis, items[], note? }`。两条硬约束：

1. **只存用户的选择，不存任何分数字段**——分数换个书库版本就会变，存进文件会让收件人以为「对方的分数」可比，而它不可比。
2. `items[]` 只留 `book_id / title / tier` 三项，供收件人在自己书库里对照；缺失时不假装匹配。版本只向前兼容：`schema` 比本应用新就拒绝导入并明说，不硬读。

## 4. 技术思路

### 4.1 形态：纯前端 local-first

Vue 3 + TypeScript + Vite，静态站点，**无后端、无账号、无云同步**。数据全在浏览器里：书目数据是随包分发的静态 JSON，用户的书与笔记在 IndexedDB。

为什么不做后端（ADR-002）：产品的数据有三类——诊断答案（含困境自述，属敏感个人信息）、划线笔记（长期资产）、书目（可公开）。做后端立刻带来 2–3 人月开发、备份、隐私合规与运营成本，而 MVP 要验证的是「诊断 → 推荐 → 读下去」这条链是否成立，不是「多设备能不能同步」。

副作用是好的：**「我们不上报」不是一句承诺，是没有服务器可以上报。**

### 4.2 分层与依赖方向

```
views / components     只装配与交互
engine/                业务编排（推荐、诊断、导入、分页、定位）
domain/                纯函数：无 I/O、无 DOM、无 Vue、无数据库
data/                  静态数据与词表
storage/               IndexedDB 读写
lib/                   通用小工具（摊平、格式化、离线注册）
contracts/             类型声明，编译后零字节
```

依赖只能向下。`domain/` 里出现 `Math.random` 或 `Date.now` 会被测试拦下——**可复现是推荐结果的前提**。

### 4.3 数据三层

| 层 | 规模 | 内容 | 用途 |
|---|---|---|---|
| 核心库 | **68 本** | 34 字段齐全，含 5 段预写文案 | 进入主推荐池，能出完整理由 |
| 候选池 | **6551 本** | 元数据 + 豆瓣标签，无预写文案 | 宽池「和你这个困境相关的还有 N 本」 |
| 派生标注层 | 6551 本全覆盖 | 由 33 标签词表派生的困境标签 | 让没人工标注的书也能进池，但如实报覆盖率 |

候选池来自公开书目数据的本地抓取（7734 行原始记录清洗为 6551 条）。**这批数据不随代码授权**，只作演示数据随仓库分发——它派生自第三方站点，本项目无权以 CC 协议再授权。用一个自己并不拥有的权利去授权，比不授权更糟。

### 4.4 打分算法（核心，读准单位）

**执行顺序不可颠倒**：硬过滤 → 打分 → 排序 → 分档。

**七因子权重，和恒为 10000**：

| 因子 | 权重（基点） | 含义 |
|---|---|---|
| problem | 3800 | 困境匹配（覆盖率口径：Σmin(用户权重, 书权重) / Σ用户权重） |
| difficulty | 1800 | 难度适配 |
| depth | 1200 | 深浅（要 why 还是要 how） |
| form | 1000 | 文体形态（叙事 / 框架 / 练习） |
| length | 1000 | 篇幅 |
| readability | 700 | 文字可读性 |
| availability | 500 | 可得性（能否马上拿到） |

**一切分数是 0–10000 的整型基点，不是 0–1 小数。** 混用不会报错，只会让 `>= 8000` 这类判据恒假。

**四条容易踩的规则**：

1. **跳答不等于填中位数**：某组未答，对应因子整条移除，其余权重按比例归一到 10000。填中位数会让未观测维度稳定输出 5000 分。
2. **`availability` 归一化后也不许超过 800 基点**，超出部分按比例还给其他因子。可得性不能主导推荐。
3. **覆盖率降级**：字段缺失的书不填默认值，而是让对应因子整条不参与打分，并如实报出覆盖率。这样 6551 本都能进池，但不会因为填了默认值而假装准确。
4. **硬过滤 7 条**在打分之前执行：难度超限、篇幅超限、创伤内容、临终丧亲、无困境标签、用户排除、仅元数据。其中创伤类（自杀 / 性暴力）**不可豁免**；临终丧亲可被「我能接受沉重内容」开关豁免——**开关承诺的范围必须等于放行的范围**。

**排序 6 级全序**：分数降序 → problem 契合降序 → difficulty 契合降序 → 可得性升序 → 预计时长升序 → 书 id 升序。最后一级保证全序，且链上不含任何时间字段（否则不可复现）。

**分档**：≥8000 较为契合，≥6000 值得一读，其余可以试试。阈值是绝对值，禁止为了「好看」下调——一旦下调，「高度契合」就变成夸奖词，而用户发现第 1 本读不下去时，整套诊断的可信度会一次性归零。

### 4.5 为什么不用 LLM（ADR-004）

四个硬要求让它出局：**可解释**（用户会问「为什么是它」，答不上来就退化成黑箱推荐器）、**可单测**（推荐是这个产品的判断力所在，不能被断言就只能盲改）、**可复现**（LLM 即使在 temperature=0 下也不保证跨版本跨供应商一致）、**零成本**（每次推荐都产生调用成本，而这个产品连账号都没有）。

所以：打分用规则，理由用预写文案 + 模板渲染，自由文本用同义词表 + 允许插入成分的匹配（实测 32 句真实说法命中率 ≥70%，完全零命中 ≤15%）。

### 4.6 阅读器为什么自建（ADR-009）

原计划引 foliate-js，理由是它的 CSS 多列分页最成熟。落地时改了，因为那套方案把**标注绑在 DOM Range 上**——而本项目大部分书由用户自己导入，换一份文件就换一套 DOM，Range 必然失效，而且**静默错位**（用户不会发现，只会看到划线跑到别的句子上）。

改为自建字符流渲染 + 双锚点定位。代价是明确放弃的能力：固定版式、表格排版、原书字体。这个代价写进了 ADR 的「放弃清单」，不是事后解释。

### 4.7 六个「错了也不响」的坑

这些坑的共同点是：**不报错、不崩、门禁全绿，只是行为不对。** 它们是这个项目最贵的知识。

| 坑 | 症状 | 根因 | 定式 |
|---|---|---|---|
| 响应式 Proxy 写不进 IndexedDB | 进度「有时候」不保存 | `IDBObjectStore.put` 抛 `could not be cloned`，而调用处是 `void save(...)`，异常被吞 | 写库前统一摊平（保留 ArrayBuffer / Blob / Date） |
| 段落首子节点是注释锚点 | 脚本化划线永远不出现 | Vue 的 fragment 在段首留注释节点，`firstChild` 建 Range 得到折叠空选区 | 用 `TreeWalker` 找第一个有字的文本节点 |
| CSS 令牌拼错 | 界面上某处「看起来还行」 | CSS 变量拼错不报错，只是那条声明被丢掉 | 新增 `token-audit`：引用未定义即红 |
| 编码判定顺序写反 | 全文乱码但不抛错 | GB18030 解码器对任何字节都能出字 | BOM → 严格 UTF-8(fatal) → UTF-16LE → GB18030 |
| 用本地文件头解 ZIP | 少数书解析出奇怪内容 | 本地头可伪造，中央目录才是真源 | 只认中央目录 |
| 闸门断言写成恒真 | 测试全绿但闸门 0/10 也过 | 断言写成 `<= 10` 这类永真式 | 每条门禁都要有「必须能红」的测试 |

最后一条是最贵的：**测试全绿和闸门通过是两件事**。写断言时唯一该问的是「这个断言有没有可能失败」。

### 4.8 门禁即规格

`npm run check` 串起 10 条检查，每条都对应一份文档条款，**并且每条检查自己都带测试**（既证能红，也证不误红）：

| 命令 | 拦什么 |
|---|---|
| `typecheck` | 契约与实现不一致 |
| `test` | 打分、金标、导入、分页、定位降级、文案一致性 |
| `check:enums` | SPEC / ARCH 与代码枚举分叉 |
| `audit:style` | emoji、硬编码色值、单文件超长（src ≤300 行 / tools ≤400 行） |
| `audit:token` | 引用了不存在的 CSS 令牌 |
| `audit:copy` | 禁词、营销话术、危机页埋点泄漏 |
| `audit:doc` | 文档里的表格列数错位、emoji、失效锚点 |
| `audit:crisis` | 危机资源可核实性（必须有来源与核对日期，超期红灯） |
| `data:verify` / `data:map-core` | 书目数据、派生标注与规则逐位一致 |

**三态纪律**：每条检查只能报「通过 / 失败 / **未验证**」。扫描对象为空时必须报「未验证」并非零退出——**「扫到了 0 个文件」不是通过**。用 `|| true`、`console.warn` 代替断言，或「扫到 0 当通过」，都是明令禁止的。

| 不做 | 原因 |
|---|---|

### 5.4 三处「按现实改写规格」的裁量

规格书是按最终形态写的，落地时有三处照抄会变成假话，改了并在 SPEC 里留了条款：

1. **P0-13 内置 30–40 本公版全文 → 改为 1 本自写示例书。** 两个理由都不是省事：公版文本版本差异极大（断句、错字、注释、删节），随手放一份进去用户看到的是劣质底本，而我们无力逐字校勘；分发他人全文要同时回答「底本来源 / 校勘责任 / 整理者权利」三问，而整理者权利（点校、注释本）在中国法下并非总是清晰。示例书解决的真问题是「在导入自己的书之前先试手感」，且三个问题一个都不存在。公版书仍可通过外链读到。
2. **P0-17 无 inline 域说明条 → 显示与否从书库算。** 规格写死了三个域名，其中一个是「情绪与自我」，而情绪域其实有公版书，照抄就会在一个有两本公版书的域里说「基本都还在版权期内」。改成从书库实时计算：书库长出来，说明条自动消失。
3. **能力开关而非硬编码。** 阅读器未上线时，所有涉及能力的话过一道布尔开关（`READER_AVAILABLE`）：「可直接阅读」降级为「公版·站外可读」，「导入后就能读」降级为「每本书都给了找书的路径」。**被挡住的定稿文案不删不重写**，注释里写明怎么改回来——上线只翻一个布尔值。这个开关已翻为 `true`。

### 8.3 雷区（违反会静默出错或直接被门禁拦下）

1. **不要在 `domain/` 里用 `Math.random` 或 `Date.now`**：可复现是推荐的前提，有测试拦。
2. **不要混用「基点」和「小数」**：所有分数是 0–10000 整数，写成 0.85 不会报错，只会让阈值判断恒假。
3. **不要混用 6 个困境域和 6 个文体类**：都是 6，混用会静默成功——测试全绿但排序变了。
4. **不要下调档位阈值让数字好看**：只允许调权重与标注。阈值一旦松动，「较为契合」就变成夸奖词。
5. **不要给缺失字段填默认值**：正确做法是让该因子整条不参与打分并如实报覆盖率。
6. **不要在危机页加任何埋点或第二个入口**：配额恒为 2，由 DOM 计数断言守。
7. **不要写「扫到 0 个文件 → 通过」的检查**：只能报「未验证」并非零退出。
8. **改契约的顺序**：先改 SPEC → 再改类型草稿 → 同步 `contracts/` → 跑 `check:enums` 对拍。反序必然分叉。
