## 4. 发现的问题

### P1-1 危机页号码不可点击拨打（新发现，真实缺陷）

- **现象**：`/crisis` 四组号码 `['12356', '010-82951332', '400-161-9995', '120 / 110']` 全部包在 `<p class="crisis-contact">` 里，全项目 `grep "tel:"` 结果为 **0**。
- **影响**：这是全站唯一「用户可能正在危机中」的页面。手机上看到号码不能点，得长按选择、复制、切到拨号盘粘贴——在那一刻，每多一步都是真实的门槛。`120 / 110` 还是两个号拼在一个 `<p>` 里，无法整段包成一个链接。
- **修法**：`contact` 增加可选的 `tel` 字段（`"120 / 110"` 拆成两条独立资源，或给 emergency 加 `tels: ['120','110']`）；模板里渲染成 `<a :href="'tel:' + ...">{{ contact }}</a>`，并保留纯文本兜底（桌面浏览器点 `tel:` 无反应，需要文案提示）。
- **注意**：`CrisisView.vue` 受 `copy-audit` 层 2 三条 `crisis-*` 规则约束，改模板后必须重跑 `npm run audit:crisis` 与 `audit:copy`。

### P1-2 `computeStreak` 的 `freezes_used` 虚报（已知缺陷 1）

- **现象**：连续三天全勤也显示「已用 1 次冻结」；漏一天时记 2 次。
- **根因**：碰到缺口时立刻 `freezes += 1`，**在确认缺口后面还有记录之前**就记账；结尾那段没救到任何东西的缺口也被计入。
- **修法**：把 `freezes += 1` 移到「确认能继续」之后，或先收集缺口位置再统一结算。
- **状态**：`tests/domain/stats.test.ts` 有 3 条 `it.fails` 分别钉住：连续三天全勤、漏一天、已经断了不该再报冻结。

### P2-1 `dayNumber('')` 返回 0（已知缺陷 2）

- **现象**：`Number('') === 0`，空串被当成「1970-01-01」收进集合，可能虚增连续天数。
- **修法**：入口先做 `/^\d{4}-\d{2}-\d{2}$/` 校验，非法返回 `NaN`。
- **状态**：`it.fails` 钉住。

### P2-2 未知书架分组导致白屏（已知缺陷 3）

- **现象**：`buildShelf` 遇到不认识的 `group` 会 `out[group].push(...)` → `undefined.push` → TypeError，整页书架白屏。
- **触发**：旧版本数据 / 手工改库 / 将来加组别时漏改。
- **修法**：未知分组折回 `'want'` 并记一条 warn，不抛错。
- **状态**：`tests/domain/shelf.test.ts` 用 `it.fails` 钉住。

### P2-3 导出按钮高度 36px（触控尺寸）

- **现象**：`/library` 的 `.notes-btn`（导出笔记 / 从文件导入）实测 `36px`，低于 44px 规范。`NotesTransfer.vue` 里写的是 `min-height: 36px`。
- **影响**：移动端可点区域偏小，相邻两个按钮间距仅 8px，容易误触。
- **修法**：改 `min-height: 44px`（或 `padding` 补足），同时确认不撑破 375px 布局。

### P3 观察项（不算缺陷，记录备查）

- `percentText(NaN)` 输出 `'NaN%'` —— 上游目前不会传 `NaN`，但接口没有兜底。
- `isChapterRef([])` 返回 `true` —— 宽松，下游安全。
- `/compare?a=X&b=X` 渲染两列相同的书 —— 无害，但可以加去重。
- 内联链接高度 17–25px：书库卡片标题（25px）、页脚链接（19–21px）、危机页「来源」（17px）。**属于正文内联链接**，按 WCAG 2.5.8 的「inline 豁免」不算违规；只有 `.notes-btn` 这类独立按钮必须达 44px。
