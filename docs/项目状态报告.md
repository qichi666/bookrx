## 一、项目概况

**BookRx（书方）**是一款纯前端、无后端、无账号的读书推荐应用（计划以 Web 形态发布，GitHub 开源）。

- **核心定位**：不做"大众评分"或"猜你喜欢"，而是让用户描述**当下具体困境**（如"开会不敢发言"），系统基于一套**可复现的确定性打分算法**推荐 ≤5 本书，并**逐本说明推荐理由**（为什么是这本、契合在哪、不契合在哪）。
- **与竞品的差异**：主流工具（微信读书 / Goodreads /豆瓣）按人群偏好推荐；本产品按"困境 → 书"的单人匹配推荐，理由逐本预写而非生成。
- **明确不做**：社区、评论、打卡、排行榜、PDF/漫画/TTS/OPDS、账号云同步、豆瓣评分、LLM 生成理由（不可复现）。
- **三项已冻结决策**：产品名 BookRx（书方）、首发 60 本核心库、阅读器放到 M2。

### 3. 打分内核 `src/domain/scoring/`（8 个纯函数模块）

| 文件 | 职责 | 关键不变量 |
|---|---|---|
| `numeric.ts` | 定点算术 + 最大余额分配 | 所有 `*_bp` 均为 0–10000 整型基点；分配结果 Σ===total 且与输入顺序无关 |
| `weights.ts` | 七因子权重表 | 和恒 =10000；跳答重归一化后仍 =10000；`availability` 封顶 800 bp |
| `targets.ts` | 问卷答案 → 各因子 target | target 恒为整数（选项只允许 25/50/75）；跳答的因子整条移除 |
| `fit.ts` | 七因子 fit 计算 | problem 用覆盖率口径（Σmin/Σ用户权）；`primary_hit` 为整型基点 |
| `score.ts` | 打分 | `contribution = floor(fit×w/10000)`，`score_bp = Σ contribution`（构造上严格相等，不靠补差）；七项全中恰得 10000 |
| `filters.ts` | 硬过滤（打分之前） | `FILTER_RULES` 7 条：`EX-difficulty / EX-load / EX-trauma / EX-terminal / no-problem-tags / excluded-by-user / metadata-only`；`EX-trauma` 不可豁免，`EX-terminal` 可被 `include_heavy` 豁免 |
| `rank.ts` | 6 级全序 tie-break | `score_bp↓ → problem.fit↓ → difficulty.fit↓ → availability↑ → est_reading_hours↑ → book_id↑`；末级保证全序，无时间字段 |
| `tier.ts` | 分档 | 阈值绝对值 8000/6000 bp；`primary_hit=0` ⇒ 封顶 `explore`（不改分数只改标签） |

**七因子权重**（和 = 10000，单测锁定）：problem 3800 / difficulty 1800 / depth 1200 / form 1000 / length 1000 / readability 700 / availability 500。

### 4. 推荐引擎与库外路径 D

- `src/engine/recommend.ts`：主链路 ①硬过滤 → ②打分 → ③排序 → 库外补位。**库内不足 5 条时用路径 D 补到 5 条**（推荐数量不受书库规模限制）；库外候选也不足时如实少给，不伪造。

### 核心算法机制（接手必读）

1. **打分是纯函数**：同输入同输出，禁止 `Math.random`/`Date.now`（有测试强制）。结果可逐字节复现是闸门 0 两项指标的前提。
2. **执行顺序不可颠倒**：① hardFilter → ② score → ③ rank → ④ slotAssembly → ⑤ relax → ⑥ tier（④⑤⑥ 属 M1，未实现）。
3. **一切分数是 0–10000 整型基点**，不是 0–1 小数——混用不会报错，只会让 `≥8000` 这类判据恒假。
4. **主诉封顶**：`primary_hit = 0` ⇒ 档位封顶 `explore`，与总分无关。这是"防止一本不沾题的书靠难度/篇幅全中混进 worth"的保险。
5. **跳答 ≠ 中性值**：第 3 屏某组未答，对应因子整条移除、权重按比例归一到 10000。填中位数会让未观测维度稳定输出 5000 分。
6. **`include_heavy` 只豁免 `EX-terminal`**（临终/丧亲），不豁免 `EX-trauma`（自杀/性暴力）——开关文案只承诺了前者，承诺范围必须等于放行范围。
7. **`domain`（6 困境域）≠ `category_l1`（6 文体）**：都是 6，混用会静默成功——测试全绿但排序变了。
8. **文档里错一个数字，进代码就是一条永远失败的测试**——改数字前先跑 `npm run test`，以 `tests/domain/arch-3-9.test.ts` 为准。

## 五、给接手 AI 的注意事项

1. **先读 `docs/SPEC.md`**，它是唯一契约；PRD/ARCH/UIUX 与它冲突时一律以 SPEC 为准。
2. **改契约的顺序**：先改 SPEC，再改 `docs/types-draft.ts`，再跑生成脚本同步 `src/contracts/`（`tools/check-enums.mjs` 会把两边对拍）。
3. **不要绕过门禁**：`npm run check` 与 `npm run build` 的每条断言都在不达标时非零退出；`|| true`、`console.warn` 代替断言、"扫到 0 个当通过"都是被明令禁止的。
4. **方案未确认前不动手写代码**（用户的硬规矩）；用户说"调整/改成"≠开工指令，只有明确"开始做"才算。
5. **推荐数量不受书库规模限制**：库内不足就用库外路径 D 补齐，不得以"库里只有 60 本"为由中断或拒绝回答；库外书直接以书名列出并标注「未入库」。
6. 优先级最高的两件工程事：**`git init` 建立版本控制**、找机会对三位协作者离线期间的单人产出做一轮复核。
