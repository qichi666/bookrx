# BookRx 数据源调研与推荐方案 v1.0

> 版本：2026-10-19 · 状态：方案（未实施，待确认）
> 适用：BookRx（困境 → 书）纯前端确定性推荐应用
> 本文回答四个问题：① 用哪些公开数据、怎么拿；② 怎么清洗；③ 怎么推荐、怎么呈现；④ 怎么教用户读书。附竞品调研。

---

## 0. 结论摘要

1. **没有任何单一公开数据集同时具备「高质量中文书目 + 简介 + 分类 + 评分」**。可行路径是**多源合并**：豆瓣抓取（中文元数据最全）为主 + OpenLibrary / Google Books（ISBN、英文补齐）为辅 + goodbooks-10k（评分先验参考）。
2. **英文大库（UCSD Book Graph 236 万本、Amazon Books 440 万件）许可为「仅学术、不得再分发/商用」**，不能内置进开源静态站。它们只能离线用于**方法验证与先验估计**，不能成为产品数据。
3. **评分不能当主排序依据**。图书评分是「大众口味」信号，与「你此刻的困境」正交；且新书评分少会被误杀。正确用法是**贝叶斯收缩后只做同档 tie-break 与质量闸门**。
4. **推荐形态必须是内容匹配而非协同过滤**：纯前端、无账号、无历史行为，CF 无从谈起；内容匹配还天然可解释，符合「每本推荐都要说清为什么」的产品契约。
5. **覆盖率问题的解法是三层书库**：书目层（万级，机器抓取，只进搜索）→ 候选层（千级，机器初筛 + 轻标注）→ 核心层（数百本，人工核对 34 字段，唯一进打分推荐）。

## 1. 公开书籍数据集调研

### 1.1 筛选标准

| 编号 | 标准 | 要求 | 理由 |
|---|---|---|---|
| S1 | 字段覆盖 | 至少含书名、作者、简介/描述、分类、评分 | 用户明确要求 |
| S2 | 规模 | 中文候选 ≥1 万条 | 解决「总是那几本书」 |
| S3 | 许可 | 允许再分发，或仅用于离线生成自有衍生数据 | 项目是开源静态站，内置数据要能公开 |
| S4 | 可获取性 | 有稳定下载或可编程接口，不依赖私有 key | 可复现、可定期更新 |
| S5 | 中文覆盖 | 中文书名/作者/简介可读 | 目标用户是中文读者 |
| S6 | 维护状态 | 近 5 年有更新，或数据本身是静态事实 | 评分/在架状态会过期 |

### 1.2 候选数据集逐个画像

#### D1 · UCSD Goodreads Book Graph
- **来源**：加州大学圣地亚哥分校 McAuley Lab，2017 年末抓取 Goodreads 公开书架，2019-05 修订。
- **规模**：2,360,655 本书（1,521,962 works / 829,529 作者）、876,145 用户、228,648,342 条书架交互（含 104,551,549 条评分）。
- **字段结构**（`goodreads_books.json.gz`，单条 JSON）：

| 字段 | 含义 |
|---|---|
| book_id / work_id | 书 / 作品 ID |
| title / title_without_series | 书名 |
| authors | 作者数组（含 author_id） |
| description | 简介（HTML） |
| average_rating / ratings_count / text_reviews_count | 评分与计数 |
| similar_books | 平台给出的相似书 ID 列表 |
| popular_shelves | 用户书架标签及计数（可提取题材） |
| num_pages / publication_date / publisher / language_code | 版本信息 |
| is_ebook / format | 载体形式 |

- **获取方式**：<https://cseweb.ucsd.edu/~jmcauley/datasets/goodreads.html>，`goodreads_books.json.gz` 约 2GB（解压约 8GB）；按题材有子集（如 children 12.4 万本）。
- **许可**：**仅学术使用，禁止再分发、禁止商用**（页面原文明确）。
- **优点**：字段最全、有 `similar_books` 可直接做相似度验证、有题材子集。
- **局限**：英文为主、中文书几乎没有；2017 年快照，评分已过期；许可不允许进产品。

#### D2 · goodbooks-10k
- **来源**：Kaggle 社区整理（原始抓取 2017-08），已修复重复与异常，是推荐系统经典练手集。
- **规模**：10,000 本书、约 5 万用户、5,976,479 条评分；5 张表。
- **字段结构**：

| 表 | 字段 |
|---|---|
| books.csv（23 列） | book_id, goodreads_book_id, title, authors, original_publication_year, language_code, average_rating, ratings_count, work_text_reviews_count, ratings_1..5, image_url |
| ratings.csv | user_id, book_id, rating（1–5） |
| to_read.csv | user_id, book_id |
| book_tags.csv | goodreads_book_id, tag_id, count |
| tags.csv | tag_id, tag_name |

- **获取方式**：<https://github.com/zygmuntz/goodbooks-10k>（CSV 直下）；Kaggle 同名数据集。
- **许可**：数据集以公开仓库分发，原始内容版权归 Goodreads。
- **已知质量问题**：`original_publication_year` 有缺失与**负年份**；`book_tags.count` 存在**负值**；ISBN 有空值；多作者以 `-` 分隔导致 CSV 列错位。
- **优点**：干净、体量适中、有逐星分布（ratings_1..5），适合估计「评分先验」与验证排序。
- **局限**：仅 1 万本、英文为主，不适合当产品库。

#### D3 · Amazon Reviews 2023 — Books
- **来源**：McAuley Lab 2023 版（571.54M 全站评论，Books 类子集）。
- **规模**：Books 类 10.3M 用户 / 4.4M 商品 / 29.5M 评分。
- **字段结构**：
  - 评论：rating（1–5）、title、text、verified_purchase、helpful_vote、timestamp、asin、parent_asin、user_id
  - 元数据：main_category、title、average_rating、rating_number、features、description、price、categories、details、bought_together
- **获取方式**：<https://amazon-reviews-2023.github.io/>（`meta_Books.jsonl.gz` 等直链）。
- **许可**：研究用途，需引用；不得商用再分发。
- **优点**：规模最大、元数据最丰富（含价格、类目层级）。
- **局限**：亚马逊商品条目混杂（练习册、涂色书、套装），不是严格「图书」；英文为主；不能内置。

#### D4 · Book-Crossing
- **来源**：德国弗莱堡大学 Cai-Nicolas Ziegler，2004 年 8–9 月抓取图书漂流社区。
- **规模**：278,858 用户、271,379 本书、1,149,780 条评分。
- **字段结构**：
  - BX-Books：ISBN、Book-Title、Book-Author（**仅第一作者**）、Year-Of-Publication、Publisher、Image-URL-S/M/L
  - BX-Users：User-ID、Location、Age
  - BX-Book-Ratings：User-ID、ISBN、Book-Rating（1–10 显式；0 = 隐式）
- **获取方式**：Kaggle（CC0 版本）、天池、原始站点；CSV 合计约 120MB。
- **优点**：许可宽松（CC0）、经典基准、适合验证协同过滤基线。
- **局限**：**无简介、无分类**；2004 年数据，书龄二十年；仅第一作者；不满足 S1。

#### D5 · OpenLibrary Data Dumps + API
- **来源**：Internet Archive 的 OpenLibrary 项目。
- **规模**：每月全量 dump；editions 约 9.2G、works 约 2.9G、authors 约 0.5G；另有 ratings dump（约 5M 行）与 reading-log（约 65M 行）。
- **字段结构**：TSV，固定 5 列 `type / key / revision / last_modified / JSON`；JSON 内含 title、authors、description、subjects、covers、ISBN、publish_date、number_of_pages 等。ratings dump 列为 `Work Key, Edition Key, Rating, Date`。
- **获取方式**：<https://openlibrary.org/developers/dumps>（月更）+ REST API（`/search.json?q=`、`/isbn/{isbn}.json`）。
- **许可**：数据以 CC0 精神开放（条目由社区/图书馆贡献），适合再分发。
- **优点**：**唯一「许可干净 + 覆盖全球 + 有 ISBN」的大库**；字段足够补齐书名/作者/简介/主题。
- **局限**：中文书目覆盖弱于豆瓣；描述与主题多来自图书馆编目，可读性一般；评分数据稀疏（5M 行对千万级 works）。

#### D6 · Google Books API
- **来源**：Google Books 公开 API v1。
- **规模**：索引级（未公开总量），可按关键词、ISBN、作者检索。
- **字段结构**（`volumeInfo`）：title、subtitle、authors[]、publisher、publishedDate、description、industryIdentifiers[]（ISBN_10/13）、pageCount、categories[]、averageRating（1–5）、ratingsCount、language、imageLinks、previewLink、infoLink。
- **获取方式**：`GET https://www.googleapis.com/books/v1/volumes?q=...`，公开卷无需鉴权，有配额限制。
- **许可**：遵守 API 条款，需保留署名与跳转链接；不可批量导出当自有库。
- **优点**：字段最规整、有 ISBN 与分类、中文检索可用（覆盖率中等）；适合**按 ISBN 逐本补全**。
- **局限**：不能整库导出；`averageRating` 常缺失或样本极小；配额限制批量调用。

#### D7 · 豆瓣系数据集（抓取型）
- **来源**：豆瓣读书（book.douban.com）。官方 API 已死：图书 API 2019-04 起不可用，公开 API 2019 年整体下线，开发者平台 2023 年关停。现存数据全部来自社区抓取。
- **代表数据集**：

| 数据集 | 规模 | 字段 | 获取 |
|---|---|---|---|
| 和鲸「豆瓣读书数据集」 | 60,000 本 | 书名、出版时间、页数、价格、ISBN、评分、评论数 | 和鲸社区（CSV 5.9MB） |
| GitCode「豆瓣图书数据集」 | 2,300+ 本 | ISBN、title、author、author_intro、tag、numRaters、average、binding、pages、publisher、origin_title、summary、url | GitCode 仓库 |
| Douban-Dushu-Dataset | 3,700 万条短评 / 1.8 万本书 / 100 万用户 | 评论、星级、点赞、日期、书名、标签 | Google Drive / 百度云，CC BY-NC-SA |

- **优点**：**中文书目字段最齐全**（评分 + 标签 + 简介 + 作者简介 + 出版社 + 页数），与目标用户完全匹配。
- **局限**：无官方接口、反爬严格；**版权归豆瓣，原始数据不可再分发**；数据集多为 2019–2022 年快照，评分会漂移；小数据集字段常有空值。

#### D8 · 中文商业数据集（闭源）
- **代表**：DataSN「6 类 275,784 中文图书」（价格/作者/出版社，28 列，153MB）、「45 类 26,770 本（目录/内容简介/作者简介）」；海数据「书籍信息综合数据库」（ISBN/书名/作者/分类/简介/评分，4MB）。
- **获取方式**：付费下载 / API。
- **优点**：规模大、中文全、字段规整。
- **局限**：**闭源付费，不可再分发**；来源多为电商抓取，评分真实性无法验证；不满足 S3。

### 1.4 选型结论

**主数据源：D7 豆瓣抓取（中文元数据）+ D5 OpenLibrary（ISBN 与世界书目）+ D6 Google Books（按 ISBN 补全）**

分工：

| 层 | 数据来源 | 产出 | 用途 |
|---|---|---|---|
| 书目层（1–3 万条） | 豆瓣标签页爬取 + OpenLibrary 搜索 + Google Books 按需补全 | `public/catalog/candidates/*.json`，每条：书名/作者/出版社/ISBN/一句话简介/豆瓣或 OpenLibrary 链接 | 搜索全覆盖，标「未入库」，外链兜底 |
| 候选层（500–2000 本） | 书目层按「评分人数 + 标签相关度」筛 | 同上 + 初步归类（7 域） | L4「这些都不对」的扩展、核心层供料 |
| 核心层（300–500 本，先 70 本） | 候选层 → 人工核对 34 字段 | `catalog/shards/*.json`（现有契约） | **唯一参与打分推荐** |

**辅助验证源：D2 goodbooks-10k + D1 UCSD 子集**
- 仅离线用于：估计评分先验参数（贝叶斯 C、m）、验证排序策略、评估「评分 vs 困境匹配」的相关性。
- 不进产品、不进仓库。

**明确排除**：
- **D4 Book-Crossing**：无简介无分类，2004 年数据，不满足 S1/S6。留作协同过滤基线复现用。
- **D3 Amazon 2023**：许可不允许再分发；品类混杂。仅在需要「价格/类目层级」参考时离线查看。
- **D8 商业闭源库**：付费且不可再分发，与开源定位冲突。

**版权与合规的硬边界**（写进 README 与 SPEC）：
- 图书**书目事实**（书名、作者、出版社、ISBN、页数）版权风险低，可内置。
- **简介不能整段复制**：一句 40–60 字的 `one_line_what` 必须自有改写（现有契约已如此）。
- **评分不原样内置**：只内置「贝叶斯收缩后的档位/百分位」，并标注「参考豆瓣/OpenLibrary 公开评分，采集日期 X」。
- 抓取遵守：只抓公开页面、不登录、单站 ≤1 请求/1.5 秒、遵守 robots.txt、不存储用户 UGC 文本。

### 1.5 与现有 34 字段契约的映射

| 现有契约字段 | 数据来源 | 缺失时处理 |
|---|---|---|
| title / authors / publisher / isbn / pages | 豆瓣 → OpenLibrary → Google Books 依次补 | 书名+作者必有，其余可空 |
| one_line_what（一句话是什么） | **自有改写**（不得复制简介） | 无源则人工撰写 |
| match_brief（为什么对症） | 人工标注 | 核心层必填，候选层可空 |
| problem_tags[] | 豆瓣标签 + 人工校正 | 至少 1 个，否则不入核心层 |
| difficulty / depth / readability / form / length | 人工标注（依据页数、体裁、作者门槛） | 核心层必填 |
| availability（获取方式） | 微信读书/豆瓣/出版社 在架核对 | 核不到填 unknown |
| quality_prior（新增，见 §3.4） | 贝叶斯收缩后的评分 | 无评分则用同域先验 |
| content_warnings | 人工标注 + 豆瓣条目核对 | 宁可多标 |
| similar_books（新增，见 §3.5） | 人工整理 2–3 本 | 可空 |

## 2. 字段清洗规则

### 2.1 字段处理总则

| 动作 | 字段 | 规则 |
|---|---|---|
| 保留 | 书名、作者、出版社、ISBN13、页数、出版年、评分、评分人数、标签 | 原样或规范化后保留 |
| 派生 | 语言、域、难度、长度档、可读性、质量先验 | 由规则计算 |
| 丢弃 | 封面 URL、价格、库存、销量、用户评论正文 | 与「困境匹配」无关或版权风险 |

### 2.2 缺失值

| 字段 | 缺失等级 | 处理 |
|---|---|---|
| 书名 / 作者 | 必填 | 缺失整条丢弃 |
| ISBN | 重要 | 缺失保留，但**不参与去重主键**（改用 title+author 归一） |
| 简介 | 重要 | 缺失则该书**只能进书目层搜索**，不进候选/核心层 |
| 评分 / 评分人数 | 重要 | 缺失 → `quality_prior = null`，排序时排在同档末尾；评分人数 <10 → 视同缺失（防止 1 人 5 星） |
| 页数 | 可选 | 缺失 → `length = unknown`，长度因子给中性分 |
| 出版年 | 可选 | 缺失保留；异常见 §2.4 |
| 分类/标签 | 重要 | 缺失 → 用 Google Books `categories` 或 OpenLibrary `subjects` 补；仍缺 → 标注 `unclassified`，不进推荐 |

### 2.3 重复项

三级去重，依次执行：

1. **ISBN 级**：ISBN-10 统一转 ISBN-13（校验位重算），去连字符；相同 ISBN13 → 保留字段最全的一条（完整度打分）。
2. **作品级（同书不同版本）**：`normalize(title)` 相同且作者姓氏集合有交集，且出版年差 ≤3 → 合并为同一 `work_id`，保留页数中位数、出版年最早、评分取加权平均。
3. **模糊级**：`normalize(title)` 编辑距离 ≤2 且作者相同 → 人工抽检后合并。

`normalize` 规则：去空白与标点、书名号/引号、「（第X版）」等版本后缀、繁体转简体、英文小写化。

**已知坑**（来自 D2 实操）：作者字段用 `-` 分隔会在 CSV 里造成列错位，导入时按引号解析而非逗号切分。

### 2.4 异常值

| 异常 | 判定 | 处理 |
|---|---|---|
| 评分为 0 或 >5（Goodreads 口径）/ >10（豆瓣口径） | 越界 | 先按来源口径归一（§2.5），越界置 null |
| 评分为负数 | 明显错误 | 置 null 并计入质量报告 |
| 出版年为负或 > 当前年+1 | 明显错误 | 置 null |
| 页数 ≤0 或 >2000 | 异常 | ≤0 置 null；>2000 视为套装，长度因子记 `very-long` 但不丢弃 |
| 评分人数 > 1 亿 | 不可能 | 置 null |
| 书名重复且作者为空 | 疑似占位数据 | 丢弃 |
| 标签计数为负（D2 实测存在） | 数据错误 | 丢弃该标签行 |

### 2.5 评分标准化

**口径统一**：Goodreads/Amazon/Google 为 1–5，豆瓣为 0–10 → 统一映射到 0–1：

```
r_norm = (rating - min) / (max - min)
```

**贝叶斯收缩**（解决「3 人打 5 星」问题）：

```
score = (v / (v + m)) * R + (m / (v + m)) * C
```

- `R`：该书归一后评分；`v`：评分人数；`C`：同域均分；`m`：先验强度，**初值取 50**（即 50 条评分前，权重一半给域均值）。
- 用 D2 的 10,000 本做参数校准：取 `m ∈ {10, 25, 50, 100}`，以「与人工排序的 Spearman 相关」最高者定稿。**结论待实验，文档先写方法。**

**为什么必须收缩**：原始均值在低样本时方差极大。示例：两本书同为 4.8 分，A 有 20 人评、B 有 5000 人评，直接比均值会让 A 碾压 B，明显不合理。

### 2.6 分类标准化

豆瓣标签 → 7 域的主映射（多标签保留，取权重最高为 primary）：

| 豆瓣高频标签 | 归入域 |
|---|---|
| 心理学 / 心理 / 自助 / 情绪 / 焦虑 | psychology（心理与情绪）|
| 沟通 / 人际关系 / 社交 | relationship（关系与沟通）|
| 职场 / 管理 / 职业发展 / 效率 | work / career |
| 成长 / 自我提升 / 习惯 / 时间管理 | growth（成长与习惯）|
| 哲学 / 人生 / 意义 / 生死 | meaning（意义与存在）|
| 决策 / 思维 / 认知 / 逻辑 | thinking（思维与决策）|
| 小说 / 文学 / 传记 | 非「困境」域，只进书目层，不进推荐 |

规则：一书最多 3 个域标签；跨域冲突时以 `match_brief` 的人工判断为准。

## 3. 推荐算法设计

### 3.1 为什么不做协同过滤

| 方案 | 可行性 | 结论 |
|---|---|---|
| 协同过滤（User-CF/Item-CF/矩阵分解） | 需要用户-书交互历史；产品无账号、无历史、纯前端 | ✗ 不可行 |
| 内容匹配（结构化的困境标签 × 书的标注） | 只需书的标注；可完全离线、确定性 | ✓ 采用 |
| LLM 语义匹配 | 需联网或内置模型；不可复现 | ✗ 与「无网络请求」冲突 |
| 混合（内容 + 质量先验） | 内容主导，评分只做 tie-break | ✓ 采用（本文新增） |

**理由**：BookRx 的输入是「一次性的困境描述」，不是长期用户画像。内容匹配让「为什么推荐这本」可以被逐条解释，这是产品契约（结果页每个理由都要能指回用户的某个选择）。

### 3.2 用户画像（单次会话）

画像 = 四屏问卷 + 自由文本，产出：

| 成分 | 来源 | 权重 |
|---|---|---|
| 主诉标签 | 第 2 屏显式选择 | 0.60 |
| 次诉标签 | 第 3 屏选择 | 0.25 |
| 第三诉求 | 第 3 屏选择 | 0.15 |
| 自由文本命中 | 第 4 屏，命中既有词典 | 已有标签取 max(现权重, 0.6)；新命中 0.15 |
| 约束条件 | 难度上限、长度偏好、形式（纸质/电子/有声） | 硬过滤，不参与打分 |

`need_tags` ≤6 个，按（权重降序, 标签字典序）截断；主诉必须显式（不允许「按选择顺序」推断）。

### 3.3 匹配打分（沿用现有 7 因子）

| 因子 | 含义 | 判据 |
|---|---|---|
| problem | 困境匹配 | 书标注的 problem_tags 与 need_tags 的交集与权重 |
| readability | 可读性 | 译文质量、行文密度、术语量（人工 1–5 档） |
| depth | 深度 | 浅显科普 ↔ 学术专著（1–5 档） |
| difficulty | 难度 | 与用户「难度上限」比较，超限扣分 |
| form | 形式 | 纸质/电子/有声可用性 |
| length | 篇幅 | 页数分档，与阅读耐力匹配 |
| availability | 可得性 | 在架状态；不可得封顶 |

档位：`strong`（高度契合）/ `worth`（较为契合）/ `explore`（换个角度），阈值与权重见 SPEC §6（已实现，本文不改）。

**排序键**（6 级链）：`档位 → 总分 → problem 因子分 → availability → 长度适配 → book_id`。前 5 级保证「越像越前」，第 6 级保证**同输入同输出**。

### 3.4 质量先验【新增】

- 计算：§2.5 的贝叶斯分数 `q ∈ [0,1]`。
- **只用在两处**：
  1. **同档同分 tie-break**：插在排序链第 5 级与第 6 级之间（`q` 降序）。
  2. **质量闸门**：`q < 0.65` 且 `v ≥ 100` 的核心层书**降一档**（防止大众口碑差的书写进 strong）。
- **明确不做**：不参与主排序、不改变档位阈值。原因：评分反映「多数人喜欢」，不是「对你有用」；一本 7.8 分的冷门书可能正好治你的病。

### 3.5 冷启动

| 场景 | 策略 |
|---|---|
| 书无评分（新书） | `q = null`，同分时排在中间；核心层新书必须有人工 `match_brief` 才能进入 |
| 用户无自由文本 | 只用三档标签权重，正常出结果 |
| 用户三维全跳（L4） | 不凑数：展示 0 本 + 困境重述 + 路径 D（按原词扩展）→ 外链 |
| 候选层书 | 永不进入打分推荐，只在 L4 兜底时以「库里没找到，外面这些可能有用」外链呈现 |

### 3.6 多样性【新增】

问题：现有实现里同一诊断永远返回同一批书。三层增强：

1. **同分轮换**：同档同分内，排序种子 = `hash(diagnosis_id + rotate_epoch)`，`rotate_epoch` 是本地「换一批」计数（每次点击 +1）。同输入 + 同 epoch → 同输出（确定性不破）。
2. **结果集内去重约束**：同一作者 ≤2 本；同一系列 ≤1 本；同一域标签的「换个角度」位最多 1 本。
3. **「换一批」**：本地记录已展示 `book_id`，点击后已读过的书在同档内排到最后；当核心层全部看过 → 提示「当前书库里的相关书都看过了」并给外链，而不是硬凑。

**为什么不用完整 MMR**：结果集只有 5 本、且每本都要可解释；MMR 的 λ 权衡会让「为什么是这本」变模糊。用硬约束（作者/系列上限）+ 轮换即可，成本低、可测试。

### 3.7 相似书（人工 curated，不走 CF）【新增】

`similar_books` 由人工整理 2–3 本（同困境、不同角度或不同难度），用于：
- 结果页「如果这本读不下去，可以换这本」；
- 书库扩充时的选题线索。
不用平台算法推荐，避免「相似」变成「同一作者的其他书」。

## 4. 结果呈现逻辑

### 4.1 排序与分组

```
[危机信号?] → 是 → 只显示危机资源（互斥，P0-17）
            → 否 → 按档位分组：
                  高度契合（strong，1–3 本）
                  较为契合（worth，1–3 本）
                  换个角度（explore，0–2 本）
                  都读不下去？（L4 兜底 + 外链）
```

总条数上限 5；一组为空则不显示该组，**不用低质书填满**。

### 4.2 每张书卡展示字段

| 位置 | 内容 | 说明 |
|---|---|---|
| 主标题 | 书名 | 必显 |
| 副标题 | 作者 / 译者 / 出版社 / 页数 | 译者对中文读者重要 |
| 一句话 | `one_line_what` | 自有改写，不超过 60 字 |
| 为什么是这本 | 命中理由（见 §4.3） | 必显，可解释性核心 |
| 难度与篇幅 | 「偏通俗 · 约 300 页」 | 帮助预估投入 |
| 入口 | 微信读书 / 豆瓣 / 图书馆 | 外链，新窗口 |
| 次要动作 | 「怎么读这本书」 | 打开读书框架抽屉（§5） |

### 4.3 解释文案模板

三类，均引用用户自己的原词（逐字回显）：

1. **主诉命中**：「你说『{user_phrase}』——这本书正好讲{书的标签对应问题}。」
2. **难度匹配**：「你说想要{通俗/能读下去}的，这本是{难度档}，{页数}页，大概{时长}能读完。」
3. **角度不同（explore 档）**：「这本不直接谈{主诉}，它从{另一个角度}切进去，适合想换个思路的时候。」

禁用的文案：「很多人都在读」「大数据推荐」「你将改变人生」——不可验证的断言。

### 4.4 空状态与边界

| 状态 | 呈现 |
|---|---|
| 0 本 + 有外链 | 「库里没找到真正对味的，不凑数。外面这些可能有用：豆瓣 / 微信读书 / OpenLibrary」 |
| 全部读完 | 「相关的几本你都看过了。要不要换个说法再描述一次？」+ 换一批 |
| 危机信号 | 只显示危机资源条，不显示任何书（宁可误报，不可漏报） |

## 5. 新增功能：读书框架（读得进去，才算推荐成功）

### 5.1 定位

不是打卡工具，也不是笔记软件。目标只有一个：**让被推荐的书真的读完、真的用上**。
入口两处：① 结果页每张书卡「怎么读这本书」；② 首页底部「读书方法」独立页。

### 5.2 内容模型

```json
{
  "framework_version": 1,
  "book_kind": "practical | psychology | classic",
  "stages": [
    {
      "stage": "before",
      "title": "开读前：先想清楚要解决什么",
      "minutes": 10,
      "steps": [
        "用一句话写下你此刻的困境（就是你刚才搜的那句）",
        "翻目录，只挑 3 章看起来最对症的",
        "设定一个问题：读完我要能回答『____』"
      ]
    },
    {
      "stage": "during",
      "title": "读中：检视 → 分析",
      "minutes": 60,
      "steps": [
        "先读序言、目录、最后一章（20 分钟建立地图）",
        "每章一张卡片：一个观点 / 一条证据 / 我一个能用上的动作",
        "100 页法则：100 页还没抓到东西，允许弃读，不内疚"
      ]
    },
    {
      "stage": "after",
      "title": "读后：讲出来才算读懂",
      "minutes": 20,
      "steps": [
        "用费曼法讲给一个完全没读过的人听（3 分钟）",
        "写 300 字：读完我会改变的一个具体动作",
        "14 天后回看：那个动作做了吗？"
      ]
    }
  ]
}
```

三类书的差异化读法：

| 书型 | 读法要点 | 反面案例 |
|---|---|---|
| 实用类（沟通/习惯/效率） | 问题导向，只读能用的章节；每章必须产出一个动作 | 从头读到尾然后全忘 |
| 心理类（情绪/关系/自我） | 慢读 + 自我观察；每读完一章记一次「我今天在哪个场景里看到了它」 | 当小说快读，读完只剩结论 |
| 经典（哲学/意义） | 主题阅读：一次读 2–3 本对照；先读导论与二手解读 | 硬啃原文，三天放弃 |

### 5.3 个人读书框架（可选，本地）

- 三列表：`问题 → 书 → 卡片`（本地存储，可导出 Markdown）。
- 每季度视图：读了几本、哪类问题反复出现、哪些书给了可执行动作。
- **隐私**：笔记只存本机 localStorage，不上传、不进统计；About 页的「清除我的数据」一并清空。

### 5.4 交互

- 结果页书卡 → 底部抽屉（半屏），三阶段折叠展开，默认展开「开读前」。
- 不做强制打卡、不做连续天数、不发通知——避免把「读书」变成「完成 KPI」。
- 可选「标记读完」：只影响本地「换一批」的已读集合，不做社交展示。

## 6. 竞品调研

| 产品 | 核心推荐依据 | 冷启动 | 多样性与解释性 | 可借鉴 | 不适用 |
|---|---|---|---|---|---|
| **豆瓣读书** | 收藏/评分/标签的协同过滤 + 榜单 + 豆列 | 靠榜单与标签浏览 | 「喜欢这本书的人也喜欢」；解释弱 | 标签体系与榜单的公信力 | 依赖历史行为；API 已关闭 |
| **微信读书** | 算法（阅读时长/划线/跳过）+ 好友在读社交背书 + 榜单书单 | 新用户靠榜单与免费卡 | 好友在读提供「信任解释」 | 「好友在读」= 社交背书式解释；笔记导出 | 需账号与社交图谱；重运营 |
| **Goodreads** | 书架 + 评分的协同过滤；「Readers also enjoyed」 | 靠年度榜单/类型页 | 相似书推荐直观 | 书架三态（想读/在读/读过） | API 2020-12 停止发放；数据封闭 |
| **The StoryGraph** | 多维定性标签：mood / pace / 篇幅 / 类型 + 机器学习 | 导入 Goodreads 历史 | 显示 match 百分比；可按 mood 组合筛选 | **把「读起来什么感觉」做成结构化标签**（与我们的 need_tags 同构） | 需要大量用户标注；闭源 |
| **Amazon Books** | item-to-item 协同过滤（买了又买）+ 评论量 | 靠畅销榜 | 推荐强但解释弱、广告混入 | 「同类替代品」的呈现方式 | 无困境维度；商业驱动 |
| **BookBub** | 品类 + 价格 + 邮件订阅的优惠提醒 | 注册时选品类 | 弱 | 订阅式「每日一书」的节奏感 | 以促销为目的，不解决「该读什么」 |
| **得到 / 樊登** | 人工解读 + 编辑书单 + 年度报告 | 编辑推荐 | 强（有人讲解） | **「解读」降低理解门槛**；年度阅读报告 | 二手解读替代原书；付费墙 |
| **Blinkist** | 15 分钟摘要 + 品类订阅 | 编辑精选 | 强 | 「时间承诺」前置（这本要读多久） | 摘要不等于读书 |

### 6.1 三条可借鉴结论

1. **StoryGraph 验证了「多维感受标签」的方向**：mood + pace 本质上就是我们的「困境标签 + 难度/篇幅」。差别在于我们用**困境**（问题导向）而非情绪（体验导向），更接近「治病」而非「消遣」。
2. **微信读书的「好友在读」是最强的解释性设计**：它把「为什么推荐」变成「你信任的人正在读」。BookRx 没有社交，但可以用**本地匿名计数**（「和你类似困境的人，选得最多的是这本」）做弱化版——且完全不上传。
3. **豆瓣/Goodreads 的「相似书」是协同过滤的产物，BookRx 用不了**：应改为**人工 curated similar_books**，保证「相似」是「同困境不同角度」，而不是「同作者」。

### 6.2 差异化定位

市面产品的共同前提是「你已经有阅读历史」。BookRx 的前提是「你现在很难受，不知道该读什么」：

- 不问历史，只问困境（冷启动即满血）；
- 不追求全库覆盖到推荐层，宁可少而准（不凑数）；
- 无账号、无上传、无追踪（隐私即卖点）；
- 每条推荐都给得出「为什么是这本」。

## 8. 风险与开放问题

| 风险 | 影响 | 缓解 |
|---|---|---|
| 豆瓣反爬升级 / 页面改版 | 抓取脚本失效 | 多源兜底（OpenLibrary/Google Books）；脚本幂等可重跑 |
| 数据版权争议 | 开源项目被投诉 | 只内置书目事实与自有改写；评分只存档位；不存 UGC |
| 评分漂移 | 质量先验失真 | 每季度重抓；先验只做 tie-break，影响可控 |
| 书目层包体过大 | 首屏变慢 | 按域分片懒加载，首屏不加载 |
| 人工核对成本 | 核心层扩不动 | 半自动起草 + 抽检；每本 10–15 分钟 |
| 「换一批」破坏确定性 | 测试不稳定 | epoch 进种子；测试固定 epoch |

**开放问题（需产品决策）**：
1. 书目层是否收录小说/文学类？现有 7 域只覆盖非虚构困境，收录小说会让搜索更全但推荐无法覆盖。
2. 评分是否显示原始数值？显示会更直观，但有版权与「分数崇拜」风险；当前设计只显示档位。
3. 读书框架的笔记是否需要导出？导出增加价值，也增加隐私顾虑。
